# BA Specification: Fix check-budget-overage.py for Multi-Currency Support (Bug8 + Bug26 Combined)

**Request ID**: dev-20260406-010006
**Created**: 2026-04-06T01:00:06Z

## Goal

Fix `scripts/check-budget-overage.py` to detect the plan currency from `budget.json` and use
the correct field names for overage extraction, rather than hardcoding EUR field names. For CNY
plans the script must find `overage_cny` / `overage_percent` or derive overage from `total` vs
`user_budget` fields. The argument parameter name and all output labels must also be
currency-aware (not hard-wired to EUR symbols and threshold labels).

## Context

The script was written assuming all plans use EUR. Three real `budget.json` structures exist:

1. **EUR plan** (`beijing-exchange-bucket-list`): `data.overage_eur` + `data.overage_percentage`
   at the `data` top level.
2. **CNY plan** (`wangfujing-dongdan-beijing`): `data.days[0].budget_vs_user.overage_cny` +
   `data.days[0].budget_vs_user.overage_percent` (per-day, must aggregate or take trip_summary).
   Also has `data.trip_summary.overage_cny` + `data.trip_summary.overage_percent` at trip level.
3. **CNY multi-day plan** (`china-feb-15`): no top-level overage fields; only per-day `total`
   figures and notes referencing EUR equivalents in strings.

The budget agent schema (`budget.md`) defines the agent summary JSON as `overage_amount` +
`overage_percent` (currency-agnostic names), while actual `budget.json` files use currency-
suffixed names (`overage_eur`, `overage_cny`). This inconsistency is the root cause.

Bug8 (in a related script) and Bug26 (this script) share the same file and the same class of
defect: EUR-hardcoded field names and output labels. This spec combines both fixes into one
coherent change to `check-budget-overage.py`.

## Requirements (MoSCoW)

### Must Have

1. **Currency detection**: Detect the plan currency from `budget.json` by inspecting field names
   in the following priority order:
   - Presence of `overage_eur` (at root, `summary`, or `data` level) → currency = EUR, symbol = €
   - Presence of `overage_cny` (at root, `summary`, `data`, or `data.trip_summary`) → currency = CNY, symbol = ¥
   - Presence of `overage_amount` (agent summary format) → currency = generic, symbol = currency-neutral
   - Fallback: derive overage from `total` minus `user_budget` fields if no explicit overage field

2. **CNY field lookup**: For CNY plans, look for overage in this priority order:
   - `data.trip_summary.overage_cny` + `data.trip_summary.overage_percent`
   - `data.overage_cny` + `data.overage_percent` (root level)
   - `summary.overage_cny` + `summary.overage_percent`
   - Derived: `sum(day.budget_vs_user.overage_cny for day in data.days)` with percentage from
     `total_cost / user_budget - 1`

3. **Rename threshold parameter**: The function signature `threshold_eur` and CLI argument
   `overage_threshold_eur` must be renamed to `threshold_amount` / `overage_threshold` to be
   currency-agnostic.

4. **Currency-aware output labels**: All `print()` calls that use `€` hardcoded must use the
   detected currency symbol. Error messages referencing `overage_eur` must list all accepted
   field variants.

5. **Updated docstring and usage**: Update module docstring examples and `--help` text to use
   generic parameter names, not EUR-specific ones.

### Should Have

- If per-day aggregation is used, include the day count in the output (e.g.,
  "Aggregated over N days").
- Log which field path was used to find overage (debug-level or as part of the normal output
  line), so future debugging is easier.

### Could Have

- Support for additional currencies (USD, JPY, GBP) using the same detection pattern
  (`overage_usd`, `overage_jpy`) without requiring code changes — achieved by making the
  detection loop over a currency map.

### Won't Have (Non-Goals)

- Changes to `budget.json` data files or the budget agent schema
- Support for mixed-currency plans (a plan in both CNY and EUR simultaneously)
- Any change to exit codes (0 / 1 / 2 remain the same)
- Any change to other scripts beyond `check-budget-overage.py`

## Edge Cases & Risks

- **No explicit overage field, no derivable total/user_budget**: The script must exit with code 2
  and print an informative error listing all field names it searched.
- **`overage_percent` vs `overage_percentage`**: CNY plans use `overage_percent` (no `age`
  suffix), EUR plans use `overage_percentage`. The lookup must handle both.
- **Negative overage (under budget)**: Already handled by `abs()` in threshold comparison;
  must be preserved.
- **`data` field is a list not a dict**: The `china-exchange-bucket-list-2026` budget.json has
  `data` as a list of day objects with no trip_summary. Overage derivation must guard against
  `data` not being a dict.
- **Per-day aggregation rounding**: Summing floats across days may produce small floating point
  drift; round to 2 decimal places before comparison.

## Acceptance Criteria

### AC1: EUR plan continues to work
- GIVEN `beijing-exchange-bucket-list/budget.json` with `data.overage_eur: -1043.33` and
  `data.overage_percentage: -29.8`
- WHEN `check-budget-overage.py <path> 200 20` is called
- THEN exit code 0 and output shows `€` symbol with the correct overage values

### AC2: CNY plan with trip_summary works
- GIVEN `wangfujing-dongdan-beijing/budget.json` with
  `data.trip_summary.overage_cny: 0` and `data.trip_summary.overage_percent: 0`
- WHEN `check-budget-overage.py <path> 500 20` is called
- THEN exit code 0 and output shows `¥` symbol; no EUR field error

### AC3: Missing overage fields produce actionable error
- GIVEN a `budget.json` with no overage fields of any currency and no `total`/`user_budget` to
  derive from
- WHEN the script is called
- THEN exit code 2 and stderr lists all searched field paths including CNY and EUR variants

### AC4: Threshold parameter is currency-agnostic
- GIVEN calling `check-budget-overage.py <path> 1000 15`
- WHEN the plan is CNY
- THEN the threshold `1000` is compared against `overage_cny` (in CNY), not converted to EUR

### AC5: Combined Bug8 + Bug26 — single file fix
- GIVEN the file `scripts/check-budget-overage.py`
- WHEN the fix is applied
- THEN no occurrence of `overage_eur` remains in field-lookup logic or output labels (only in
  the currency-detection map where it is a key string, not a hardcoded assumption)

## Technical Hints

- Affected file: `scripts/check-budget-overage.py` (sole file to modify)
- Currency detection map pattern (suggested implementation):
  ```python
  CURRENCY_FIELDS = {
      'EUR': {'symbol': '€', 'overage': 'overage_eur', 'pct': ['overage_percentage', 'overage_percent']},
      'CNY': {'symbol': '¥', 'overage': 'overage_cny', 'pct': ['overage_percent', 'overage_percentage']},
  }
  ```
- Search order for CNY overage: `data.trip_summary` → root → `summary` → per-day aggregation
- Rename `threshold_eur` → `threshold_amount` in function signature and all call sites
- Keep exit codes identical; only field lookup and output labels change
