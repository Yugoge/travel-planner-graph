# BA Specification: Fix silent data loss bug in POI agents — slot-level merge

**Request ID**: dev-20260416-172720
**Created**: 2026-04-16T17:27:20Z

---

## Goal

Implement slot-level merging for POI agent saves so that a partial-day update (e.g., only `dinner`) does not silently wipe sibling slots (`breakfast`, `lunch`) in the same day object. This requires a new `--merge-slots` flag in `scripts/save.py`, a new `merge_agent_slots()` function in `scripts/lib/json_io.py`, updating six POI agent prompts to use the new flag, adding an audit script for historical data loss detection, and creating an integration test.

---

## Context

The existing `merge_agent_days()` function (json_io.py:317-372) performs day-level replacement: when a POI agent saves a partial day (e.g., only `dinner`), the entire day object is overwritten with the agent's output, destroying `breakfast` and `lunch`. This is correct for the timeline agent (whole-day recalculation) but wrong for POI agents that update individual slots. A confirmed instance of loss was recorded in `data/china-20260412-092624/meals.json`: commit `47fccd4` (2026-04-13 13:14) wiped Day 2 breakfast and lunch while the modification log only recorded `changed_fields: ["days[1].dinner"]`. The user has pre-approved the fix approach (Option C: new `--merge-slots` flag, backward-compatible with existing `--merge-days`).

## Edge Cases & Risks

- **Array merge semantics**: For array-based agents (attractions, entertainment, shopping, cafe), "slot-level merge" means: if update includes the `attractions` key, replace the entire array for that day; if update does NOT include the `attractions` key, preserve existing array. This is still safer than current behavior because an agent that only updates `attractions` won't wipe the day's `date` or `location` metadata. Confirm with user if deeper array element merging is needed (currently not requested).
- **transportation.md and budget.md**: These agents also use `--merge-days` but are not in spec scope. Do not change them. Flag this as a follow-up risk in the dev report.
- **review.md references**: The `review.md` command file references `--merge-days` in the context of timeline saves. These are correct references and must not be changed.
- **Import export chain**: `save.py` imports `merge_agent_days` from `lib.json_io` at line 33. Dev must add `merge_agent_slots` to this import line and to json_io.py's public exports.
- **`_prepare_agent_data()` in save.py:479**: This function currently only branches on `merge_days`. A parallel branch for `merge_slots` is needed. Both `merge_days` and `merge_slots` should not be used simultaneously — add mutual exclusion guard in `_validate_args()`.
- **No tests directory**: `scripts/tests/` does not currently exist. Dev must create it.
- **Audit script dependency**: `scripts/audit-data-loss.py` depends on git log being available and the trip directories containing git history. It must gracefully handle trips where git log yields no meals.json commits.
