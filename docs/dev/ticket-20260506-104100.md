## BA Decisions (cp-01 .. cp-05)

### cp-01 — `transportation.intra_city_routes` and `budget.breakdown.*_detail` `additionalProperties` decision

**Decision**: KEEP `additionalProperties: true` for both fields in this cycle. **Rationale**:

1. The user's binding directive is "最小最安全最完美最确定性地实现用户的需求，而不是扩大修复范围。一切以用户需求为中心" — promoting these to strict would force a broad migration of existing data shape (per spec §8 schema-tightening risk).
2. `verify-plan-integrity.py --strict-schema` already enforces `additionalProperties:false` on the TOP-level schemas (timeline, attractions, etc.). The two `additionalProperties:true` regions are FREEFORM SUB-OBJECTS (route descriptors, budget breakdown details) where strict allowlists would actively break existing data without user benefit.
3. Spec 5.6's `plan_label` ban is enforced at the TOP-level `timeline_activity.additionalProperties:false` (already strict) — the freeform intra_city_routes / breakdown sub-objects are NOT where `plan_label` leaked in. Tightening them does not address the user's stated need.
4. Schema tightening risk (spec §8): "making `transportation.intra_city_routes` strict will reject existing data" — current data uses route descriptor keys like `planA_wutongqiao_to_leshan_station_taxi` (line 242). Promoting to false would require enumerating every descriptor pattern across all trips — out of user-need scope.

**Migration**: none required (no schema change).

### cp-02 — strict-write validator approach for 5.1

**Decision**: **Option (b) — wire existing `verify-plan-integrity.py --strict-schema` into PreToolUse**, extended with a new `--target-file <path>` single-file mode (currently it scans the entire trip dir). **Rationale**:

1. `verify-plan-integrity.py` ALREADY has `--strict-schema` flag (lines 401-405) — proven, already used at deploy by `generate-and-deploy.sh:160-162, 200-202`. Reusing avoids drift between deploy gate and write-time gate.
2. `plan-validate.py` is 1788 lines and has different concerns (issue severities, agent-specific rules). Adding `--strict-schema` there would duplicate logic.
3. Building a NEW write-time validator (option c) violates "和现有功能对齐，而不是所有问题都要重新造轮子" — codex audit and user both rejected wheel-reinvention.
4. The single-file mode extension is small (estimated ~30 LOC) — accept a `--target-file <path>` arg, scope `check_schemas()` to that path's parent dir, scope per-file checks to the named file.

**Implementation shape**:
```
verify-plan-integrity.py [<plan-id> | --target-file <abs-path>] --strict-schema [--cross-ref]
```

The PreToolUse hook is a small Python script (`pretool-validate-data-write.py`) that reads `tool_input.file_path`, identifies the trip slug from the path, and invokes `verify-plan-integrity.py --target-file <file_path> --strict-schema`. Exit 2 on FAIL.

**Why not PostToolUse**: PostToolUse runs AFTER the write — too late to prevent the bad state from reaching the next checkpoint ref. Spec §5.1 explicitly says "BEFORE the file is allowed to persist into checkpoint." PreToolUse is the right place. (Note: PreToolUse cannot see the in-flight content for a `Write` directly via tool_input — but `tool_input.content` for `Write` and `tool_input.new_string` for `Edit` ARE in the payload. The hook simulates the post-write state by applying the change in-memory, then validating.)

### cp-03 — schema-tightening migration plan

**Decision**: **Option (a) widen schema where current data needs space; Option (b) normalize where the user's invariants demand strictness; HYBRID per field**:

| Field | Current | Target | Rationale |
|-------|---------|--------|-----------|
| `transportation.intra_city_routes` | `additionalProperties: true` | **keep `true`** (cp-01) | freeform descriptor keys; tightening out of scope |
| `budget.breakdown.*` | `additionalProperties: true` | **keep `true`** (cp-01) | freeform breakdown; tightening out of scope |
| `timeline_activity.plan_label` (line 77-80) | currently DEFINED | **REMOVE** the property + the `additionalProperties:false` (line 87) is already strict, so removal alone is sufficient | user's verbatim "plan_label 直接删除，这不是我们 schema 中的" |
| `transportation_segment.plan_label` (if present) | check + remove | **REMOVE** | same |
| `name_local` | `type: string` | tighten with CJK regex pattern (per 5.5 bug 6 acceptance) | "every `name_local` ... contains at least one Chinese character" |

## Technical Hints

- `verify-plan-integrity.py` extension to `--target-file` mode: re-use `find_project_root()` (line 381), accept either `<plan-id>` positional or `--target-file <abs-path>`; when `--target-file` given, derive `data_dir` from the file's parent and constrain `check_schemas()` / `check_forbidden_tokens()` etc. to that one file.
- `pretool-validate-data-write.py` shape:
  - Read JSON from stdin (Claude Code hook contract).
  - Extract `tool_name`, `tool_input.file_path`, `tool_input.content` or `tool_input.new_string`.
  - Match `data/**/*.json` glob.
  - For Edit: simulate the post-edit content by applying the diff in-memory.
  - Write simulated content to a tempfile.
  - Invoke `verify-plan-integrity.py --target-file <tempfile> --strict-schema --cross-ref`.
  - Exit 2 on FAIL with the verifier's stderr surfaced; exit 0 on PASS.
- `git update-ref refs/checkpoints/<branch>`: equivalent of a no-fast-forward commit but never advances HEAD.
  - `tree=$(git write-tree)` (after `git add -A` to index)
  - `parent=$(git rev-parse refs/checkpoints/<branch> 2>/dev/null || git rev-parse HEAD)`
  - `commit=$(git commit-tree "$tree" -p "$parent" -m "checkpoint: ...")`
  - `git update-ref refs/checkpoints/<branch> "$commit"`
  - **Critically**, do NOT call `git commit` — that advances HEAD. Use `commit-tree` + `update-ref` only.
- `save.py --day N`: argparse `add_argument('--day', type=int, required=True)`. Add a `_filter_input_to_day(data, day)` that scopes the input dict to entries belonging to that day. Reject if input contains entries for other days.
- For 5.9 translation, add a `_translate_user_language(item)` function called in `_prepare_agent_data` (line 503): map `{primary, plan_a, plan-a, planA, 主行程, 套餐 A}` → `optional:false`; map `{plan_b, plan_c, alternative, 备选, 可选, plan-b, plan-c}` → `optional:true`; strip the original key.
- For 5.7 referential integrity, key checks:
  - **Orphan POI**: for each `attractions/meals/entertainment/shopping[i].name_base`, check substring-match in `timeline.json[day].timeline.<key>` for the same day. Allow free substring match because timeline keys often append decoration.
  - **Hollow plan branch**: count entries per plan label; if any label has < 2 items unless explicitly single-item-marked, fail.
  - **Triple-duplicate transit**: build a `(name_base, day, time-window)` triple set across `transportation.intra_city_routes[*]`, `timeline.travel_segments[*]`, `timeline.timeline.<key>` (where `transit:true`); fail if any triple appears in more than one source AND time windows overlap.

- **Composability with existing PreToolUse hooks** (`pretool-quality-gate.py`, `pretool-block-production-files.sh`, `pretool-workflow-gate.py`): order in `.claude/settings.json` matters. Add new hook AFTER existing path-block (cheap) and BEFORE workflow-gate (expensive). Use `on_error: "ignore"` ONLY if the verifier is meant to be advisory — but spec §5.1 says BLOCK, so use no `on_error` (fail-closed).
