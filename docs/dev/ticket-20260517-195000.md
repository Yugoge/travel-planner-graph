## Goal

Fix three photo layout regressions introduced in task 20260517-172103: timeline slot images render as giant heroes instead of compact thumbnails (P0), `.slot-selected` has no flex layout so the thumbnail stacks above text instead of sitting beside it (P1), and the `#trip-cover` upscales 500px source images to 794px producing blur (P2).

---

## Context

Cycle 20260517-172103 added POI photos and city covers to the trip editor. It used a shared `.card-photo` CSS rule (`width:100%; aspect-ratio:16/9`) that works correctly for the ~235px-wide candidate sidebar but produces a 712×401px hero image in the 738px-wide timeline pane. The `.slot-selected` container was left as `display:block`, stacking the image above the name text. The `renderCover()` function unconditionally shows the cover image without checking natural resolution.

## Edge Cases & Risks

1. **CSS cascade order**: The scoped `.slot-selected .card-photo` override must come after the base `.card-photo` rule in the file. Dev must verify ordering; inserting before the base rule will be silently overridden.
2. **Cached images**: If the browser has the cover image cached, `onload` fires synchronously before `img.src` assignment completes in some engines. Setting `onload` before `img.src` avoids this race. The `img.hidden = false` must NOT precede the `onload` check — image should stay hidden until the check passes.
3. **No-image slots**: When `url` is null/undefined in `_writeSlotSelected`, `img.hidden = true` already; the flex layout must still render the text children correctly without the image occupying space. `flex: 0 0 80px` on a hidden element collapses correctly in modern browsers only if `hidden` maps to `display: none` — verify the `[hidden]` rule at `main.css:436-439` covers `.slot-selected .card-photo[hidden]`.
4. **Multiple day switches**: `renderCover()` is called on every day change; assigning `img.onload = () => { ... }` as a property (not addEventListener) replaces the previous handler, preventing accumulation.
5. **naturalWidth on error**: If both `onerror` and `onload` could fire (e.g. partial image), `onerror` handler hides+clears src; `onload` would not fire after an error in standard browser behavior — no conflict.

### JS changes (Codex-verified, refined for hidden-until-loaded pattern)

Replace the `if (url)` block in `renderCover()` at `web/js/state.js:162-164`:

```js
if (url) {
  img.onload = () => {
    if (img.naturalWidth >= 800) {
      img.hidden = false;
    } else {
      img.hidden = true;
      img.removeAttribute("src");
    }
  };
  img.hidden = true;   /* keep hidden until resolution verified */
  img.src = url;
} else {
  img.onload = null;
  img.hidden = true;
  img.removeAttribute("src");
}
```

Note: `onload` is assigned as a property (replaces previous handler on each call) before `img.src` is set — prevents accumulation across day switches and handles cached-image synchronous-fire race correctly.

### Codex Q3 outcome — no `object-position` change

Codex recommended keeping `object-position: center` (current implicit default) for `#trip-cover`. With a 21/9 crop on city skyline images, `top` tends to over-emphasize sky. No CSS change needed for `object-position`.
