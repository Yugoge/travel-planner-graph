# BA Specification: Fix check-budget-overage.py Multi-Currency Support

**Request ID**: dev-20260406-010001
**Created**: 2026-04-06T01:00:01Z

## Goal

Fix `scripts/check-budget-overage.py` crashing with exit code 2 when processing CNY-based budget plans, by teaching it to locate overage and percentage fields regardless of which currency the plan uses.

## Context

The script was written assuming EUR-denominated plans, where `overage_eur` and `overage_percentage` appear under `data`. CNY plans use different field names: `overage_cny` / `overage_percent` (in `data.trip_summary`) or `overage_cny` / `overage_percent` (in `data.days[*].budget_vs_user`). A third plan shape has neither field at any known path, meaning the budget agent did not emit a trip-level summary at all. The script currently exits 2 for all three CNY shapes because none of them match the hard-coded `overage_eur` lookup.

Four budget files exist in the codebase; one has the EUR shape, three do not:

| Plan | Shape | overage field |
|------|-------|---------------|
| `beijing-exchange-bucket-list-20260202-232405` | EUR (with CNY conversion) | `data.overage_eur` + `data.overage_percentage` |
| `wangfujing-dongdan-beijing-20260405-192905` | CNY trip_summary | `data.trip_summary.overage_cny` + `data.trip_summary.overage_percent` |
| `china-exchange-bucket-list-2026` | per-day only, no trip total | absent |
| `china-feb-15-mar-7-2026-20260202-195429` | per-day only, no trip total | absent |

## Requirements (MoSCoW)

### Must Have
- Detect currency from the budget file (presence of `overage_eur` vs `overage_cny` vs `overage_percent`)
- Resolve absolute overage from whichever named field is present: `overage_eur`, `overage_cny`, or generic `overage`
- Resolve percentage overage from whichever named field is present: `overage_percentage` or `overage_percent`
- Search the same set of candidate paths as today (`root`, `summary`, `data`, `data.trip_summary`, `data.days[*].budget_vs_user`) for both field name variants
- When an absolute overage is found in CNY, convert it to EUR using `data.currency_exchange_rate.cny_to_eur` if present, or a configurable fallback rate, before applying the EUR threshold
- Alternatively, when no EUR conversion rate exists, skip the absolute EUR threshold check and rely solely on the percentage check (percentage is currency-agnostic)
- Return exit code 2 only for genuinely missing data, not for a currency mismatch
- Update the error message to list all accepted field name variants

### Should Have
- Print which currency and field path was resolved (for debuggability)
- Accept an optional `--currency` CLI argument to override auto-detection

### Could Have
- Support a `threshold_cny` CLI argument as a direct CNY absolute threshold alternative to EUR conversion

### Won't Have (Non-Goals)
- Generating or populating missing overage fields in budget files (that is the budget agent's responsibility)
- Modifying any budget.json files
- Supporting currencies other than EUR and CNY at this time

## Edge Cases & Risks

- Plans with per-day budget data only and no trip-level summary: cannot compute an aggregate overage — script should exit 2 with a clear message distinguishing "missing trip summary" from "missing field"
- Exchange rate absent or zero: guard against ZeroDivisionError when converting CNY to EUR
- `overage_percent` (no `age` suffix) vs `overage_percentage` (full word): both must be accepted
- Negative overage values (under-budget): `abs()` is already applied, must remain so for both currencies
- The `data` key may hold a list instead of a dict in some edge-case future shapes: guard with `isinstance` check

## Acceptance Criteria

### AC1: EUR plan unchanged
- GIVEN a budget.json with `data.overage_eur` and `data.overage_percentage`
- WHEN `check-budget-overage.py` is invoked with that file
- THEN exits 0 or 1 (not 2) and prints EUR-denominated overage line

### AC2: CNY plan with trip_summary
- GIVEN a budget.json with `data.trip_summary.overage_cny` and `data.trip_summary.overage_percent`
- WHEN `check-budget-overage.py` is invoked with that file
- THEN exits 0 or 1 (not 2) and prints CNY-denominated overage line

### AC3: CNY plan with currency_exchange_rate applies EUR threshold
- GIVEN a budget.json with `data.overage_cny`, `data.overage_percentage`, and `data.currency_exchange_rate.cny_to_eur = 7.8`
- WHEN script is invoked with default `threshold_eur = 200`
- THEN converts `overage_cny / 7.8` to EUR and applies the EUR threshold correctly

### AC4: Plan with no trip-level overage summary
- GIVEN a budget.json where overage fields are absent at all known paths
- WHEN `check-budget-overage.py` is invoked with that file
- THEN exits 2 with an error message that lists all accepted field names and paths (not just `overage_eur`)

### AC5: Percentage-only check when no exchange rate
- GIVEN a budget.json with `overage_cny` but no `currency_exchange_rate`
- WHEN script is invoked
- THEN applies only the percentage threshold (skips EUR absolute check) and exits 0 or 1

## Technical Hints

- Affected file: `scripts/check-budget-overage.py`
- Pattern to follow: extend the existing multi-path lookup loop rather than duplicating the function
- The CNY->EUR rate in the beijing plan is stored as `data.currency_exchange_rate.cny_to_eur` (float, e.g. `7.8`); extract it alongside overage fields
- `overage_percent` (wangfujing shape) and `overage_percentage` (beijing shape) are the two spellings; both must be accepted
- No new dependencies needed; stdlib only
