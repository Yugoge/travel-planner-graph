**Request ID**: 20260514-200530

## Goal

Replace a China-specific memory file that was incorrectly phrased as a universal rule with a properly scoped content-source policy (China vs international), and add a trip-scope qualifier to the Jade INFJ preferences file so it only applies when Jade is a traveling companion.

## Context

`feedback_no_gaode_for_content.md` was written after one China trip incident (Beijing-Lijiang-Dali, rednote rate-limit event). Its current phrasing bans gaode for ALL trips universally and implies rednote is the only allowed source everywhere. A future Paris trip agent reading this file would incorrectly believe "I must only use rednote and can never use google maps". Similarly `user_jade_infj.md` applies Jade's INFJ preferences to all trips, but should apply only when Jade is a traveler on the trip.

Additionally, `accommodation.md` lacks the explicit China/international branching in its research Tasks section that all five other content agents already have (meals, attractions, entertainment, shopping, cafe all have "For China destinations: Use RedNote-driven discovery only / For global destinations: Use Google Maps" in their Tasks body).

## Edge Cases & Risks

- The rate-limit rule (pause-and-report, never fallback to POI search) applies only to China trips where rednote is in use — embedding it as a sub-note inside the China section avoids implying it constrains international trips
- If a trip involves both China and international legs (e.g., Beijing + Tokyo), agents need to apply the China rule on China days and international rule on international days — this is handled per-day by reading destination context, not by the memory file; the spec does not need to enumerate this edge case
- Renaming the memory file from `feedback_no_gaode_for_content.md` to `policy_content_source.md` requires MEMORY.md index to be updated atomically in the same change; if dev edits the file in-place instead, the old filename is still valid and MEMORY.md does not need an update for the key entry (only the description)
- `user_jade_infj.md` is referenced by name in `accommodation.md` line 52 ("Cite Jade's INFJ + Matilde memory entries in `why_fits_user`") — adding the scope qualifier does NOT break this reference since that specific accommodation rule is already for couple trips in context
