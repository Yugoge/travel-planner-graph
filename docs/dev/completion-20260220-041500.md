**Original**: 为什么这一步就开始fetch image了？不应该present step之后才fetch吗！

**Clarified**: Fix image fetching workflow order in /plan and /review commands. Images should be fetched AFTER user confirms day is perfect, not BEFORE presenting the day to user.

**Success Criteria**:
- In plan.md Step 15 INNER loop, image fetching happens AFTER user chooses 'This day is perfect'
- In review.md Step 14 INNER loop, image fetching happens AFTER user chooses 'This day is perfect'

- Step numbering remains consistent (no duplicate step numbers)

## Root Cause Analysis

**Symptom**: Image fetching todo appears before day presentation in review.py (line 9), causing orchestrator to attempt fetching before user sees the day

**Root Cause**: Commit 94bca5f added Step 14a/4a image fetching but placed it OUTSIDE the INNER loop, before user confirmation. Todo scripts were created to match this incorrect order.

**Root Cause Commit**: `94bca5f - feat: Add progressive image fetching to plan and review commands`

**Timeline**: Introduced 2026-02-13, affects all /plan and /review executions since then

**Why Issue Occurred**: Feature added image fetching per day to avoid waiting until final HTML generation, but didn't consider nested loop workflow where user may iterate multiple times on same day

**Why Problematic**: Fetching images before user confirms wastes time if user requests changes (images fetched, then day modified, then images need re-fetch). Correct pattern: confirm perfect → fetch once → advance to next day.

## Implementation

**Approach**: Move image fetching substep to INSIDE the INNER loop, immediately after user confirms 'This day is perfect' but BEFORE exiting loop (before setting day_confirmed_perfect=true). This ensures images fetched once per confirmed day, not on every presentation.

**Scripts Created**: None (workflow fix, no new scripts needed)

   - Image fetching now positioned RIGHT AFTER user confirmation, BEFORE day_confirmed_perfect=true

   - Removed 'Step 14a: Fetch Images for Current Day' entry

   - Moved 'Fetch images for confirmed day' from position 3 to position 5
   - Now appears AFTER 'Process user choice', matching actual workflow execution order

**Git Rationale**:

Commit 94bca5f added Step 14a/3a image fetching but placed it OUTSIDE the INNER loop, before user confirmation. This caused images to be fetched on every day presentation iteration, wasting time if user requested changes (fetch → modify → re-fetch pattern).

**Fix**: Moved image fetching INSIDE the INNER loop as a substep of Option 1 processing ('This day is perfect'). Now images fetch ONCE per confirmed day, AFTER user confirms perfect but BEFORE exiting loop to next day.

**New Pattern**:
