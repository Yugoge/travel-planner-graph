# BA Specification: Include Schema File Paths in Step 8 Agent Prompts

**Request ID**: dev-20260406-020003
**Created**: 2026-04-06T02:00:03Z

## Goal

Add a schema validation instruction to each of the 6 parallel agent prompts in Step 8 of `plan.md`, directing agents to self-validate their JSON output against the corresponding schema file before saving, so that `validate-agent-outputs.py` passes on the first attempt and eliminates re-invocation waste.

## Context

Step 8 of the `/plan` workflow invokes 6 specialist agents in parallel (meals, accommodation, attractions, entertainment, shopping, transportation). Each agent writes a JSON file to `data/{destination-slug}/`. Step 9 then runs `validate-agent-outputs.py`, which validates each JSON against the schema in `schemas/`. When violations are found (e.g., `accommodation` written as `null` instead of an object, `transportation` written as an array instead of an object), Step 9 forces re-invocation of the offending agents — a costly extra round-trip.

The schemas already exist for all 6 agents:
- `schemas/meals.schema.json`
- `schemas/accommodation.schema.json`
- `schemas/attractions.schema.json`
- `schemas/entertainment.schema.json`
- `schemas/shopping.schema.json`
- `schemas/transportation.schema.json`

The agent definition files in `.claude/agents/` do not currently reference these schema paths. The Step 8 prompts in `plan.md` also do not reference them. Agents therefore have no self-validation signal and only discover violations when the orchestrator runs the external validator in Step 9.

## Requirements (MoSCoW)

### Must Have
- Each of the 6 agent prompts in Step 8 of `plan.md` must include a line instructing the agent to validate its output against its schema before saving.
- The schema path must be an absolute path (`/root/travel-planner/schemas/{agent}.schema.json`) so the agent can read it regardless of working directory.
- The instruction must appear immediately before the `Save to:` directive in each agent prompt block, so the save step is the final action after validation passes.
- The instruction wording must be consistent across all 6 agents.

### Should Have
- The 6 agent definition files in `.claude/agents/` (meals.md, accommodation.md, attractions.md, entertainment.md, shopping.md, transportation.md) should also reference their schema path, so agents invoked via re-invocations in Steps 15 and 20 also self-validate.
- The schema reference in agent definition files should appear in the "Tasks" or "Output" section, near the save instruction.

### Could Have
- A brief note in each prompt explaining which common violations the schema catches (e.g., "accommodation must be an object, not null").

### Won't Have (Non-Goals)
- Changing the schema files themselves.
- Adding a new validation script or modifying `validate-agent-outputs.py`.
- Modifying timeline-agent or budget-agent prompts (they are serial, post-validation, and not in scope).
- Changing the Step 9 validation gate — it stays as the authoritative check.

## Edge Cases & Risks

- **Transportation agent**: Only processes days with `location_change`. Its schema (`transportation.schema.json`) uses `data.days` array with route entries. The instruction must still be included; the agent can skip validation if it writes an empty days array.
- **Agent re-invocations in Steps 15 and 20**: These invoke agents via Task tool with inline prompts, not via the agent definition file. Schema reference in Step 8 prompts covers Step 8 invocations; adding it to agent `.md` files covers all other invocations.
- **Absolute vs relative paths**: Agent working directories vary. Always use absolute path `/root/travel-planner/schemas/`.
- **Read tool restriction**: All 6 agents already have `Read` in their tools list, so they can read the schema file. No permission changes needed.

## Acceptance Criteria

### AC1: Step 8 prompts reference schema paths
- GIVEN plan.md Step 8 contains 6 agent prompt blocks
- WHEN a developer reads any of the 6 prompts
- THEN each prompt contains the line `Validate output against schema: /root/travel-planner/schemas/{agent}.schema.json before saving.` immediately before the `Save to:` line

### AC2: Agent definition files reference schema paths
- GIVEN `.claude/agents/{agent}.md` files for meals, accommodation, attractions, entertainment, shopping, transportation
- WHEN a developer reads the Tasks section of any agent definition
- THEN each file contains a reference to `/root/travel-planner/schemas/{agent}.schema.json` near the output save instruction

### AC3: No regressions in existing prompts
- GIVEN the modified plan.md
- WHEN the orchestrator runs Step 8
- THEN all existing prompt fields (bilingual annotations, GPS coordinates, file paths, return value) remain unchanged
