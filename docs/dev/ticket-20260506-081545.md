### Objection 2 (investigation_completeness — Python-internal write surface uncovered)

**Verbatim file evidence (this BA session)**:
- `scripts/sync-agent-data.py:181-183` (Read in this session):
  ```
  with open(path, "w", encoding="utf-8") as f:
      json.dump(output, f, ensure_ascii=False, indent=2)

  ```
  Where `path` resolves to `data/<plan_id>/<filename>` — a Python-internal write to `data/<trip>/<file>.json`.
- `scripts/strip-image-url-fields.py:36-37` (Read in this session):

**Resolution adopted (per QA's required option (a)+(b))**:
- **(a) Move enforcement INTO `scripts/lib/json_io.py:save_agent_json`** — extend it to ALSO enforce per-agent `owned_files` ownership. This catches all Python-internal writes through the canonical save path.
- **(b) Refactor `sync-agent-data.py` and `strip-image-url-fields.py` to route through `json_io.save_agent_json`** — removes the bypass surface entirely.
- The Bash heredoc/redirect detection in the hook is the **secondary** defense (catches direct shell redirects bypassing `json_io`).

`scripts/lib/json_io.py` extension point confirmed (Read in this session, 517 lines): `save_agent_json` already runs `_reject_unsafe_image_payloads(envelope)` at line 183. The per-agent ownership check is a **new** sibling rejector function modeled on the existing `_reject_unsafe_image_payloads` at lines 117-132.

## Edge Cases & Risks

- **B1 risk (low)**: any external script that depended on exit 2 = warnings-only would silently pass. Investigation showed zero shell callers and the only Python caller (`sync-agent-data.py`) uses importlib not subprocess, so blast radius is nil. Mitigation: run `grep -rn 'validate-agent-outputs' --include='*.sh'` post-fix — must remain 0 hits.
- **B2 risk (medium)**: extending matcher to Bash adds one PreToolUse syscall to every Bash invocation. Performance: the early-exit on non-data Bash is a few regex matches → negligible. False-positive risk: a Bash command containing the literal `scripts/save.py` substring but not actually invoking it (e.g., a grep query) — mitigation: anchor the regex to actually executing it (`^|;|&&\s*python\s+...scripts/save\.py\s`).
- **B2 risk (medium)**: stdin-piped form (`cat ... | python scripts/save.py`) cannot be inspected from a PreToolUse hook (the hook fires before the pipe runs). C1 acknowledges this as a coverage gap; the agent docs already discourage this form for non-meal data, so risk is bounded.
- **B2 risk (medium, NEW IN ITER 2)**: settings.json registration adds a hook to every PreToolUse Write/Edit/Bash invocation. Performance: hook runs in milliseconds (case dispatch + regex). Mitigation: hook short-circuits at line 32 for tool names outside Write|Edit|Bash (after iter 2 expansion).
- **B2 risk (medium, NEW IN ITER 2)**: json_io ownership rejector reads `.claude/agents/<name>.md` frontmatter on every save_agent_json call. Performance: file read is cheap (< 1ms); cache via `functools.lru_cache` on `_load_owned_files(agent_name)` if profiling shows it matters.
- **B2 risk (medium, NEW IN ITER 2)**: refactoring `sync-agent-data.py` to route through `save_agent_json` may change behavior if these scripts depend on side effects of direct `open()` (e.g., not creating .bak, not running validation). Mitigation: pass `validate=False, create_backup=False, allow_high_severity=True` to preserve current behavior; ownership + image_url deny still apply (these are non-bypassable rejectors). Dev MUST verify the refactor preserves all existing test outputs; if any test fails, dev reports `paused-pending-user`.
- **B2 risk (low, NEW IN ITER 2)**: `strip-image-url-fields.py` refactor: this script REMOVES image_url fields and re-saves; the resulting payload is image_url-free, so `_reject_unsafe_image_payloads` does not fire. The ownership rejector applies (must match owned_files for the agent inferred from filename).
- **B2 risk (low, NEW IN ITER 2)**: hook AND `json_io._reject_unauthorized_ownership` both enforce ownership (defense-in-depth — Bash-level catches direct redirects; json_io-level catches Python-internal writes). Both must agree on the ownership rules (both read the same `.claude/agents/<name>.md` frontmatter). Mitigation: dev MAY extract owned_files reading into a shared helper and call it from both contexts.
- **B3 risk (low)**: if the user is mid-refactor with an active sentinel + uncommitted hook edits, removing the sentinel from the working tree mid-session would re-engage the guard and block their pending Edits. Mitigation: dev verifies no uncommitted `.claude/hooks/` or `.claude/commands/` Edits are in flight (git status) before doing the `rm`. If any are in flight, dev reports `paused-pending-user` and stops.
- **All three**: do NOT propose any destructive git operation (revert, force-push, hard-reset) per Destructive-Action Escalation contract. The `git rm --cached` for B3 is a normal index update, NOT a history rewrite.
