# BA Specification: Unify all agent save behavior — slot-level merge as default, delete --merge-days

**Request ID**: dev-20260417-001800
**Created**: 2026-04-17T00:18:00Z

---

## Goal

Remove the two-flag merge system (`--merge-days` / `--merge-slots`) from the save pipeline and replace it with a single automatic behavior: whenever the target file exists, slot-level merge is performed unconditionally. All 9 agent prompts and the review.md command file are updated to remove flag references.

---

## Context

Cycle 1 (spec-20260416-172720) added `--merge-slots` as a second merge flag alongside the existing `--merge-days`, giving POI agents a non-destructive save path. That fix was correct and passed QA. This cycle completes the simplification: with `merge_agent_slots()` now proven safe for both partial-day (POI) and whole-day (timeline/transportation/budget) outputs, there is no remaining reason to keep two flags. The distinction is purely cosmetic — slot-level merge is a superset of day-level merge for complete-day payloads. Two paths means two ways for future agents to get it wrong. The user has explicitly approved deleting both flags and making slot-level merge the unconditional default.

## Edge Cases & Risks

- **timeline/transportation/budget agents output complete days**: slot-level merge with a complete-day payload is safe — `dict.update()` with all keys present is equivalent to replacement. No data loss risk.
- **First save (file does not exist yet)**: auto-merge must NOT fire when the target file is absent. The existing `if agent_file.exists()` guard in `_merge_existing_slots()` handles this correctly — do not remove it.
- **`_merge_existing_slots()` docstring references "POI agents"**: update the docstring to reflect it is now universal.
- **test_merge_agent_days_backward_compat_still_replaces_whole_day**: this test verifies behavior of the function being deleted. Must be removed or converted to a test of `merge_agent_slots` semantics.
- **Worktree files**: the overnight worktree at `.claude/worktrees/overnight-20260412-c6ec78c9/` contains its own copies of agent .md files with `--merge-days`. These should NOT be modified — they live on a different git branch and are not in active use.
- **`save_batch()` does not use merge flags**: confirmed — `save_batch()` does not call `save_single_agent()` with merge flags, so no change needed there.
