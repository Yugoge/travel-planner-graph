## Goal

- **Hook-ordering**: the new gaode check must run BEFORE the standard tool/path check, otherwise `meals` could be denied at the path layer with a confusing "write target" message instead of the gaode-specific message. Recommended: gaode check is the first decision in `pretool-tool-policy.py:main` after `resolve_agent_type`.
- **Bash command parsing**: `bash -c "$(cat wrapper.sh)"` patterns can hide the gaode invocation. The hook's bash classifier should scan the full command string for tokens AND resolve any script-path argument. Best-effort acceptable; hostile evasion (e.g. `eval $(echo Z2FvZGUtbWFwcw==|base64 -d)`) is out of scope (the user's threat model is "agent forgets the rule", not "agent is adversarial").
- **`google-maps` confusion**: the spec says google-maps remains allowed for non-China destinations. The deny patterns must match `gaode-maps` / `amap` / `高德` ONLY — NOT `google-maps`. Verify by negative test: a meals agent calling `python3 .../google-maps/scripts/places_search.py` is allowed.
- **Skill manifest stays user-invocable**: the gaode skill remains user-invocable via the `Skill` tool when the user (not a subagent) triggers it. The hook discriminates on agent_id, not on the skill metadata. No change needed to `/root/travel-planner/.claude/skills/gaode-maps/skill.md`.
- **`agent_id` resolution race during dispatch**: the LOW-10 fail-open exists because the agent-index entry can be missing during the first PreToolUse on a freshly-dispatched subagent. The gaode-scoped fail-CLOSED is acceptable here because (a) gaode calls are low-frequency, (b) a one-cycle false deny is recoverable (the user re-runs), (c) the alternative (false allow) silently breaks the spec's authority chain. Document the asymmetric behavior in `agent_resolver.py` docstring.
- **Hook performance**: the gaode regex/prefix scans run on every Bash call. Profile in the negative-test suite; if measurable overhead, lazy-load policy on first call (already cached in `policy_registry._CACHE`).
- **`pm` / `product-owner` / `ui-specialist`**: these are currently NOT listed as allowed-to-use-gaode in any agent .md (verified by grep). They are still in §5.1's explicit out-of-scope set, so they should receive the DO-NOT block too OR rely on default-deny by virtue of not being in the allowlist. Recommendation: add the DO-NOT block to ALL non-allowlist agent .md files for documentation parity; let the harness be the actual enforcement.
- **Existing trip data is unaffected**: M1 changes hooks + agent prompts + policy file. No data file under `/root/travel-planner/data/**` is touched.
