- **Hook-ordering**: the new gaode check must run BEFORE the standard tool/path check, otherwise `meals` could be denied at the path layer with a confusing "write target" message instead of the gaode-specific message. Recommended: gaode check is the first decision in `pretool-tool-policy.py:main` after `resolve_agent_type`.
- **Bash command parsing**: `bash -c "$(cat wrapper.sh)"` patterns can hide the gaode invocation. The hook's bash classifier should scan the full command string for tokens AND resolve any script-path argument. Best-effort acceptable; hostile evasion (e.g. `eval $(echo Z2FvZGUtbWFwcw==|base64 -d)`) is out of scope (the user's threat model is "agent forgets the rule", not "agent is adversarial").
- **`google-maps` confusion**: the spec says google-maps remains allowed for non-China destinations. The deny patterns must match `gaode-maps` / `amap` / `高德` ONLY — NOT `google-maps`. Verify by negative test: a meals agent calling `python3 .../google-maps/scripts/places_search.py` is allowed.
- **Skill manifest stays user-invocable**: the gaode skill remains user-invocable via the `Skill` tool when the user (not a subagent) triggers it. The hook discriminates on agent_id, not on the skill metadata. No change needed to `/root/travel-planner/.claude/skills/gaode-maps/skill.md`.
- **`agent_id` resolution race during dispatch**: the LOW-10 fail-open exists because the agent-index entry can be missing during the first PreToolUse on a freshly-dispatched subagent. The gaode-scoped fail-CLOSED is acceptable here because (a) gaode calls are low-frequency, (b) a one-cycle false deny is recoverable (the user re-runs), (c) the alternative (false allow) silently breaks the spec's authority chain. Document the asymmetric behavior in `agent_resolver.py` docstring.
- **Hook performance**: the gaode regex/prefix scans run on every Bash call. Profile in the negative-test suite; if measurable overhead, lazy-load policy on first call (already cached in `policy_registry._CACHE`).
- **`pm` / `product-owner` / `ui-specialist` / `ba` / `qa` / `dev` / `user`** (global agents at `/root/.claude/agents/`): these are currently NOT listed as allowed-to-use-gaode in any agent .md (verified by Grep `(gaode|amap|高德)` over `/root/.claude/agents/` — 0 matches). **Resolution** (per Won't Have decision above, resolves QA OBJ-1): **EXCLUDED** from M1 affected_files. ### Architectural decisions (8 items from /redev dispatch)

**Decision 1 — arch-prop-1 content-based scanner** — **ADOPT (REVISION-2: explicit field whitelist, replacing shape-based dispatch)**.

QA + Codex (cycle-3 review) demonstrated that shape-based dispatch by "string contains slash and resolves under denied prefix" is internally inconsistent: it cannot satisfy AC12 (block path-shaped substring inside `Edit.old_string`) and AC15 (NOT block documentation Edit referencing the same path) simultaneously. REVISION-2 replaces shape-dispatch with an **explicit per-tool field whitelist**. The content scanner walks ONLY fields semantically used as paths/globs/filenames/URLs:

**Read-path matcher receives (path/glob fields)**:
- `Read.file_path`
- `Glob.pattern`, `Glob.path`
- `Grep.path`, `Grep.glob` (Codex Q5: `Grep.glob` was missed in earlier draft; explicitly added — closes the QA-flagged forgotten-field class)
- `Edit.file_path`, `Write.file_path`, `MultiEdit.file_path`, `NotebookEdit.notebook_path`
- `mcp__playwright__browser_take_screenshot.filename`
- `mcp__playwright__browser_file_upload.paths[]`
- `mcp__playwright__browser_snapshot.filename`, `mcp__playwright__browser_console_messages.filename`, `mcp__playwright__browser_network_requests.filename` (output-save paths; flagged for catalog completeness even though they are write-targets not read-sources — listed in T3 catalog as path-typed fields)

**Network-host matcher receives (URL fields)**:
- `WebFetch.url`
- `mcp__playwright__browser_navigate.url`
- `mcp__playwright__browser_evaluate.function`, `mcp__playwright__browser_run_code.code` → URL-substring extraction (regex `https?://[^\s'"\`]+`); each matched URL fed to network-host matcher; non-URL substrings stay unscanned
- All `mcp__claude_ai_*.*` string-valued fields → URL-substring extraction (same regex)

**Bash matcher receives (Bash.command + heredoc bodies)**:
- `Bash.command` and every heredoc body extracted by `bash_write_targets.extract_heredoc_bodies(command)` are each fed through all 4 bash matchers (token, resolved-path, network-host, env-var) — cycle-1 behavior preserved with heredoc-body extension per Decision 5.

**Outbound-exfil exception (env-var matcher only)**:
- `mcp__claude_ai_Gmail__send.body`, `.subject`, `.html`, `.text` (and any other Gmail content fields if schema lists them) → fed to env-var matcher to catch `$AMAP_KEY` / `$GAODE_*` references in outbound mail. Rationale: Gmail send is a network-effect outbound channel, not a local documentation field. Codex Q4 confirmed this exfil-semantics-dominates-content-semantics call. NOT fed to read-path or network-host matchers (the network-host matcher only fires on URLs in Gmail string fields, which is already covered by the previous bullet).

**Content fields — NOT SCANNED (closes documentation-blackhole)**:
- `Edit.old_string`, `Edit.new_string`
- `MultiEdit.edits[].old_string`, `MultiEdit.edits[].new_string`
- `Write.content`
- `NotebookEdit.new_source`
- Any free-text in `Bash.command` that is not the command itself (already cycle-1 behavior)

Documentation/code-review text mentioning banned paths or tokens in any of the above content fields is NEVER blocked by gaode-policy. This is the design commitment that makes AC12 and AC15 simultaneously satisfiable: AC12 tests path/glob fields (Read.file_path, Glob.pattern, etc.); AC15 tests content fields (Edit.old_string with documentation prose).

**Why field whitelist (not shape-dispatch)**: shape-dispatch creates the AC12/AC15 inconsistency QA flagged. Field whitelist makes the scanner's "where" precisely enumerable in spec text — dev cannot misinterpret. Trade-off: a NEW MCP tool with a path/URL field requires a catalog update; T3 verifier (Decision 4) makes that contract explicit and CI-enforceable.
