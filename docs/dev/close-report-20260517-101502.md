## Round 2 — Codex Adversarial Challenge

Codex examined all artifacts and issued findings on each of the four Round 1 concerns.

### Codex findings

**Concern 1 — AC5 undocumented deviation: BLOCKS**

Codex ruling: If AC5 literal deviation is acknowledged, close must use the AC-deviation-PASS branch (close.md branch 1b). Conditions for branch 1b:
- (a) `ac_deviation_with_user_need_satisfied: true` in dev report  
- (b) deviated AC identified by ID with verbatim user-need citation  
- (c) evidence provided  
- (d) the deviated AC does not directly encode the user-need test itself

Current dev-report-20260517-101502.json field: `"ac_deviation_with_user_need_satisfied": false`

Branch 1b conditions (a)-(c) are not satisfied. The close-debate agent cannot update the dev report.

Additionally, the dev report's codex rationale for the border deviation is factually incorrect: "BA spec CSS section explicitly mandates 'pane-days: border-right: 1px solid var(--border)'" — but the BA spec M9 CSS section (ticket-20260517-101502.md line 366-371) states:

```css
.pane { border: none; border-radius: 0; }
.pane-days, .pane-candidates { background: var(--bg-page); }
.pane-middle { background: var(--bg); border-top: 8px solid var(--accent); }
```

No `border-right` or `border-left` appears in the M9 CSS specification. The dev's claim that "BA spec explicitly mandates these as separators" is unsupported by the spec text. AC5 says "border: none" for pane-days and pane-candidates. The implementation added border-right/border-left — a genuine AC5 violation, not a BA-sanctioned deviation.

PROPOSED_FIX: Either (a) remove `border-right: 1px solid var(--border)` from `.pane-days` and `border-left: 1px solid var(--border)` from `.pane-candidates` in main.css so AC5 passes literally, or (b) update the dev report to set `ac_deviation_with_user_need_satisfied: true` with AC5 cited and evidence provided, then the close-report can invoke branch 1b.

**Concern 2 — Thin QA artifact: OBSERVATION_ONLY**

Codex ruling: The close-debate agent independently verified ACs 1–11 via live Playwright in Round 1. Those results are real evidence. The thin qa-report artifact is a documentation gap, not a functional failure. Does not block close on its own.

**Concern 3 — Mobile day-select not sticky: BLOCKS**

Codex ruling: AC8 text states "day selection accessible as a compact sticky UI within the middle pane." The word "sticky" is in the AC literal text. The implementation renders `<select id="mobile-day-select">` as a normal block element inside `.pane-middle-header`. CSS: `.mobile-day-select { display: none; }` at main.css:230 — no `position: sticky`.

On a long mobile timeline at 390px, the pane-middle overflows and the user must scroll to reach the select element at the top of the pane. The select is not permanently visible — it can scroll out of view. The user need in AC8 is "day selection accessible" — sticky positioning is the mechanism AC8 specifies to ensure accessibility on mobile. A non-sticky select does not satisfy the AC as written.

Dev report disposes this as "out of scope — BA spec does not mandate sticky positioning in AC8." This disposal is incorrect: the BA spec does use the word "sticky" in AC8 verbatim.

PROPOSED_FIX: Add `position: sticky; top: 0; z-index: 10;` to `.mobile-day-select` in main.css (or to the `.pane-middle-header` containing it) so the element remains visible during scroll at 390px.

**Concern 4 — Day row visible text separator missing: BLOCKS**

Codex ruling: AC1 says "each row text matches 'Day N · CityName'." The BA spec Technical Hints M5 pseudocode explicitly shows: `row.textContent = cityName ? \`Day \${dayN} · \${cityName}\` : \`Day \${dayN}\``.

The implementation (state.js:680–701) uses two separate spans:
- `label.textContent = \`Day \${dayN}\``  (class: day-row-label day-title)
- `city.textContent = cityName` (class: day-row-city)

No "·" text node exists between them. The visible rendering shows Day N and CityName as two stacked text elements (or concatenated without separator in textContent). The aria-label was correctly set but the visible text structure does not match the spec's "Day N · CityName" format.

The dev report acknowledges codex found this (issue 1: "day-row text missing separator") and disposed it by "aria-label added to day-row buttons." Adding aria-label does not fix the visible text content. The AC says "row text matches" — this refers to what the user sees, not the accessibility tree alone.

PROPOSED_FIX: Change the implementation to use a single textContent with the separator, OR add a separator span between label and city: `const sep = document.createElement("span"); sep.className = "day-row-sep"; sep.textContent = " · ";` inserted between label and city spans, so the visible text reads "Day N · CityName."

## Round 3 — Synthesis and Final Verdict

### Blocker 1 (AC5) — Analysis

The dev report has `ac_deviation_with_user_need_satisfied: false`. This is a hard contractual field. The AC-deviation-PASS branch (close.md branch 1b) requires this field to be `true` with AC deviation documented. The field is explicitly `false`, meaning the dev itself does not claim the deviation is intentional and user-need-satisfying.

Beyond the contractual issue: the dev report's rationale for the border deviation cites a non-existent BA spec mandate. The BA spec M9 CSS section does NOT specify border-right or border-left on pane-days or pane-candidates. The implementation added borders that the spec did not call for, violating AC5's explicit "border: none" requirement.

The close-debate agent cannot update the dev report. The fix required is either: (a) remove the side borders from CSS (one-line fix per pane), or (b) dev updates the report field and re-runs QA. Without either fix, AC5 is a literal failure.

**Blocker 1 disposition: UNRESOLVED. AC5 FAIL.**

### Blocker 2 (AC8 sticky) — Analysis

AC8's literal text: "day selection accessible as a compact sticky UI within the middle pane." The word "sticky" describes the required behavior. The mobile-day-select is not sticky — it is a normal block element that can scroll away on a long timeline.

The dev report's codex finding #4 is acknowledged as a known gap, disposed as "out of scope." But "out of scope" requires the AC to not specify the behavior — and AC8 explicitly specifies it as "sticky." This is not out of scope; it is an unmet AC.

**Blocker 2 disposition: UNRESOLVED. AC8 FAIL.**

### Blocker 3 (AC1 visible text separator) — Analysis

AC1: "each row text matches 'Day N · CityName'." The BA spec Technical Hints M5 pseudocode was the implementation guide: `row.textContent = cityName ? \`Day \${dayN} · \${cityName}\`` — a single text string with "·" separator. The implementation deviated by using two spans without a separator.

The fix applied (aria-label) addresses accessibility but not the visible text. AC1 says "row text matches" — the visible text does not match "Day N · CityName" because no separator exists between the two spans in the rendered output.

**Blocker 3 disposition: UNRESOLVED. AC1 FAIL.**

## Recommended Next-Cycle Fixes

### Fix 1 — AC5: Remove side borders (main.css)

In `web/css/main.css`, remove `border-right` from `.pane-days` and `border-left` from `.pane-candidates`:

```css
.pane-days {
  background: var(--bg-page);
  /* Remove: border-right: 1px solid var(--border); */
  padding: var(--sp-3) 0;
}
.pane-candidates {
  background: var(--bg-page);
  /* Remove: border-left: 1px solid var(--border); */
  padding: var(--sp-4);
}
```

Visual separation is achieved by background-color difference (var(--bg-page) vs var(--bg)) per the M9 spec and AC5. No border needed.

### Fix 2 — AC8: Make mobile-day-select sticky (main.css)

In `web/css/main.css`, add sticky positioning to the element or its container:

```css
@media (max-width: 767px) {
  .mobile-day-select {
    display: block;
    position: sticky;
    top: 0;
    z-index: 10;
    background: var(--bg);
  }
}
```

### Fix 3 — AC1: Add visible separator (state.js)

In `web/js/state.js` `renderDaysPanel()`, replace the two-span approach with a single textContent including the separator (per M5 spec pseudocode):

```javascript
row.textContent = cityName ? `Day ${dayN} · ${cityName}` : `Day ${dayN}`;
```

Note: If the `.day-title` class is still needed for AC12 typography, keep the span but add the separator:

```javascript
const label = document.createElement("span");
label.className = "day-row-label day-title";
label.textContent = cityName ? `Day ${dayN} · ${cityName}` : `Day ${dayN}`;
row.appendChild(label);
// Remove the separate city span
```

Or add a separator text node:

```javascript
const sep = document.createElement("span");
sep.className = "day-row-sep";
sep.setAttribute("aria-hidden", "true");
sep.textContent = " · ";
row.appendChild(label);
row.appendChild(sep);
row.appendChild(city);
```
