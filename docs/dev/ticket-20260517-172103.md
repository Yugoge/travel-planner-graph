# BA Specification: Add Photo Rendering to Trip Editor Cards and Cover

**Request ID**: 20260517-172103
**Created**: 2026-05-17T17:21:03Z
**Tier**: STANDARD

## Goal

Add photo rendering to the interactive trip editor so that candidate cards, timeline selected cards, and the page cover image all display actual photos — matching the visual fidelity of the published Notion-style page. Images are already fetched and stored in `images.json`; this spec covers surfacing them in the editor UI.

## Context

The trip editor at `/trip/beijing-lijiang-dali-20260418-100846` uses a 3-column Notion-style layout (Days | Timeline + Dashboard | Candidates) implemented in Cycle 3. However, all venue cards are text-only: no photos appear on candidate cards (right sidebar) or on timeline selected cards. The published `published-page-desktop.png` shows each restaurant/activity card with a prominent Amap CDN photo and a city cover image at the top. The visual gap degrades the editing experience relative to the published view.

The gap has three components:
1. Candidate cards (right sidebar) — text only, no photo
2. Timeline selected cards — text only, no photo
3. No cover image at top of the page

Image URLs are already present in `data/beijing-lijiang-dali-20260418-100846/images.json` (`pois` dict and `city_covers` dict), but the server API does not expose them and the frontend has no code to render them.

## Requirements (MoSCoW)

### Must Have
- M1: `GET /api/trip/<id>` response includes `images` key containing `{ pois: {...}, city_covers: {...} }` (normalized from images.json — only these two sub-keys, no extra fields)
- M2: `hydrate_trip()` gracefully returns `images: { pois: {}, city_covers: {} }` when `images.json` is absent (no 500 error)
- M3: `_fetchTrip()` in state.js assigns `state.images = { pois: data.images?.pois || {}, city_covers: data.images?.city_covers || {} }` so image data is available during rendering
- M4: `#tpl-candidate-card` in index.html gains an `<img class="card-photo" draggable="false">` element (as first child of the article, before `.card-head`, to match published-page visual order)
- M5: `_buildCard()` calls a new `_writeCardPhoto(node, opt)` helper after cloning the template
- M6: `_buildMealsCandidateGroup()` calls the same `_writeCardPhoto(node, opt)` helper in its option loop (currently the only code path that does NOT go through `_buildCard()`)
- M7: `_writeCardPhoto(node, opt)` looks up `state.images.pois["gaode_" + opt.name_local]`; if a URL is found, sets `img.src = url`; if not found, sets `img.hidden = true` AND calls `img.removeAttribute("src")` (do NOT set `src=""` — browsers request empty src and may show a broken icon)
- M8: `_writeSlotSelected(node, sel)` creates an `<img class="card-photo" draggable="false">` element, applies the same lookup logic, and appends it to `selEl` (before nameDiv to match photo-first visual order)
- M9: A `<img id="trip-cover" class="trip-cover" draggable="false">` element is placed inside the timeline tab content (`#tab-timeline`) at the very top, before the `.timeline-header` div — NOT added to `<header>` or outside `<main>` to avoid grid/layout disruption
- M10: A `renderCover()` function in state.js sets `#trip-cover` src from `state.images.city_covers[cityName]` (where `cityName` is derived via existing `_deriveCityName(_getActiveDay())`); hides cover img and removes src if no match; called from `renderAll()`. The `#trip-cover` img must also have an `onerror` handler: on error, hide and removeAttribute('src').
- M11: CSS additions are limited to `.card-photo` and `#trip-cover` component-local rules only: sizing (e.g., width/height or aspect-ratio), `object-fit: cover`, optional border-radius, and `.card-photo[hidden], #trip-cover[hidden] { display: none; }` — dev MUST NOT write bare `img[hidden]` or `img:not([src])` selectors as those are global and match all img elements on the page; no token changes, no grid changes, no mobile rules

## Edge Cases & Risks

1. **images.json absent** — trips without images.json must not cause a 500. `hydrate_trip()` must catch `FileNotFoundError` for images.json specifically and return the default empty dict.
2. **name_local is None or empty** — if `opt.name_local` is falsy, the lookup key `"gaode_" + opt.name_local` will never match; `_writeCardPhoto` must guard against this: if `!opt.name_local`, skip lookup and hide img.
3. **img src="" triggers browser network request** — do NOT set `img.src = ""` or `img.setAttribute("src", "")` for the no-image case; use `img.removeAttribute("src")` + `img.hidden = true`.
4. **img draggable conflicts with card drag** — browser default makes `<img>` elements draggable, which interferes with existing card drag-and-drop; set `draggable="false"` on all photo img elements.
5. **Cover image stale on day switch** — `renderCover()` must be called from `renderAll()` (not just once on init) so that switching active days updates the cover city photo.
6. **Cover placement outside layout** — placing the cover img outside `#tab-timeline` or inside `<header>` would change the grid; it MUST be the first child of `#tab-timeline`, inside the existing middle pane.
7. **CDN timeout / load error** — `onerror` handler should hide img and remove src to prevent the broken-image icon appearing after a delayed load error.
8. **images.json extra fields** — the file contains `destination` and potentially `fallback_unsplash` fields; the server must normalize to only `{pois, city_covers}` to avoid leaking unnecessary data.
