# BA Specification: Fix Duplicate POIs Across Categories and Broken Day 1 Timeline

**Request ID**: dev-20260413-064500
**Created**: 2026-04-13T06:45:00+08:00

## Goal

Eliminate duplicate POIs that appear in multiple category files (attractions, entertainment, shopping) for the same day, causing items to render twice on the page and breaking the timeline view with overlapping time slots.

## Context

The travel planner uses separate JSON data files per category (attractions.json, entertainment.json, shopping.json), each produced by independent subagents. The HTML generator (`generate-html-interactive.py`) merges all categories into a unified timeline view. When multiple subagents independently include the same place (e.g., a historic street that could be classified as attraction, entertainment, or shopping), the place appears multiple times on the rendered page and in the timeline. The user specifically called out Day 1 where 前门大街 and 杨梅竹斜街 appear in both attractions and entertainment with identical time slots, and noted "这两个地方明显不是entertainment也不是shopping" -- they are streets/attractions, not entertainment.

## Requirements (MoSCoW)

### Must Have
- Remove 9 identified cross-category duplicate POIs from the data files (keep the item in the most appropriate single category, remove from others)
- Fix the timeline deduplication logic in `generate-html-interactive.py` to prevent future duplicates from rendering twice (the current dedup only filters `optional` items with identical `slot:type:name` keys, which misses cross-category duplicates entirely)
- Day 1 timeline must render correctly without overlapping blocks

### Should Have
- Add a systemic cross-category deduplication step in the HTML generator that removes items with the same `name_local` on the same day regardless of category
- Log a warning when cross-category duplicates are detected during generation

### Could Have
- Add validation to the data generation pipeline to prevent subagents from producing cross-category duplicates in the first place

### Won't Have (Non-Goals)
- Restructuring the multi-agent data generation architecture
- Changing how subagents decide category assignments
- Fixing timeline overlaps caused by different (non-duplicate) items with genuinely overlapping schedules

## Edge Cases & Risks

- Some POIs legitimately appear on different days in different categories (e.g., 回民街 on Day 9 as attraction, Day 10 as shopping) -- dedup must be per-day only
- 外滩 (Day 12) and 田子坊 (Day 13) have different time slots across categories -- these represent the same place visited at different times (daytime attraction vs evening entertainment); the generator should deduplicate by name_local per day, keeping the entry with the earliest start time or the one from the "primary" category
- 前门大街 appears in THREE categories on Day 1 (attractions + entertainment + shopping) -- all three must be resolved to a single entry
- The shopping entry for 前门大街 has a different time slot (19:15-20:15) vs the attractions/entertainment entries (18:45-19:00) -- need to decide which time to keep

## Acceptance Criteria

### AC1: No duplicate name_local values within same day across all categories
- GIVEN the data files (attractions.json, entertainment.json, shopping.json)
- WHEN items are loaded for any given day
- THEN no name_local value appears in more than one category file for that day

### AC2: Day 1 timeline renders without overlapping duplicate blocks
- GIVEN Day 1 data after deduplication
- WHEN the timeline view is rendered
- THEN 前门大街 and 杨梅竹斜街 each appear exactly once

### AC3: HTML generator deduplicates cross-category items
- GIVEN any future data where the same name_local appears in multiple categories for a day
- WHEN the timeline view is built (lines 2553-2601 of generate-html-interactive.py)
- THEN the dedup logic removes cross-category duplicates, keeping the item from the highest-priority category (attractions > entertainment > shopping)

### AC4: All 9 identified duplicates resolved
- GIVEN the full dataset across 15 days
- WHEN a cross-category duplicate scan is run
- THEN zero duplicates are found

## Technical Hints

- Affected data files:
  - `data/china-20260412-092624/attractions.json`
  - `data/china-20260412-092624/entertainment.json`
  - `data/china-20260412-092624/shopping.json`
  - `data/china-20260412-092624/timeline.json` (may need regeneration)
- Affected code file:
  - `scripts/generate-html-interactive.py` (lines 2553-2601, timeline dedup logic)
- Current dedup flaw (line 2594-2601): The key is `slot + ':' + e._type + ':' + name` -- because `_type` is part of the key, an "attraction" and "entertainment" with the same name and time slot are treated as DIFFERENT entries. The dedup only filters out `optional` duplicates with the SAME type.
- Fix approach: Add a second dedup pass keyed on `name_local` (or `name_base`) only, ignoring `_type`, with category priority: attractions > entertainment > shopping
- Related patterns: The existing dedup was added to handle duplicate brand cards within shopping (commit cfc5766 reference at line 748)
