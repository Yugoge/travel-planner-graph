## Goal

Collapse the viewer/editor split: `/trip/<id>` is now one unified page that is simultaneously the published viewer AND the fully functional editor. Remove the `EDITOR_MODE` boolean entirely from the React template and from the Python HTML-generation layer. All 12 editor features listed below must be unconditionally active.

---

## Context

The current codebase ships two code paths:

- `generate_html(gen)` in `render_html_builders.py` — injects `EDITOR_MODE=false`, produces the published read-only page
- `generate_editor_html(gen, trip_id)` — injects `EDITOR_MODE=true`, produces the editor page served by `serve-trip.py`

The React template (`react_template.tpl`) gates editor UI behind `EDITOR_MODE` checks at ~15 locations. The editor path (`EDITOR_MODE=true`) already passes `effectiveDay` to both `KanbanView` and `TimelineView` (via `const day = EDITOR_MODE ? effectiveDay : publishedDay` at line 1930), but this conditional must become unconditional once `EDITOR_MODE` is removed.

The `window.setEditorSelection` bridge is the only current save path; it silently swallows network errors, lacks save status feedback, offline detection, and 409 conflict handling. All 12 features listed below address these gaps.

Prior cycle (task `20260517-211850`) shipped `generate_editor_html()` and the EDITOR_MODE injection. This cycle removes that split entirely.

## Edge Cases & Risks

1. **editorTripData null on load**: `effectiveDay` useMemo and CandidatesSidebar must handle `editorTripData === null` gracefully (loading skeleton or null render) — not throw
2. **409-soft vs HTTP 409 distinction**: session conflict returns HTTP 200 + `{conflict: "409-soft"}`; only `StateMachineError` raises HTTP 409. Both must show ConflictBanner but with different severity
3. **stale route responses**: `/api/route` is async and responses may arrive out of order; discard responses whose `request_seq` is not the latest for that slot pair
4. **adaptV2Option vs PLAN_DATA card shape**: `adaptV2Option()` output is for CandidatesSidebar only; never use it to replace enriched PLAN_DATA cards in KanbanView/TimelineView
5. **Accommodation slot shape in editorDay**: accommodation may not have `.options[]` in all day files; feature 14 must check `editorDay?.accommodation?.options` before enabling live cover
6. **Mobile breakpoint vs useBreakpoint**: existing `useBreakpoint()` returns 'sm' at <640px; new `isMobileLayout` uses <768px — both coexist; do not remove existing `bp` logic
7. **Two-step tap cancellation**: pending selection must be cancellable (tap away or tap another candidate) to avoid stuck UI state
8. **Budget recompute response shape**: `BudgetRequest.day` is `Optional[int]`; pass integer day number not string; only update `day_total` from response unless response provides unambiguous per-category keys
9. **generate_html signature change**: any other caller of `generate_html(gen)` (e.g., `generate-html-interactive.py` line 598) must be updated or verified to not break — they call the old 1-arg form; the new function must accept `trip_id=None` with a default or they will crash
