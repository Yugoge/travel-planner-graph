**Request ID**: 20260518-101127

## Goal

Collapse the viewer/editor split: `/trip/<id>` is now one unified page that is simultaneously the published viewer AND the fully functional editor. Remove the `EDITOR_MODE` boolean entirely from the React template and from the Python HTML-generation layer. All 12 editor features listed below must be unconditionally active.

---

## Context

The current codebase ships two code paths:

- `generate_html(gen)` in `render_html_builders.py` — injects `EDITOR_MODE=false`, produces the published read-only page
- `generate_editor_html(gen, trip_id)` — injects `EDITOR_MODE=true`, produces the editor page served by `serve-trip.py`

The React template (`react_template.tpl`) gates editor UI behind `EDITOR_MODE` checks at ~15 locations. The editor path (`EDITOR_MODE=true`) already passes `effectiveDay` to both `KanbanView` and `TimelineView` (via `const day = EDITOR_MODE ? effectiveDay : publishedDay` at line 1930), but this conditional must become unconditional once `EDITOR_MODE` is removed.

The `window.setEditorSelection` bridge is the only current save path; it silently swallows network errors, lacks save status feedback, offline detection, and 409 conflict handling. All 12 features listed below address these gaps.

Prior cycle (task `20260517-211850`) shipped `generate_editor_html()` and the EDITOR_MODE injection. This cycle removes that split entirely.

## Edge Cases & Risks

1. **editorTripData null on load**: `effectiveDay` useMemo and CandidatesSidebar must handle `editorTripData === null` gracefully (loading skeleton or null render) — not throw
2. **409-soft vs HTTP 409 distinction**: session conflict returns HTTP 200 + `{conflict: "409-soft"}`; only `StateMachineError` raises HTTP 409. Both must show ConflictBanner but with different severity
3. **stale route responses**: `/api/route` is async and responses may arrive out of order; discard responses whose `request_seq` is not the latest for that slot pair
4. **adaptV2Option vs PLAN_DATA card shape**: `adaptV2Option()` output is for CandidatesSidebar only; never use it to replace enriched PLAN_DATA cards in KanbanView/TimelineView
5. **Accommodation slot shape in editorDay**: accommodation may not have `.options[]` in all day files; feature 14 must check `editorDay?.accommodation?.options` before enabling live cover
6. **Mobile breakpoint vs useBreakpoint**: existing `useBreakpoint()` returns 'sm' at <640px; new `isMobileLayout` uses <768px — both coexist; do not remove existing `bp` logic
7. **Two-step tap cancellation**: pending selection must be cancellable (tap away or tap another candidate) to avoid stuck UI state
8. **Budget recompute response shape**: `BudgetRequest.day` is `Optional[int]`; pass integer day number not string; only update `day_total` from response unless response provides unambiguous per-category keys
9. **generate_html signature change**: any other caller of `generate_html(gen)` (e.g., `generate-html-interactive.py` line 598) must be updated or verified to not break — they call the old 1-arg form; the new function must accept `trip_id=None` with a default or they will crash
10. **Bidirectional drag source-slot clearing**: when a placed card is dragged plan→candidates, the source slot's `selected_option_id` must be cleared before re-render; if the drag is cancelled mid-air, the slot must remain selected
11. **Slot↔slot move atomicity**: slot-to-slot move must clear source AND set destination in a single `editorSelections` update; no intermediate render between clear and set
12. **Cross-meal copy + already-selected deselect**: if option A is selected in breakfast and user drags option A from the Meals group to lunch, the copy-then-select logic must detect option A is already in lunch.options (idempotent check) and not duplicate it
13. **Missing vs absent slot distinction**: a slot key that is present but has `options: []` is NOT the same as a slot key that is absent from effectiveDay; only truly absent keys trigger "missing" state
14. **Export button validation span**: `_anyValidationError()` checks all days (not just the active day) — export buttons remain disabled until every day's required slots are filled

### Key Implementation Notes

1. **generate_html backward compatibility**: `scripts/generate-html-interactive.py` line 598 calls `_bld.generate_html(self)` (one arg). The new function signature MUST be `generate_html(gen, trip_id=None)` with `trip_id` defaulting to `None`. When `trip_id is None`, inject `const TRIP_ID = null;` into `HTML_SCRIPT`. This preserves backward compatibility with all one-arg callers. Do NOT make `trip_id` a required positional arg.

2. **409-soft detection**: Check `resp.json().conflict === '409-soft'` in the React `fetch` callback — this is an HTTP 200 response with conflict info in the body. HTTP 409 is a separate case (StateMachineError). Both should trigger ConflictBanner but with different messages if desired.

3. **effectiveDay useMemo guard**: After removing `EDITOR_MODE`, the memos and effects that fetch editorTripData must handle the null case: `if (!editorTripData) return publishedDay;` (line 1900's equivalent, but unconditional).

4. **TRIP_ID injection**: `const TRIP_ID = __TRIP_ID__;` must remain in HTML_SCRIPT (replaced by `render_html_builders.py`). `EDITOR_MODE` line is removed. The `__TRIP_ID__` placeholder is still needed.

5. **stage mutation shape**: verified from `scripts/lib/server/save.py` `_apply_stage_mutation`: mutation needs `type: "stage"` and `to_stage: "user-selected"`. Including `from_stage` is safe (save.py reads it for validation) but must match the actual current stage.

6. **CandidatesSidebar prop addition**: add `editorSelections` prop to `CandidatesSidebar` at line 1789. The call site at line 2120 must pass `editorSelections={editorSelections}`.

7. **useBreakpoint vs isMobileLayout**: `useBreakpoint()` returns 'sm' at <640px. For mobile layout (AC13), add `isMobileLayout = window.innerWidth < 768` (or equivalent React state from a resize listener). Both can coexist.

8. **Budget recompute endpoint**: `/api/budget/recompute` already exists at `scripts/serve-trip.py:218`. Do NOT add it again.

9. **adaptV2Option output scope**: `adaptV2Option(opt)` converts v2 option fields for CandidatesSidebar rendering ONLY. Do not use its output to populate or replace KanbanView/TimelineView cards.

10. **Route gaps request_seq**: must be monotonically increasing per slot pair; use a per-pair counter or timestamp to filter stale responses on receipt.

11. **Bidirectional drag payload**: the `dragstart` handler must set `data-origin-slot-id` (with the `-id` suffix — matches `data-origin-slot-id` in M19 and `dataset.originSlotId` in `web/js/drag.js:73`) on placed cards so the `drop` handler knows to clear the source slot. Note: the DOM attribute is `data-origin-slot-id`; the dataTransfer JSON field and `/api/save` mutation field are both `origin_slot_id` (snake_case). `origin_slot_id` MUST always be the concrete meal slot id (`breakfast`, `lunch`, or `dinner`), never `"meals-any"`. A placed card in the timeline carries its current `slotId` as `slot_id` in the dataTransfer payload; the drop handler checks if the drop target is the CandidatesSidebar container and, if so, sets `editorSelections[dayKey + ':' + srcSlotId] = null` (key-presence deselect, per AC10/AC17) and POSTs the clear mutation.

12. **Slot↔slot move atomic update**: use a functional state update that takes the previous `editorSelections` and returns a new object with the source key present and set to `null` (NOT deleted — deleting the key causes the hasOwnProperty resolver from AC10 to fall back to the persisted `slot.selected_option_id`, resurrecting the source slot as still-selected) and the destination key set to the `option_id`, in one functional update call; this prevents intermediate re-renders.

13. **Meals dedup logic**: iterate `['breakfast', 'lunch', 'dinner']` in order; for each slot's `options`, add to the merged array only if `option_id` not already in a `Set`. Cards in the merged array carry `originSlotId` of the first slot that contained them.

14. **Cross-meal copy**: in `requestSelectMutation`, before `slot.selected_option_id = optionId`, check if `MEAL_SLOTS.has(slotId)` and if `optionId` is absent from `slot.options`; if so, find the option object across all meal slot `options` arrays and push a shallow copy. This is the exact logic in `web/js/state.js:requestSelectMutation` — mirror it in the React equivalent.

15. **Export endpoints**: `/api/export/pdf` and `/api/export/ical` already exist at `serve-trip.py:222/308` via `handle_export`. Do NOT add new routes. The response shape includes `file_path` on success.

16. **setInterval for save status**: use a single `setInterval` with 15 000ms in a `useEffect` that is set up once on mount. The interval callback reads `saveState` and `lastSaveTs` from current state (use a ref if needed to avoid stale closure) and updates the displayed text.

17. **conn-status element**: render as a `<span>` in the header JSX alongside the save status badge; toggled in the same `online`/`offline` event listener as OfflineBanner.

18. **ConflictBanner dismiss**: add a close button to the banner JSX; its `onClick` calls a state setter `setConflict(false)` (or equivalent) which hides the banner without page reload. The existing reload button calls `window.location.reload()`.

19. **Approve button required-slot validation**: do NOT mirror `_allRequiredSlotsFilled` from `web/js/state.js` — that function iterates `ALL_SLOT_KEYS` (all 7 slots) and would incorrectly gate on activity slots. Instead, implement the React equivalent using the explicit constant: `const REQUIRED_SLOT_KEYS = ['accommodation', 'breakfast', 'lunch', 'dinner'];`. For each key in `REQUIRED_SLOT_KEYS`, evaluate: if the slot key is ABSENT from `effectiveDay` (missing state per AC22) → not all filled (counts as unfilled, disables Approve); if the slot key is present AND the slot is not skipped AND has no `selected_option_id` → not all filled. Activity slots (`morning_activity`, `afternoon_activity`, `evening_activity`) MUST NOT be checked here. The same `REQUIRED_SLOT_KEYS` constant governs AC26 export button gating. On the backend, `validators.py:_check_stage_gate` must be updated to apply `STAGE_GATE_VIOLATION` only for `slot_id in REQUIRED_SLOT_KEYS` (while `_check_selected_id_exists` continues for all 7 slots).

20. **"missing" slot detection**: a slot is "missing" only when `_getSlotByKey(effectiveDay, slotId)` returns `null` (key absent). An empty options array is NOT missing — it is a normal slot with no candidates.
