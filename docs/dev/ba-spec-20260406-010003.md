# BA Specification: Fix Gaode API Key Environment Variable Name in fetch-images-batch.py

**Request ID**: dev-20260406-010003
**Created**: 2026-04-06T01:00:03

## Goal

Fix `scripts/fetch-images-batch.py` to read the Gaode (Amap) API key from the correct environment variable `AMAP_MAPS_API_KEY` instead of the incorrect variable name `GAODE_API_KEY`, which is never populated, causing geocoding lookups to silently fail.

## Context

The script uses Gaode's REST API (`restapi.amap.com/v3/geocode/geo`) as a fallback for city coordinate resolution. The working API key lives in the environment variable `AMAP_MAPS_API_KEY` (consistent with the gaode-maps skill scripts under `.claude/skills/gaode-maps/`). However, `fetch-images-batch.py` reads from `GAODE_API_KEY` (line 130), which is never set, so `gaode_key` is always `None` and the geocoding branch is always skipped. The orchestrator originally described this as a hardcoded expired key (`c0a3b4e300f38b4038845a8a24a0e348`), but that key no longer exists in the file; the current issue is the wrong env var name causing the same symptom (geocoding never executes).

## Requirements (MoSCoW)

### Must Have
- Change `os.environ.get("GAODE_API_KEY")` to `os.environ.get("AMAP_MAPS_API_KEY")` at line 130
- Update the comment on line 127 to reference `AMAP_MAPS_API_KEY`

### Should Have
- Verify no other references to `GAODE_API_KEY` remain in the script

### Could Have
- Add a warning log when `AMAP_MAPS_API_KEY` is not set, to aid future debugging

### Won't Have (Non-Goals)
- Changing env var names in any gaode-maps skill scripts (they already use `AMAP_MAPS_API_KEY` correctly)
- Changing Google Maps API key handling
- Any refactoring beyond the key variable name fix

## Edge Cases & Risks

- If `AMAP_MAPS_API_KEY` is also not set in the runtime environment, geocoding will still silently skip — this is acceptable existing behavior (graceful degradation)
- No other files reference `GAODE_API_KEY`; this is an isolated single-file fix

## Acceptance Criteria

### AC1: Correct env var name used
- GIVEN the script is run in an environment where `AMAP_MAPS_API_KEY` is set to a valid key
- WHEN city coordinate geocoding fallback is triggered
- THEN the Gaode geocoding API call is made successfully (not skipped)

### AC2: Wrong env var name removed
- GIVEN the updated script
- WHEN grepped for `GAODE_API_KEY`
- THEN no matches are found

### AC3: No regression to skill scripts
- GIVEN the gaode-maps skill scripts
- WHEN grepped for `AMAP_MAPS_API_KEY`
- THEN they still reference `AMAP_MAPS_API_KEY` (unchanged)

## Technical Hints

- Affected files: `scripts/fetch-images-batch.py` (lines 127, 130)
- Related patterns: gaode-maps skill scripts at `.claude/skills/gaode-maps/scripts/` all use `AMAP_MAPS_API_KEY` — follow that convention
- Constraints: Single variable rename; no logic changes required
