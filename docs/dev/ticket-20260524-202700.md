## Edge Cases & Risks

- **Drag API in headless Playwright**: HTML5 drag-and-drop requires explicit `dataTransfer` simulation in Playwright. Use `page.dispatchEvent` with dragstart/drop sequence or Playwright's `dragTo` API. The board card has `onDragStart` setting `dataTransfer.setData`; the sidebar has `onDrop` calling `handleSidebarDrop`. Both must be exercised.
- **`/api/save` interception**: The Playwright test must intercept or observe the POST to `/api/save` to confirm the mutation payload. Use `page.route` or `page.waitForRequest`.
- **useEffect dep array change (M5)**: Adding `editorSelections` to the dep array at line 2918 may cause `preserveCurrentAccommodationOption()` to run more frequently. Since the function is idempotent (checks `options.some(o => o.option_id === selectedAccId)` before pushing), this is safe. Dev should verify no infinite loop results from the new dep.
- **iPending visual regression reversal (M4)**: The prior `candidateCardStyle` helper (now dead) encoded `isPending` as blue border `#3b82f6` + blue background `#eff6ff`. The restored affordance should match or improve on this. The inline style on the card div currently hard-codes `background: '#fff'` and `border: isSelected ? ...`; dev must add an `isPending` branch.
- **IIFE dedup scope (M6)**: The duplicate IIFEs at lines 2425/2456 and 2479/2513 compute the same value. The simplest fix is to extract the result into a `const` before the JSX block. The `getSlotLabel()` extension (Could Have) would be cleaner but is not required.
- **Regeneration required**: Any code change to `react_template.tpl` must be followed by running `generate-html-interactive.py` for both active plans and `deploy-travel-plans.sh` before Playwright verification, or the browser will test stale HTML.
