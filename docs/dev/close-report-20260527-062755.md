**Codex PROPOSED_FIX 2 — Persistence/reload durability:**

Classification: OUT OF SCOPE — real observation, does not block close.

The `save.py` `_apply_select_mutation` (lines 75-104) writes only `selected_option_id` to disk; it never clears the `skipped` field. The fix is client-side only — `editorTripData` React state has `skipped=false` in-session, but `day-01.json` on disk retains `skipped: true`. On page reload, the API fetch re-reads the JSON from disk, which means the slot would be gated again on first load after the session is abandoned without a separate `skip` mutation being persisted.

However, the spec's acceptance criteria AC1-AC4 are entirely in-session assertions (`editorTripData.days[N].slots[srcSlotId].skipped`, `isGated`, `data-droppable`). No AC mentions server persistence, disk state, or page-reload durability. The user's verbatim complaint ("早餐午餐移除默认之后就无法添加新的了") describes an in-session interaction failure — not a reload-then-try-again failure. This is a pre-existing architectural gap (skipped flag on disk vs. in-session state) that is outside the spec's stated scope. Routing to `out_of_scope_observations` for a future cycle, not a close blocker.

**Codex PROPOSED_FIX 3 — Mobile/tap-to-select layout:**

Classification: OUT OF SCOPE — explicitly excluded by spec.

The spec's Setup/Environment section states: "non-UI — hook; cycle does not produce (1) rendered UI changes, (2) browser interaction, (3) Playwright invocation, (4) screenshot evidence, or (5) any change to user-triggered code paths other than state mutation inside the drag handler."
