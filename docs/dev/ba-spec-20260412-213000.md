# BA Specification: Fix City Covers, Meals Layout, and Shopping Images

**Request ID**: dev-20260412-213000
**Created**: 2026-04-12T21:30:00+08:00

## Goal

Fix three distinct bugs in the travel-planner rendering pipeline: (1) city cover images are empty because `location_local` is blank in the skeleton, (2) meals render in separate rows per meal type instead of a single horizontal row per day, and (3) shopping brand cards show default/empty images despite real images being available in cache.

## Context

The travel-planner generates an interactive HTML itinerary from JSON data files. The current plan `china-20260412-092624` has 15 days across 5 cities (Beijing, Datong, Chengdu, Xi'an, Shanghai). The image fetching script `fetch-images-batch.py` and the HTML generator `generate-html-interactive.py` work together but have data flow issues causing these three symptoms.

## Requirements (MoSCoW)

### Must Have

- **BUG-1 (City Covers)**: `fetch_cities()` must resolve city Chinese names even when `plan-skeleton.json` has empty `location_local`. The fix should derive Chinese city names from the `location` field (English name mapping) or from POI data in agent files.
- **BUG-2 (Meals Layout)**: Meals section must render all three meal types (breakfast, lunch, dinner) as cards in a single horizontal grid row, not as three separate sub-sections each with their own heading and grid.
- **BUG-3 (Shopping Images)**: Shopping brand cards must use the parent mall's image from the images cache (already available via `gaode_<name_local>` keys) instead of falling back to `brand_<name>` keys that never exist.

### Should Have
- After fixing BUG-1, re-run image fetching to populate city covers for all 5 cities.
- Verify all 10 shopping POIs across 7 days have real images, not empty strings.

### Won't Have (Non-Goals)
- Modifying `plan-skeleton.json` schema or upstream generators.
- Adding new features to the meal or shopping card UI.
- Changes to the image fetching API integrations (Gaode/Google).

## Root Cause Analysis

### BUG-1: City Covers Empty

**Symptom**: `images.json` has `city_covers: {}` -- no city images fetched.

**Root Cause**: `fetch_cities()` at line 525 builds `city_local_map` from `plan-skeleton.json` by reading `day["location_local"]`. Every day in the skeleton has `location_local: ""` (empty string). The code at line 528 (`if loc and loc_local`) requires BOTH to be non-empty, so no cities enter the map. With an empty map, no fetches happen.

**Evidence**: `plan-skeleton.json` lines 20, 72, 120, 180, 228, etc. all show `"location_local": ""`.

**Fix Direction**: When `location_local` is empty, derive the Chinese city name from an alternative source. Options:
1. Use a static English-to-Chinese mapping for the known cities (Beijing=北京, Datong=大同, Chengdu=成都, Xi'an=西安, Shanghai=上海).
2. Better: Look up the city name from any POI in agent files for that day -- agent files contain `location_local` fields with Chinese city names.
3. Best: Use the Gaode geocoding API already available in `_resolve_city_coord()` to translate the English city name.

### BUG-2: Meals Three Separate Rows

**Symptom**: Meals section renders three sub-sections: "Breakfast" with its grid, then "Lunch" with its grid, then "Dinner" with its grid.

**Root Cause**: In `generate-html-interactive.py` lines 2167-2220, the React template iterates `['breakfast', 'lunch', 'dinner']` and for EACH type creates a separate `<div>` with its own heading (`<div style={{ marginBottom: '16px' }}>`) and grid. This naturally stacks vertically.

**Fix Direction**: Remove the per-type heading and wrapper div. Collect ALL meal cards (breakfast + lunch + dinner) into a single flat array and render them in ONE grid. Each card should still display its meal type (breakfast/lunch/dinner) as a badge/label within the card itself, not as a section header.

### BUG-3: Shopping Brand Images Default/Empty

**Symptom**: Shopping cards show no image (empty string) or generic fallback.

**Root Cause**: In `generate-html-interactive.py` lines 746-757, when brands exist, the code tries `brand_cache_key = f"brand_{brand['name']}"` (e.g., `brand_Ruifuxiang Silk`). This key format does not match anything in `images.json` pois cache, which uses keys like `gaode_前门大街`. The fallback to `mall_image` should work because `mall_image` is set at line 739 from `shop_item.get("image_url")`, BUT `_get_placeholder_image("attraction", ...)` at line 739-744 looks up using the shopping center's name -- and for the China plan, these ARE in cache (e.g., `gaode_前门大街` matches). The real issue is that the `image_url` field in `shopping.json` already contains real Gaode URLs, and `mall_image` should pick them up. Need to verify the actual rendering output to confirm whether the image is truly empty or just displaying incorrectly.

**Secondary Investigation**: The `shopping.json` items already have `image_url` fields with real Gaode URLs. So line 739 (`shop_item.get("image_url", "")`) should return the real URL. The issue may be that brand cards (which are split from the parent) use `brand_img` from line 754-757, which tries the nonexistent `brand_*` cache key and then falls back to `mall_image`. If `mall_image` is correct, brand images should work. Need to verify if `shopping.json` items are actually missing `image_url` or if it is being overwritten.
