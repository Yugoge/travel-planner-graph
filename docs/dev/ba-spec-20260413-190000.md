# BA Specification: Fix sync-agent-data.py meal_types Detection Bug

**Request ID**: dev-20260413-190000
**Created**: 2026-04-13T19:00:00+08:00

## Goal

Fix the bug in `sync-agent-data.py` that causes it to detect zero meal types from the schema, resulting in meals never being synced from timeline.json to meals.json. This is the root cause of stale meal times appearing in the generated HTML.

## Context

The sync script is designed to use timeline.json as the Single Source of Truth and inject authoritative times into agent files (meals.json, attractions.json, etc.). The HTML generator reads from meals.json (not directly from timeline.json) for meal times. When sync fails to update meals.json, the HTML shows stale times.

The bug was introduced when the meals schema was refactored to use a `meal_slot` wrapper (containing `primary` + `alternatives`) instead of directly referencing `meal_item`. The sync script's config loader still looks for `$ref: "#/$defs/meal_item"` in the day_entry properties, but the schema now uses `$ref: "#/$defs/meal_slot"`. This means `self._config["meal_types"]` is always an empty list, so `_sync_meals` iterates over zero meal types and reports "No changes needed."

## Requirements (MoSCoW)

### Must Have
- Fix `_load_config()` in sync-agent-data.py to correctly detect meal types from the current schema (match `meal_slot` ref, not `meal_item`)
- After fix, running sync must update meals.json Day 1 lunch from 15:10-15:40 to 13:00-13:40 (matching timeline.json)
- Generated HTML must reflect the corrected times

### Should Have
- Make the meal_type detection more robust (e.g., check for either `meal_item` or `meal_slot` ref, or use a hardcoded fallback list)

### Could Have
- Add a warning/error when zero meal_types are detected (likely indicates a schema mismatch)

### Won't Have (Non-Goals)
- Refactoring the HTML generator to read directly from timeline.json (the sync-then-read-agent-files pattern is correct by design)
- Fixing the 58 schema validation warnings (separate issue)

## Edge Cases & Risks

- If the schema is refactored again in the future (e.g., to a different wrapper type), the same bug could recur. Consider hardcoding `["breakfast", "lunch", "dinner"]` as a fallback.
- Other agent sync methods (attractions, entertainment, etc.) use `_inject_time()` which does name-based matching and is not affected by this bug.

## Acceptance Criteria

### AC1: Meal types correctly detected
- GIVEN the current meals.schema.json with `meal_slot` references
- WHEN `_load_config()` runs
- THEN `self._config["meal_types"]` contains `["breakfast", "lunch", "dinner"]`

### AC2: Sync updates stale meal times
- GIVEN meals.json Day 1 lunch has time 15:10-15:40 and timeline.json has 13:00-13:40
- WHEN `sync-agent-data.py china-20260412-092624` runs
- THEN meals.json Day 1 lunch time is updated to 13:00-13:40

### AC3: HTML shows correct times
- GIVEN meals.json has been synced with correct times
- WHEN HTML is regenerated
- THEN the Day 1 timeline shows lunch at 13:00-13:40

## Technical Hints

- Affected file: `scripts/sync-agent-data.py`, line 63-64 in `_load_config()`
- The bug: `v.get("$ref") == "#/$defs/meal_item"` should be `v.get("$ref") == "#/$defs/meal_slot"`
- The fix is a single-line change on line 63
- Related schema: `schemas/meals.schema.json` (day_entry properties reference `#/$defs/meal_slot`)
- Data flow: timeline.json -> (sync) -> meals.json -> (HTML generator) -> HTML output
