# BA Specification: Fix NameError 'days' in check_semantics

**Request ID**: dev-20260406-010002
**Created**: 2026-04-06T01:00:02Z

## Goal

Fix a `NameError: name 'days' is not defined` crash at line 708 of `scripts/plan-validate.py`
inside the `check_semantics` function, caused by a missing variable assignment before a `for` loop.

## Context

`check_semantics` validates timeline data when `agent == "timeline"`. It correctly retrieves
`timeline_data` from `all_data` at line 689, then calls `check_travel_segments(timeline_data, trip)`
which internally derives its own `days` list. However, the subsequent loop at line 708 references
`days` directly — a variable that was never assigned in `check_semantics` scope. Python's error
message ("Did you mean: 'day'?") refers to the loop variable `day`, not a fix.

The identical extraction pattern `timeline_data.get("data", {}).get("days", [])` is used
consistently in at least four other places in the same file (lines 347, 422, 631, 1030).

## Requirements (MoSCoW)

### Must Have
- Add `days = timeline_data.get("data", {}).get("days", [])` immediately before the `for day in days:` loop at line 708.

### Should Have
- Placement should be adjacent to the `days_with_acc` computation (lines 701-706) for logical grouping.

### Could Have
- Nothing additional.

### Won't Have (Non-Goals)
- Refactoring the broader `check_semantics` function.
- Changes to `check_travel_segments` or any other function.
- Altering validation logic for meals or accommodation.

## Edge Cases & Risks

- If `timeline_data` has no `"data"` key or no `"days"` key, the `.get` chain returns `[]` and the loop body is skipped — same safe behavior as every other call site.
- The fix is one line; no secondary effects are possible.

## Acceptance Criteria

### AC1: Script does not crash on timeline validation
- GIVEN a valid plan JSON with timeline data
- WHEN `plan-validate.py` is run and reaches the timeline `check_semantics` block
- THEN the script completes without `NameError` and produces validation output

### AC2: Existing meal and accommodation checks execute correctly
- GIVEN a timeline day entry with `meal_ref` and `accommodation_ref` fields
- WHEN `check_semantics` iterates over `days`
- THEN meal presence and accommodation presence checks run and report issues or pass as expected

## Technical Hints

- Affected file: `scripts/plan-validate.py` — one insertion at line 708 (before the `for` loop)
- Pattern to follow: `days = timeline_data.get("data", {}).get("days", [])` — identical to line 631 inside `check_travel_segments`
- No imports, constants, or other functions need changes
