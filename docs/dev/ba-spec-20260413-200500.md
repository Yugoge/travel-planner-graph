# BA Specification: Hard-Blocking Time Conflict Gate in save.py

**Request ID**: dev-20260413-200500
**Created**: 2026-04-13T20:05:00Z

## Goal

Add a hard-blocking time conflict gate to `scripts/save.py` so that when a timeline save contains non-optional time conflicts, save.py REFUSES to write the file (exit code non-zero, file unchanged). Not a warning, not an error log -- a hard block.

## Context

`save.py` currently delegates validation to `plan-validate.py` via `lib/json_io.validate_agent_data()`. The existing validation pipeline already detects time overlaps via `check_all_activity_overlaps()` in plan-validate.py, which produces HIGH severity issues for non-optional overlaps. However, this cross-agent overlap check is **only run when `agent_filter` is None** (line 1469: `if not agent_filter:`). When save.py calls `validate_agent_data()` with a specific agent name, `run_pipeline()` receives `agent_filter="timeline"`, which **skips the cross-agent overlap check entirely**. This means timeline saves currently pass validation even with time conflicts.

## Requirements (MoSCoW)

### Must Have
- When saving timeline data (`--agent timeline`), detect non-optional time conflicts BEFORE writing the file
- Non-optional time conflicts cause save to REFUSE (exit code 1, file unchanged)
- Reuse existing `_check_time_overlap()`, `_collect_all_activities_for_day()`, `_is_same_activity()`, and `check_all_activity_overlaps()` from plan-validate.py
- Optional activities (`optional: true`) are excluded from conflict detection (existing logic already handles this -- INFO severity vs HIGH)
- Same-event deduplication (timeline + POI agent referring to same event) is preserved (existing `_is_same_activity()` logic)
- Travel segments that overlap with non-optional activities are also blocking conflicts

### Should Have
- Clear error output listing each conflict (activity names, agents, times) so the agent can fix them
- The `--allow-high` flag should still bypass this gate (consistent with existing behavior)
- The `--no-validate` flag should still bypass this gate (consistent with existing behavior)

### Could Have
- A dedicated `--allow-conflicts` flag separate from `--allow-high` for more granular control

### Won't Have (Non-Goals)
- Changing the schema to add an `optional` field to `timeline_activity` (timeline activities are assumed non-optional; the optional flag lives on POI agent data)
- Modifying plan-validate.py's existing logic -- only reusing it
- Handling intentional overlaps (e.g., shopping inside a hutong walk) beyond what `_is_same_activity()` already deduplicates

## Edge Cases & Risks

- **Intentional overlaps**: Activities like "shopping at a market inside a walking tour" may have overlapping times. The existing `_is_same_activity()` handles timeline+POI dedup, but two distinct non-optional activities with intentional overlap will be blocked. This is the correct behavior -- if they truly overlap, the timeline should be adjusted to nest or sequence them.
- **Cross-agent data availability**: The gate needs to load ALL agent files (meals, attractions, entertainment, shopping) to detect cross-agent conflicts. `save.py` currently only loads the agent being saved. The gate must load sibling agent files from the trip directory.
- **Travel segment overlaps**: `check_travel_segment_continuity()` already detects travel-segment/activity overlaps as HIGH severity, but is also skipped when `agent_filter` is set. Must include this check too.
- **Merge mode**: When `--merge-days` is used, the merged data (not just the update) must be checked for conflicts. The merge happens before validation (line 203-211), so the gate sees the merged result -- this is correct.
- **agent_filter bypass**: The root issue is that `run_pipeline()` skips cross-agent checks when `agent_filter` is set. The fix should either (a) run the cross-agent overlap check separately in save.py, or (b) modify how validate_agent_data calls run_pipeline for timeline saves.

## Acceptance Criteria

### AC1: Non-optional overlap blocks save
- GIVEN a timeline.json with two non-optional activities overlapping on the same day
- WHEN `python3 scripts/save.py --trip <slug> --agent timeline --input <file>` is run
- THEN exit code is 1, the timeline.json file is unchanged, and stderr lists the conflicting activities

### AC2: Optional overlaps do not block
- GIVEN a timeline where an optional activity overlaps with a non-optional activity
- WHEN save.py runs
- THEN the save succeeds (exit code 0), the optional overlap is reported as INFO/warning only

### AC3: Same-event dedup is preserved
- GIVEN a timeline activity "Dinner at Dadong" and a meals entry "Dinner at Dadong" with identical times
- WHEN save.py runs
- THEN this is NOT flagged as a conflict (same real-world event from two sources)

### AC4: --allow-high bypasses the gate
- GIVEN a timeline with non-optional conflicts
- WHEN save.py is run with `--allow-high`
- THEN the save proceeds despite conflicts (with warning)

### AC5: Travel segment overlap blocks save
- GIVEN a travel segment whose time range overlaps with a non-optional activity
- WHEN save.py runs
- THEN exit code is 1, file unchanged

## Technical Hints

- **Root cause**: `run_pipeline()` at line 1469 guards cross-agent checks with `if not agent_filter:` -- timeline saves always pass `agent_filter="timeline"`, skipping overlap detection entirely
- **Affected files**: `scripts/save.py` (primary), possibly `scripts/lib/json_io.py` (if validate_agent_data needs changes)
- **Reusable functions from plan-validate.py**: `_check_time_overlap()`, `_collect_all_activities_for_day()`, `_is_same_activity()`, `check_all_activity_overlaps()`, `check_travel_segment_continuity()`
- **Implementation approach A (recommended)**: In `save_single_agent()`, after existing validation succeeds and before file write (between lines 220-228), add a dedicated time-conflict check for timeline saves. Import the overlap functions from plan-validate.py, load all_data from sibling files, call `check_all_activity_overlaps()` directly, and block on any HIGH severity results.
- **Implementation approach B**: Modify `validate_agent_data()` in json_io.py to pass `agent_filter=None` for timeline saves, enabling the full cross-agent pipeline. Risk: this also enables other cross-agent checks that may produce false positives for partial data.
- **Data loading**: Use `load_agent_data()` from plan-validate.py (or replicate its logic) to load sibling agent files from `trip_dir`.
- **Pattern**: Timeline schema uses `start_time`/`end_time` keys; POI agents use `time.start`/`time.end`. The existing `_collect_all_activities_for_day()` already normalizes both formats.
