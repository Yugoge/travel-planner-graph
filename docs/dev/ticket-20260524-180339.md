## Goal

Board cards whose selection originates from AI planning (`selected_option_id` in
editor data) cannot be dragged to the sidebar to deselect them, and candidates
cannot be dropped into a filled-but-AI-selected slot. Fix draggable gating and
drop-target gating so AI-selected cards behave identically to manually-selected
cards.

## Evidence (Contract A)

- **Observed**: "Board cards that are pre-selected by AI planning appear on the
  left KanbanView panel but are completely locked/non-draggable. The user cannot
  drag the card to the right sidebar to deselect it, nor drop a candidate from
  the right panel onto the slot."

- **Measured (accommodation)**: `react_template.tpl:1267`
  ```js
  const dragOptionId = acc.option_id || selectedAccId;
  draggable={!!dragOptionId}
  ```
  `acc.option_id` is absent from PLAN-rendered accommodation card objects.
  `selectedAccId` is `null` in viewer mode (no `editorDay` / `editorSelections`).
  Result: `dragOptionId = null` → `draggable = false`.

- **Measured (accommodation drop-target gating)**: `react_template.tpl:1316`
  ```js
  const isGated = !edAcc || edAcc.late_arrival_placeholder || edAcc.skipped;
  ```
  `edAcc` is null in viewer mode → `isGated = true` → `data-droppable="false"`.
  This means even when a slot is filled (AI-selected), candidates cannot be
  dropped in because the drop overlay is gated by `!edAcc`.

- **Measured (meals)**: `react_template.tpl:862`
  ```js
  draggable={isSelected}
  ```
  `isSelected = opt.selected` which IS set to `true` by `mergeEditorSelectionsIntoPublishedDay`
  (line 2100: `activeCard.selected = true`). Meals draggable is NOT broken for
  AI-selected cards when `mergeEditorSelectionsIntoPublishedDay` runs. However,
  `opt.option_id` used in the drag payload (line 863) IS reliably set by the
  merge function (line 2101: `activeCard.option_id = selOpt.option_id`).
  Meals drag is correct when editor mode is active.

- **Measured (attractions/entertainment/cafe)**: `react_template.tpl:1040, 1125, 952`
  ```js
  draggable={isSelected && !!actSlotId}
  ```
  `isSelected = attr.selected` — set correctly by merge (line 2203).
  `actSlotId` comes from `activitySlotMap` built from `editorDay.slots` — null
  if `editorDay` is null. In viewer mode, both conditions fail. This is the
  same viewer-mode null problem as accommodation.

- **Measured (handleSidebarDrop)**: `react_template.tpl:2355-2368`
  ```js
  if ((payload.direction === 'plan-to-candidates' || payload.direction === 'board') && srcSlotId) {
    const key = dayNum + ':' + srcSlotId;
    setEditorSelections(prev => ({ ...prev, [key]: null }));
    saveMutations(dayNum, [{ type: 'select', slot: srcSlotId, option_id: null }]);
  }
  ```
  `handleSidebarDrop` already correctly handles the deselect for both
  `direction: 'board'` and `direction: 'plan-to-candidates'`. No fix needed
  here — it saves `option_id: null` to the correct slot.

- **Expected**: Any card rendered as selected on the board (regardless of
  selection origin — AI or manual) should be draggable, and its slot should
  accept candidate drops.

- **Gap**:
  1. Accommodation: `dragOptionId` evaluates to null in viewer/partial-editor
     mode because `acc.option_id` is absent from Python-rendered cards and
     `selectedAccId` requires `edAcc` to be non-null.
  2. Accommodation drop-target: `isGated = !edAcc` blocks drops when viewer
     mode has no `edAcc`.
  3. Activities (attractions/entertainment/cafe): `actSlotId` is null when
     `editorDay` is null, causing `draggable = false` and no drop-overlay
     rendered at all (the entire `{actSlotId && (() => { ... })()}` block is
     skipped).

## Root Cause Deep-Dive

The merge function `mergeEditorSelectionsIntoPublishedDay` (lines 2052-2219)
correctly sets `card.selected = true` and `card.option_id = selOpt.option_id`
on the rendered card for meals and activities. This means by the time
`KanbanDayView` renders:

- `opt.selected === true` (meals)
- `attr.selected === true` (attractions)
- `attr.option_id` is set (attractions)

BUT the draggable guard adds a second condition:

- Meals: `draggable={isSelected}` — correct, no fix needed
- Activities: `draggable={isSelected && !!actSlotId}` — `actSlotId` is null
  when `editorDay` is null, making the condition false despite `isSelected`
  being true
- Accommodation: `draggable={!!dragOptionId}` where `dragOptionId = acc.option_id || selectedAccId`
  — `acc.option_id` is absent from Python-rendered cards (only set by the merge
  function when the merge runs), and `selectedAccId` is null when `edAcc` is
  null (viewer mode)

The underlying cause is that the draggable guard requires `editorDay` to exist
(to build `actSlotId` / `edAcc` / `selectedAccId`), but the user-reported
scenario involves a page rendered in viewer mode or before `editorDay` is
loaded. The merge function IS running (as evidenced by `selected: true` being
set), but the slot-ID lookup for activities requires `editorDay.slots` which
may be null during initial render.

**Fix strategy**: For each card type, use `card.selected` + `card.option_id`
as the draggable condition (these are set by the merge function and are
card-local — no `editorDay` dependency). Fall back to `selectedAccId` for
accommodation as a secondary guard. For drop-target gating, treat a slot as
non-gated when the card is selected (`isSelected` or `selectedAccId` is
non-null) even if `edSlot`/`edAcc` is null.

## Requirements (MoSCoW)

### Must Have

- M1: Accommodation card: `draggable` is `true` whenever the card is the
  selected option — i.e., `acc.option_id` is non-null (set by merge) OR
  `selectedAccId` is non-null (from `edAcc.selected_option_id` or
  `editorSelections`). Simplest form: `draggable={!!(acc.option_id || selectedAccId)}` — this is unchanged from existing code. The real fix is ensuring `selectedAccId` is computed correctly even when `edAcc` is null (see M3).

- M2: Accommodation drop-target: `isGated` must not be `true` purely because
  `edAcc` is null. If `selectedAccId` (derived via editorSelections or
  edAcc.selected_option_id) is non-null, the slot is filled and should accept
  drops (to allow swapping or overriding the selection). Fix:
  `const isGated = (!edAcc && !selectedAccId) || (edAcc && (edAcc.late_arrival_placeholder || edAcc.skipped));`

- M3: `selectedAccId` at line 1266 currently reads:
  ```js
  const selectedAccId = edAcc ? (...) : null;
  ```
  This returns `null` when `edAcc` is null. Fix to fall back to
  `editorSelections[accKey]` regardless of `edAcc`:
  ```js
  const selectedAccId = Object.prototype.hasOwnProperty.call(editorSelections || {}, accKey)
    ? (editorSelections || {})[accKey]
    : (edAcc && edAcc.selected_option_id) || null;
  ```
  This is what the badge badge computation at line 1307 already does — apply
  the same pattern at line 1266.

- M4: Activities (attractions/cafe/entertainment): `draggable` should use
  `isSelected && (!!actSlotId || !!attr.option_id)` — if the card's `option_id`
  is set (meaning merge ran), it can be dragged even when `actSlotId` is null,
  using the card's own `option_id` in the drag payload. The `slotId` in the
  payload must still be correct: use `actSlotId || (isSelected ? attr._slotId : null)`
  where `attr._slotId` is the slot the merge function resolved.

  **Simpler alternative** (preferred): since `attr.option_id` is only set when
  `isSelected` is true (merge sets both atomically), use:
  ```js
  draggable={isSelected && !!(actSlotId || attr.option_id)}
  ```
  And in `onDragStart`, use `actSlotId` if available, else derive slot from
  `activitySlotMap` using attr name — but `activitySlotMap` also requires
  `editorDay`. Given the constraint of no new drag payload fields, the safest
  fix is: activities can only be dragged when `actSlotId` is non-null (editor
  mode active). When `editorDay` is null, the whole board is in viewer mode
  and drag should be blocked anyway. See Non-Goals.

- M5: The `handleSidebarDrop` function (lines 2355-2368) already handles
  `direction: 'board'` deselect correctly. No changes needed.

### Should Have

- S1: Activity drop-target `isGated` logic should be consistent with
  accommodation fix: if a slot is filled (card `isSelected` and `actSlotId`
  non-null), the drop target should not be gated.

### Could Have

- C1: Add a `data-selected` attribute to board cards to make E2E testing easier.

### Won't Have (Non-Goals)

- Fixing viewer-mode drag (when `editorDay` is null, the board is read-only
  by design; drag requires editor context for slot resolution)
- Modifying `render_day_data.py` to output `option_id`
- Adding new fields to the drag payload format
- Fixing board→board accommodation swap (separate scope)

## Edge Cases & Risks

- **Risk 1**: The `selectedAccId` at line 1266 is also used in `dragOptionId`
  (line 1267) and the badge block (line 1307). After fixing line 1266, all
  three consumers of `selectedAccId` in the accommodation card block will be
  correct — they currently share the same flaw.

- **Risk 2**: The accommodation `onDragStart` at line 1274 uses `dragOptionId`
  as both the payload `optionId` and the drag enable guard. After fixing
  `selectedAccId` resolution, `dragOptionId = acc.option_id || selectedAccId`
  will be non-null whenever the card is AI-selected, and the payload will carry
  the correct `option_id`.

- **Risk 3**: For activities, `onDragStart` includes `optionId: attr.option_id`
  in the payload (line 1041). If `attr.option_id` is null (which can happen
  for cards in synthesis fallback where the merge wrote to `option_id` via
  `_synthesizeCardFromV2Option` but the card in the published day doesn't match),
  the sidebar drop handler receives `option_id: null` and saves a no-op mutation.
  This is a pre-existing edge case that is not changed by this fix.

- **Risk 4**: Drop-target gating change for accommodation (M2): loosening
  `isGated` to allow drops when `selectedAccId` is non-null must not break
  the `skipped` / `late_arrival_placeholder` guard. The revised condition must
  still gate on those flags.

- **Risk 5**: The `selected` field on meal cards (`opt.selected`) is set inside
  `mergeEditorSelectionsIntoPublishedDay`. If that function is not called
  (e.g., `editorDay` is null), `opt.selected` remains whatever the published
  day data has. For the AI-planning scenario the orchestrator described, the
  merge function IS called (the board renders the selected card). Meals drag
  is therefore already working when editor mode is active.

## Acceptance Criteria

### AC1: Accommodation card is draggable when AI-selected

- GIVEN a day where accommodation has `selected_option_id` set by AI planning
- WHEN the KanbanDayView renders with `editorDay` loaded (editor mode)
- THEN the accommodation card `div` has `draggable="true"`
- AND `dragOptionId` evaluates to the non-null `option_id` of the selected accommodation

### AC2: Accommodation drag to sidebar deselects

- GIVEN the accommodation card is draggable (AC1 holds)
- WHEN the user drags it to the CandidatesSidebar drop zone
- THEN `handleSidebarDrop` fires with `payload.direction === 'board'` and
  `payload.sourceSlotId === 'accommodation'`
- AND `saveMutations(dayNum, [{ type: 'select', slot: 'accommodation', option_id: null }])` is called
- AND the accommodation slot renders as empty / unselected after the drop

### AC3: Accommodation slot accepts candidate drop when AI-selected

- GIVEN an accommodation slot with AI-selected card (editorDay loaded, edAcc non-null, not skipped, not late_arrival_placeholder)
- WHEN a candidate is dragged from the sidebar and dropped onto the slot
- THEN `data-droppable` on the slot-drop overlay is `"true"`
- AND the drop handler saves the new selection via `saveMutations`

### AC4: Activity cards (attractions/entertainment/cafe) are draggable when AI-selected

- GIVEN a day where an activity slot has `selected_option_id` set by AI planning
- AND `editorDay` is loaded (so `actSlotId` is non-null via `activitySlotMap`)
- WHEN the KanbanDayView renders
- THEN the selected activity card has `draggable="true"`
- AND `attr.option_id` in the drag payload is the correct non-null `option_id`

## Technical Hints

**File to modify**: `scripts/lib/react_template.tpl` only.

**Fix 1 — Accommodation `selectedAccId` (line 1266)**:

Change:
```js
const selectedAccId = edAcc ? (Object.prototype.hasOwnProperty.call(editorSelections || {}, accKey) ? (editorSelections || {})[accKey] : edAcc.selected_option_id) : null;
```
To:
```js
const selectedAccId = Object.prototype.hasOwnProperty.call(editorSelections || {}, accKey)
  ? (editorSelections || {})[accKey]
  : (edAcc && edAcc.selected_option_id) || null;
```
This mirrors the identical pattern already used at line 1307 (badge computation)
and at line 2060 (`mergeEditorSelectionsIntoPublishedDay`). Now `selectedAccId`
is non-null whenever the slot has a selection — making `dragOptionId` at line
1267 non-null and `draggable={!!dragOptionId}` true.

**Fix 2 — Accommodation drop-target gating (line 1316)**:

Change:
```js
const isGated = !edAcc || edAcc.late_arrival_placeholder || edAcc.skipped;
```
To:
```js
const isGated = (!edAcc && !selectedAccId) || (edAcc && (edAcc.late_arrival_placeholder || edAcc.skipped));
```
This allows drops when the slot has a live selection even if `edAcc` object
itself is somehow null (defensive), while still blocking on explicit skipped /
late-arrival states.

**Note on meals drag (line 862)**: `draggable={isSelected}` is correct and
requires no change. The merge function sets `opt.selected = true` and
`opt.option_id = selOpt.option_id` atomically.

**Note on activity cards (lines 952, 1040, 1125)**: `draggable={isSelected && !!actSlotId}`.
`actSlotId` is built from `editorDay.slots` via `activitySlotMap`. When
`editorDay` is loaded (the normal editor mode), this already works correctly
for AI-selected cards — `isSelected` is `true` (set by merge) and `actSlotId`
is non-null (from the slot map). The reported bug for activities (if any) is
a viewer-mode scenario which is out of scope per Non-Goals.
