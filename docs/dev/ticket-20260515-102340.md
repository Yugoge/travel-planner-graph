## Goal

Fix four bugs that make the v2 interactive travel planner server non-functional on v2 trip data, and add two missing Python package dependencies that cause ImportError on PDF and iCal export requests.

## Context

The v2 interactive server (`scripts/serve-trip.py` + `web/js` ES modules) implements a 3-column drag-to-slot UI backed by a per-day-file schema (`schemas/v2/day.schema.json`). The schema places the 6 named activity slots under `day["slots"]` (not at the top level of the day dict) and enforces `additionalProperties: false` at the root. Both the save and budget server handlers were written to the old top-level shape, causing all drag-and-drop interactions to corrupt v2 day files and all budget calculations to return zero. A client-side workaround in `state.js` compensates for the save bug but will cause re-corruption once the server is fixed. The stage state machine exists in `scripts/lib/trip_contract/state_machine.py` but is never called from the save handler. The PDF and iCal exporters import `reportlab` and `icalendar` at module level but neither package appears in `requirements.txt`.

## Edge Cases & Risks

- **accommodation path unchanged**: `budget.py:128` calls `day.get("accommodation", {})` — this is correct (accommodation is top-level). If dev accidentally moves it under `"slots"`, budget will silently return 0 for accommodation.
- **409-soft vs hard 409**: The existing `conflict: "409-soft"` is an advisory response returned as HTTP 200. `StateMachineError` must trigger a true HTTP 409 (`HTTPStatus.CONFLICT`) and must NOT overload or alter the 409-soft advisory path.
- **Stage mutation still proceeds on valid transitions**: The state machine check rejects only illegal backward transitions. Forward and same-stage transitions must proceed normally.
- **Fixture affects all test cases**: `conftest.py:_build_day()` is used by all server tests. Any assertion that reads a slot value by top-level key will break after the fix — dev must check test_save_endpoint.py and test_budget_endpoint.py for affected assertions.
- **`has_user_consent` parameter**: `validate_state_transition` accepts a third parameter `has_user_consent`. For the server handler context, this should default to `False` (no user consent for backward transitions; only forward and same-stage are free).
