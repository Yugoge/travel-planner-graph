## Edge Cases & Risks

1. **Cross-meal option not in target slot's options[]**: When a breakfast option is dropped on lunch, `requestSelectMutation` writes `lunch.selected_option_id = breakfast_option_id`. But `_findSelectedOption(lunch_slot)` resolves only within `lunch.options[]`. After page reload, server-returned JSON still has the original breakfast-only `options[]` — the in-memory client copy is lost. Fix: (a) client-side in-memory copy for immediate render; (b) server-side M6 persistent copy in `save.py`. Both copies must be idempotent: check `target.options.some(o => o.option_id === optionId)` before appending. M6 server copy is meal-only; non-meal `_apply_select_mutation` behavior is unchanged.
2. **Day picker duplicate event listeners**: If `_populateDayPicker` is called on every `renderAll()`, the `change` listener accumulates. Fix: split into `_renderDayPickerOptions()` (called each render, rebuilds `<option>` elements, sets `.value`) and a one-time `_wireDayPicker()` called from `init()` using `sel.onchange = ...` (idempotent assignment).
3. **Mobile tap targets miss `meals-any`**: `_markTapTargets(slotIdHint)` at `mobile.js:107-113` marks tap targets with `s.dataset.slotId === slotIdHint`. If slotIdHint is `"meals-any"`, no slot matches. Fix: export or inline a `_isMealCompatible(srcSlot, targetSlot)` check analogous to drag.js fix.
4. **Accommodation with no selection**: On days where `accommodation.selected_option_id` is null (all options un-selected), the fallback to `day.city_name` must not throw. Guard with optional-chaining throughout.
5. **Transport block on days with only one timestamp**: Day-01 has `arrival_ts` but no `departure_ts` (arrival day); day-09 has `departure_ts` only (departure day). Callout must render gracefully for partial data, e.g. "Arrives 18:50" or "Departs 13:30".
6. **CSS rewrite must preserve all functional selectors**: `[data-drop-active]`, `[data-drop-reject]`, `[data-tap-target]`, `[data-mobile-hidden]`, `body[data-editing="disabled"]`, `.card-selected`, `.tap-selected`, `.slot[data-state="error"]`, `.slot[data-state="skipped"]`. Any omission silently breaks drag/tap/offline behavior.
7. **M6: origin slot lookup must be non-mutating**: In `_apply_select_mutation`, do NOT use `_get_or_create_slot(day, origin_slot_id)` to look up the source option — `_get_or_create_slot` calls `setdefault` which creates an empty slot if absent, corrupting the day JSON. Use a non-mutating `_get_existing_slot(day, slot_id)` helper that returns `day.get("accommodation")` for accommodation or `day.get("slots", {}).get(slot_id)` for named slots. Only the target slot uses `_get_or_create_slot`.
8. **M6: source-option-missing guard**: If `origin_slot_id` is present in the payload but the option cannot be found in the origin slot's `options[]` (origin slot missing or option absent), do not write a `selected_option_id` pointing to a non-existent option. Leave the existing `selected_option_id` unchanged.
9. **Mobile tap must carry `originSlotId`**: In `mobile.js`, when a meal card is tapped (tap-selected), store `card.dataset.originSlotId` alongside `card.dataset.slotId`. Pass `originSlotId` to `requestSelectMutation` when the user taps a slot drop zone. Without this, the mobile path sends no `origin_slot_id` and M6 cannot copy the option on the server.
10. **Correct v2 slot IDs**: The activity slots are named `morning_activity`, `afternoon_activity`, `evening_activity` (verified in `schemas/v2/day.schema.json:58-62`). Never write `activity_morning`, `activity_afternoon`, or `activity_evening` in code or comments.

### Key implementation notes

**M2 — `_buildMealsCandidateGroup(day)` logic:**
```
const MEAL_SLOT_KEYS = ["breakfast", "lunch", "dinner"];
// 1. Collect all options from all three meal slots, de-dupe by option_id
// 2. For each option, set data-slot-id="meals-any", data-origin-slot-id=<source slot>
// 3. _markCardSelectionState: option is selected if ANY meal slot's selected_option_id === opt.option_id
// 4. Empty state: if all three slots are skipped or have no options, render one "skipped" or "(no candidates)" message
```

**M2 — `requestSelectMutation` cross-meal persistence (client-side, in-memory):**
```
// Before setting slot.selected_option_id:
// If target slot does not contain option_id in its options[], push a copy of the option.
// This is idempotent: check first, append at most once.
const existing = slot.options.some(o => o.option_id === optionId);
if (!existing) {
  // find source option from any meal slot
  const srcOpt = MEAL_SLOT_KEYS.map(k => _getSlotByKey(day, k))
    .filter(Boolean).flatMap(s => s.options || [])
    .find(o => o.option_id === optionId);
  if (srcOpt) slot.options.push({...srcOpt});  // shallow clone
}
// Client sends: {type:"select", slot: targetSlotId, option_id: optionId, origin_slot_id: originSlotId}
// NOTE: slotId (targetSlotId) comes from the DROP TARGET element's data-slot-id ("breakfast"/"lunch"/"dinner"),
// NOT from the card's data-slot-id ("meals-any"). "meals-any" is only a compatibility hint.
// originSlotId comes from card.dataset.originSlotId (the source meal slot: "breakfast"/"lunch"/"dinner").
```

**M3 — city derivation helper:**
```
function _deriveCityName(day) {
  const acc = day.accommodation;
  if (acc && acc.selected_option_id) {
    const opt = (acc.options || []).find(o => o.option_id === acc.selected_option_id);
    if (opt?.city_context?.city_name) return opt.city_context.city_name;
  }
  return day.city_name || "";
}
```

**M3 — split day picker:**
- `_wireDayPicker()` called once from `init()`: `sel.onchange = () => setActiveDay(parseInt(sel.value, 10));`
- `_renderDayPickerOptions()` called from `renderAll()`: rebuild `<option>` elements using `_deriveCityName(day)`, re-set `sel.value`

**M4 — transport callout:**
```
function _buildTransportCallout(day) {
  const parts = [];
  if (day.departure_ts) parts.push("Departs " + _formatTs(day.departure_ts));
  if (day.arrival_ts) parts.push("Arrives " + _formatTs(day.arrival_ts));
  if (!parts.length) return null;
  const div = document.createElement("div");
  div.className = "transport-callout";
  div.setAttribute("aria-label", "transportation");
  div.textContent = parts.join(" · ") + (day.day_type ? " · " + day.day_type : "");
  return div;
}
// _formatTs: extract HH:MM from ISO timestamp string safely
```
Insert `_buildTransportCallout` result at top of `#timeline-slots` container when non-null.
