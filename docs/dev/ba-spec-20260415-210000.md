# BA Specification: Independent Cafe POI Type

**Request ID**: dev-20260415-210000
**Created**: 2026-04-15T21:00:00Z
**Revised**: 2026-04-15T21:30:00Z (post-QA correction -- 6 objections addressed)

## Goal

Create a brand new "Cafe" POI domain in the travel planner system, structurally isomorphic to meals but without time restrictions, covering coffee shops, teahouses, and rest/relaxation spots. Migrate ALL existing cafe entries from meals.json (across ALL days) into the new cafe.json.

## Context

The travel planner currently has 7 POI domains: meals, attractions, entertainment, shopping, accommodation, transportation, and budget. Cafe-type entries (e.g., VOYAGE COFFEE, METAL HANDS) are currently shoe-horned into meals as breakfast alternatives or even breakfast primaries, but they do not fit the breakfast/lunch/dinner structure. The user explicitly rejected "making meals flexible" and wants a clean separation: meals = breakfast/lunch/dinner, cafe = coffee, tea, rest stops at any time of day.

The system has a schema-driven auto-registration architecture -- plan-validate.py and load.py auto-derive agent configs from schema files in `schemas/`. This means creating a properly structured `cafe.schema.json` will auto-register the cafe agent with validation and data loading. However, several scripts have hardcoded agent lists or agent-specific logic that needs explicit cafe integration.

**Critical integration notes** (corrected after QA review):
- `save.py` `_collect_day_pois` (line 75-84) does NOT have a generic fallback. Line 82 checks `if agent in ["attractions", "entertainment", "shopping"]` explicitly and line 84 returns `[]` for unknown agents. Cafe must be added to this explicit list.
- `plan-validate.py` `agent_item_mapping` (line 228-234) is hardcoded with 5 agents. Cafe must be added for AGENTS_WITH_LOCAL to include it.
- `fetch-images-batch.py` has TWO `agent_files` lists (line 667 and line 1061) and per-field_name if/elif branches. Both must be updated.
- Cafe entries exist in meals.json on Day 1 (2 alternatives) AND Day 15 (1 primary). ALL must be migrated.

## Edge Cases & Risks

- **Schema auto-derivation**: plan-validate.py line 146 requires exactly one item def besides day_entry. cafe.schema.json must have exactly `cafe_item` and `day_entry` in $defs (no meal_slot equivalent needed since cafes use simple arrays)
- **Budget category mismatch**: budget.schema.json budget_categories has `additionalProperties: true` (line 83), so unknown keys pass schema validation silently. But the HTML generator budget total sum (lines 1139-1146, 1313-1320) is an explicit additive list -- cafe costs will be silently excluded unless added. Must add "cafe" to both schema required fields AND the sum calculations.
- **Image fetcher coordinate detection**: The fetch-images-batch.py uses coordinates for map service detection (gaode vs google). Cafe processing must pass coordinates like other array-based agents.
- **Migration data integrity (Day 15 primary)**: METAL HANDS on Day 15 (line 1877) is a breakfast PRIMARY, not an alternative. Removing it leaves Day 15 with no breakfast primary. Must promote the first alternative (Huguosi Snacks, line 1902) to primary.
- **Migration data integrity (Day 1 alternatives)**: Day 1 has 3 breakfast alternatives. VOYAGE COFFEE (line 41) and METAL HANDS Qianmen (line 75) are cafes. The third (Yin San Douzhir, line 109) is traditional breakfast and should remain.
- **HTML rendering order**: Cafe section should appear after meals and before attractions in the visual hierarchy to group food-related POIs together.
- **save.py _collect_day_pois has NO generic fallback**: Line 84 returns `[]` for any agent not explicitly listed in lines 77-83. Adding "cafe" to POI_AGENTS without also adding it to the branch on line 82 causes `extract_image_urls()` to silently skip all cafe POIs when saving.
- **plan-validate.py AGENTS_WITH_LOCAL is semi-hardcoded**: The agent_item_mapping dict at line 228-234 is a manual mapping. It is NOT auto-derived from schemas. Without adding cafe, name_local validation is silently skipped.
- **fetch-images-batch.py has TWO agent_files lists and per-field if/elif branches**: Lines 667-673 (collect_pois) and 1061-1067 (update_images). Both must include cafe. Additionally, the processing logic uses `if field_name == "attractions" ... elif field_name == "entertainment" ... elif field_name == "shopping"` pattern. Cafe needs its own elif branch.
- **generate-html-interactive.py has 14+ modification points**: File is 3269 lines. All line numbers verified (see Technical Hints).
- **Budget sidebar items extraction**: `handleBudgetClick` (line 3031-3059) uses explicit if/else per category. Without a cafe branch, clicking the cafe donut segment shows empty items.

## Technical Hints

- **Hardcoded agent lists**: update-agent-prompts.py:39, verify-tool-restrictions.py:36, update-agent-docs.sh:8 -- all have manually maintained AGENTS arrays.
