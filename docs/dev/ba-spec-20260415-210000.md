# BA Specification: Independent Cafe POI Type

**Request ID**: dev-20260415-210000
**Created**: 2026-04-15T21:00:00Z

## Goal

Create a brand new "Cafe" POI domain in the travel planner system, structurally isomorphic to meals but without time restrictions, covering coffee shops, teahouses, and rest/relaxation spots. Migrate existing cafe entries from meals.json into the new cafe.json.

## Context

The travel planner currently has 7 POI domains: meals, attractions, entertainment, shopping, accommodation, transportation, and budget. Cafe-type entries (e.g., VOYAGE COFFEE) are currently shoe-horned into meals as breakfast alternatives, but they do not fit the breakfast/lunch/dinner structure. The user explicitly rejected "making meals flexible" and wants a clean separation: meals = breakfast/lunch/dinner, cafe = coffee, tea, rest stops at any time of day.

The system has a schema-driven auto-registration architecture -- plan-validate.py and load.py auto-derive agent configs from schema files in `schemas/`. This means creating a properly structured `cafe.schema.json` will auto-register the cafe agent with validation and data loading. However, several scripts hardcode agent lists or have meal-specific logic that needs explicit cafe integration.

## Requirements (MoSCoW)

### Must Have
1. **Schema**: Create `schemas/cafe.schema.json` -- isomorphic to meals item fields (name_base, name_local, location_base, location_local, coordinates, cost, currency_local, cuisine_base/local, signature_dishes_base/local, notes_base/local, search_results, optional, image_url, is_home) but using array-of-items structure per day (like entertainment/shopping) instead of named slots (breakfast/lunch/dinner)
2. **Agent prompt**: Create `.claude/agents/cafe.md` -- specialized for researching coffee shops, teahouses, and rest spots; same workflow as meals.md but without time-slot constraints
3. **Data file**: Create initial `data/china-20260412-092624/cafe.json` with migrated VOYAGE COFFEE and METAL HANDS entries from meals.json Day 1 alternatives
4. **HTML generator merge**: Update `scripts/lib/html_generator.py` merge_itinerary_data() and merge_bucket_list_data() to load and merge cafe.json
5. **HTML generator render**: Update `scripts/generate-html-interactive.py` to render cafe section (new Section with icon, color, and POI cards), add "cafe" to budget categories and categoryColors
6. **Image fetcher**: Update `scripts/fetch-images-batch.py` agent_files list to include ("cafe.json", "cafe", "cafe") and add cafe processing branch (array-based, like entertainment)
7. **Save.py integration**: Add "cafe" to POI_AGENTS set and add cafe-specific _collect_day_pois branch (array-based)
8. **Sync agent**: Add _sync_cafe() method to `scripts/sync-agent-data.py` (array-based, like entertainment)
9. **Budget integration**: Add "cafe" category to budget.schema.json budget_categories and update budget total calculation in generate-html-interactive.py

### Should Have
10. **Update agent lists**: Add "cafe" to AGENTS arrays in `scripts/update-agent-prompts.py`, `scripts/verify-tool-restrictions.py`, and `scripts/update-agent-docs.sh`
11. **Remove migrated data**: After migration, remove VOYAGE COFFEE and METAL HANDS cafe entries from meals.json Day 1 breakfast alternatives
12. **Timeline integration**: Ensure cafe entries in timeline.json are recognized as cafe POIs (not meal POIs) in conflict detection

### Could Have
13. **POI classification rules**: Update `.claude/commands/poi-classification-rules.md` with cafe classification decision tree
14. **Cafe-specific emoji**: Add cafe emoji mapping in meal_utils.py or a new cafe_utils.py

### Won't Have (Non-Goals)
- Modifying the meals schema to be "flexible" -- meals stays breakfast/lunch/dinner
- Adding cafe to the budget agent's auto-calculation (budget agent will need separate update)
- Changing the timeline schema -- cafe entries appear in timeline like any other POI
- Auto-detection of cafe vs meal entries in existing data

## Edge Cases & Risks

- **Schema auto-derivation**: plan-validate.py line 146 requires exactly one item def besides day_entry. cafe.schema.json must have exactly `cafe_item` and `day_entry` in $defs (no meal_slot equivalent needed since cafes use simple arrays)
- **Budget category mismatch**: If budget.schema.json does not include a "cafe" category, the budget totals will silently exclude cafe costs. Must add to required fields.
- **Image fetcher coordinate detection**: The fetch-images-batch.py uses coordinates for map service detection (gaode vs google). Cafe processing must pass coordinates like other array-based agents.
- **Migration data integrity**: VOYAGE COFFEE in meals.json is an alternative under Day 1 breakfast. Removing it must not break the breakfast primary entry.
- **HTML rendering order**: Cafe section should appear after meals and before attractions in the visual hierarchy to group food-related POIs together.
- **save.py conflict detection**: The _collect_sibling_day_acts function and _load_sibling_agents iterate POI_AGENTS. Adding cafe to POI_AGENTS enables automatic conflict detection.

## Technical Hints

- **Self-registering systems**: plan-validate.py and load.py auto-derive from schemas. Just creating cafe.schema.json registers cafe with both.
- **Hardcoded agent lists**: update-agent-prompts.py:39, verify-tool-restrictions.py:36, update-agent-docs.sh:8 -- all have manually maintained AGENTS arrays.
- **Cafe structure**: Use array-based day_entry (like entertainment.schema.json), NOT named-slot (like meals.schema.json). This avoids the breakfast/lunch/dinner time-slot paradigm.
- **Fields from meals to keep**: name_base, name_local, location_base, location_local, coordinates, cost, currency_local, cuisine_base, cuisine_local, signature_dishes_base, signature_dishes_local, notes_base, notes_local, search_results, optional, image_url, is_home
- **Fields to add for cafe**: type_base, type_local (cafe type: "Coffee Shop", "Teahouse", "Rest Spot")
- **HTML color**: Use a warm brown/amber color for cafe (e.g., #8B6914 or #D4A574) to distinguish from meal orange
