# BA Specification: Enforce timeline.json as Single Source of Truth for Scheduling

**Request ID**: dev-20260415-010000
**Created**: 2026-04-15T01:00:00

## Goal

Refactor the travel-planner codebase so that `timeline.json` is the ONLY file that stores time/scheduling data (`{start, end}` time ranges) for all POI activities. Remove the `time` field from POI agent schemas, data files, validation logic, and the sync script — no backwards compatibility layer.

## Context

Today the codebase has a split-authority problem: both `timeline.json` and each POI agent file (`meals.json`, `attractions.json`, `entertainment.json`, `shopping.json`) store `{start, end}` time fields. `sync-agent-data.py` attempts to keep them in sync by copying times from timeline into agent files, but this creates circular dependencies, drift risk, and schema complexity. The `generate-html-interactive.py` HTML generator reads time from POI agent files rather than timeline, making timeline redundant. The design decision is a clean break: POI files hold POI data only; timeline holds all scheduling.

## Edge Cases & Risks

- **HTML display regression**: After removing `time` from POI files, `generate-html-interactive.py` will show no time on POI cards unless the timeline lookup is implemented correctly. The name-matching logic must handle both `name_base` and `name_local`, and must handle `meal_ref` for meals (since meals timeline entries use `meal_ref: "breakfast"` not item name).
- **Meal time lookup**: Timeline entries for meals use `meal_ref: "breakfast"/"lunch"/"dinner"` rather than the restaurant name. The HTML generator's meal merge (line 559) must use `meal_ref` lookup, not name-based lookup.
- **save.py conflict detection**: `check_time_conflicts()` currently reads `poi.get("time", {})` from sibling agent files. After removing time from POI files, sibling-based conflict detection will stop working. The conflict checker must be updated to source times exclusively from the sibling `timeline.json`.
- **plan-validate.py cross-agent time conflict block**: Lines 1256–1368 collect POI times from agent files for conflict detection. After removing time from those files, this entire block will silently produce zero conflicts — which is wrong. The block must be rewritten to read from timeline only.
- **26 data files** across 8 trip directories have time fields embedded in POI items. These must all be stripped, including `.bak` backup files if they exist.
- **`_normalize_time` method** in `generate-html-interactive.py` (line 383): After refactor, it will only be used for travel segment time conversion (travel segments use `start_time`/`end_time` string fields, not `time` objects). The method can remain but should document its new limited scope.

## Acceptance Criteria

### AC1: Schema clean
- GIVEN the updated schemas directory
- WHEN `jsonschema` validates any POI item (meal, attraction, entertainment, shopping) with a `time` field present
- THEN validation fails with "Additional properties are not allowed"

### AC2: Data files clean
- GIVEN any data file in `data/*/meals.json`, `data/*/attractions.json`, `data/*/entertainment.json`, `data/*/shopping.json`
- WHEN the file is parsed as JSON and each POI item's keys are inspected
- THEN no item contains a `time` key

### AC3: HTML generator uses timeline for time display
- GIVEN a plan with timeline.json containing `"Breakfast at Foo": {"start_time": "08:30", "end_time": "09:30", "meal_ref": "breakfast"}`
- WHEN `generate-html-interactive.py` is run
- THEN the generated HTML shows "08:30 – 09:30" for the breakfast card

### AC4: sync-agent-data no longer injects time into POI files
- GIVEN a plan where timeline.json has time data but POI files have no time fields
- WHEN `sync-agent-data.py` is run
- THEN POI files still contain no `time` field after the run

### AC5: plan-validate.py passes with no false positives
- GIVEN a clean plan with no time fields in POI files
- WHEN `plan-validate.py` is run
- THEN it produces zero HIGH severity issues related to missing `time` fields, and cross-agent time conflict detection still operates correctly using timeline data
