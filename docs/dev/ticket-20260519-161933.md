## Goal

Make drag-and-drop and tap-to-select visually update Timeline and Kanban slot
cards in real time, fixing the gap where prior cycle 20260518-101127 wired up
events + POST /api/save but the rendered slot card never changed. The fix
must be backward-compatible: a Yunnan trip Day with no `editor_selections`
and persisted `selected_option_id` matching its PLAN_DATA card must render
with **textContent equivalence** to the pre-cycle build (commit `9218b6bd`),
across all 9 Yunnan days. All non-Yunnan trip data files must remain
byte-identical at the file level. (Addressed in v2: RC-10 — `byte-identical
DOM` phrasing removed; replaced with explicit textContent equivalence +
ordering + pixel-diff < 1% RMSE. R3 `<style>` injection and S1 `data-*`
attributes are expected and do not violate equivalence.)

## Edge Cases & Risks

- **v2 option missing `time` / `image`**: per codex Finding 1, options
  in `data/beijing-lijiang-dali-20260418-100846/days/day-*.json`
  routinely have `time: None` and `image: None`. R1 MUST preserve the
  PLAN card's existing `time` (so Timeline still renders the entry —
  TimelineView L1483 filters out entries with `time.start === '00:00'`)
  and fall back to the existing `image` on the PLAN card.
- **Cross-meal duplicate after replace**: per codex Finding 3, if
  `dinner-2-2` replaces `day.meals.dinner` and is also present in
  `day.meal_alternatives.dinner`, two cards render. R1a filters by
  `option_id`.
- **Activity stale-primary**: per codex Finding 2, Timeline only
  renders activity entries with a `time`. If the selected option is
  the un-timed alternative and the un-replaced primary keeps its
  `time`, Timeline shows the stale primary. R1b prefers the timed
  card for replacement.
- **Inline-style specificity**: per codex Finding 6, the inline
  `background: 'transparent'` on `.slot-drop` will beat any plain
  `.slot-drop[data-drop-active] { background: ... }` rule. R3
  explicitly addresses this.
- **Accommodation array vs object**: per codex Finding 7, current
  merge L1915 `Array.isArray(day.accommodation)` is dead code.
  R1c fixes this.
- **Persisted vs computed selection**: a Yunnan trip might have
  `selected_option_id` baked into its day-*.json that points at an
  option whose content already matches the PLAN_DATA card (the
  "default" case). R4 requires byte-identity in that case, so R1
  must produce an equivalent card structure — using
  `{...existingCard, ...derived}` spread ensures all PLAN-only
  fields (like `_isPrimary`, `cuisine`, locale fields not in v2)
  are preserved.
- **board-to-board cross-meal**: per codex Finding 5, the current
  bridge sets BOTH source and target slot selection to the same
  optionId in `editorSelections` (L2496–2498). With R1 making the
  source slot's card now appear at the target option's content,
  this is visually wrong (the source slot card flickers to the
  moved-out option). S2 reins it in.

### v3 (RC-12 fix)

**Trigger**: QA v2's `ba-validation-v2` reject_narrow verdict
(qa-report-20260519-161933-ba-validation-v2.json). 11/11 of v1's

**Contradiction (v2)**: The Reference Source mapping rule at line
208 instructed dev `cost = opt.cost (already in display currency
for this trip per _meal_card → _to_display_cost)`. This was FALSE
— v2 raw option JSON persists CNY (e.g. `dinner-2-2.cost = 33.0,
currency_local = CNY`), and the trip's `display_currency = EUR`
(`scripts/lib/html_generator.py:728`). `_to_display_cost` is a
Python BUILD-TIME helper operating on `meals.json` PLAN cards;
it does NOT run in the React runtime over raw v2 option JSON.
Following line 208 literally would have shipped a synthesized
fallback card displaying "€33" for a 33 CNY value (≈4.17 EUR at
typical rate) — a ~7x cost misrepresentation. Meanwhile, Evidence
lines 106-111 and R1 v2 line 298 correctly identified the issue
("Never overwrite a display-currency cost (EUR) with a raw CNY
number"). Dev would have followed the more-explicit mapping rule
in the Reference Source section.

**Chosen alignment**: **hybrid (a) → (b)**. Specifically, codex's
refined precedence: existing active PLAN card match → PLAN
alternative match → synthesized v2 fallback (with raw-cost
display strategy).

**Rationale**:
- Alignment (a) — prefer PLAN_DATA alternative card — IS reliable
  for the load-bearing Yunnan case. `meals.json` is agent-wrapped
  (`{agent, status, data: {days: [...]}}` — verified by Read of
  `data/.../meals.json:1-5`); the generator unwraps `.data` at
  `scripts/generate-html-interactive.py:228-231`; `merge_meals`
  emits `day.meal_alternatives` from `data.days[*].dinner.alternatives`
  at `scripts/lib/render_day_data.py:99-114`. (NOTE corrected in
  task-20260520-200804: the prior text mis-stated Day 1 default as
  `selected_option_id = "dinner-1-2"` — Day 1 actually persists
  `dinner-1-1` and merge Step 1 keeps the active 云线楼 PLAN card.
  A hypothetical day persisting `dinner-1-2 / 建新园过桥米线` would
  hit alignment (a) and inherit the PLAN alternative's converted
  `cost = 4.17 EUR` from `output/travel-plan-beijing-lijiang-dali-
  20260418-100846.html:288-305`.)
- Alignment (b) — raw cost with `currency_local` suffix — is the
  correct fallback when no PLAN alternative matches (e.g.
  cross-meal injection of `breakfast-2-1` into the dinner slot
  per AC2, where no PLAN alternative `breakfast → dinner-slot`
  card exists). Codex confirmed this is the right shape: emit
  `cost_display = "33 CNY"` as a STRING and leave numeric
  `cost = 0` so `fmtCost` is never invoked on a CNY value. The

  `react_template.tpl:1876-1884`), so v3 reuses the established

- Alignment (c) — omit cost — was rejected per codex's
