# BA Specification: Fix City Cover Image Partial Matching

**Request ID**: dev-20260406-010004
**Created**: 2026-04-06T01:00:04Z

## Goal

Fix the `_get_cover_image` method in `generate-html-interactive.py` so that location strings containing parenthetical suffixes (e.g. "Beijing (Wangfujing + Dongdan)") correctly match their base city entry in the `city_covers` cache (e.g. "Beijing").

## Context

The `_get_cover_image` method at line 271 performs three lookups against `images_cache["city_covers"]`: exact match, case-insensitive exact match, and partial match. The partial match at line 294 checks `city.lower() in key or key in city.lower()` where `key` is the full lowercased location string ("beijing (wangfujing + dongdan)").

The logic is directionally correct in the second half of the OR (`key in city.lower()`), but the first half (`city.lower() in key`) tests whether the cache entry name is a substring of the full location string. Because "beijing" IS a substring of "beijing (wangfujing + dongdan)", this condition should in principle match — however the second branch `key in city.lower()` tests whether the full compound string is a substring of the short cache key, which will fail. The overall OR therefore resolves correctly only when the cache key is the shorter string and the location is longer, which is the intended case.

The real problem is that the existing partial match does work for this case in theory, but is fragile and order-dependent. Stripping the parenthetical suffix before any lookup is the robust fix: it normalises the location name up-front so that exact and case-insensitive matches handle the case cleanly without relying on substring heuristics.

## Requirements (MoSCoW)

### Must Have
- Strip parenthetical suffixes (anything from the first `(` onward, trimmed) from the `location` argument before performing any cache lookup in `_get_cover_image`.
- Retain existing exact match, case-insensitive match, and partial match fallback logic after stripping.
- Return empty string (no Unsplash fallback) when no cache entry is found — do not change the no-fallback contract.

### Should Have
- The stripped base name should also be used as the lookup key for the partial match so the condition is symmetric and readable.

### Could Have
- A log/comment noting why the strip is applied, for future maintainers.

### Won't Have (Non-Goals)
- Changes to any other method in the file.
- Changes to how `city_covers` is built or populated.
- Adding Unsplash fallback (explicitly prohibited by existing code comment).

## Edge Cases & Risks

- Location strings with no parenthetical suffix must behave identically to today.
- Location strings where the base name itself is not in the cache should still return empty string.
- Location strings that are purely a parenthetical, e.g. "(Unknown)", should strip to an empty string; an empty key must not match any cache entry.

## Acceptance Criteria

### AC1: Compound location matches base city
- GIVEN `city_covers` contains `{"Beijing": "https://example.com/beijing.jpg"}`
- WHEN `_get_cover_image("Beijing (Wangfujing + Dongdan)")` is called
- THEN the method returns `"https://example.com/beijing.jpg"`

### AC2: Simple location still matches
- GIVEN `city_covers` contains `{"Shanghai": "https://example.com/shanghai.jpg"}`
- WHEN `_get_cover_image("Shanghai")` is called
- THEN the method returns `"https://example.com/shanghai.jpg"`

### AC3: Unknown city returns empty string
- GIVEN `city_covers` does not contain any entry matching "Atlantis"
- WHEN `_get_cover_image("Atlantis (Downtown)")` is called
- THEN the method returns `""`

### AC4: Empty base after strip returns empty string
- GIVEN any `city_covers` cache
- WHEN `_get_cover_image("(Unknown)")` is called (base strips to empty)
- THEN the method returns `""`

## Technical Hints

- Affected file: `scripts/generate-html-interactive.py`, method `_get_cover_image` at line 271.
- Strip pattern: `location.split("(")[0].strip()` is sufficient; use the stripped value as the lookup key throughout the method.
- Guard against empty stripped string before iterating cache.
- No imports required; no new dependencies.
