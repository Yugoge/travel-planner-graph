# BA Specification: Horizontal Scroll Layout for Category Cards

**Request ID**: dev-20260413-181500
**Created**: 2026-04-13T18:15:00+08:00

## Goal

Redesign the travel plan HTML Kanban view so that each major category (meals, attractions, entertainment, shopping, accommodation, transportation) displays its items in a single horizontal row with uniform-sized cards. When items overflow the row, a horizontal scrollbar appears instead of wrapping to additional rows.

## Context

The current layout uses two different rendering engines:
1. **Interactive React generator** (`scripts/generate-html-interactive.py`) -- the primary generator for itinerary pages (used at travel.life-ai.app). Uses inline React JSX with `display: grid` and `auto-fill` columns that wrap to multiple rows.
2. **Bucket-list HTML generator** (`scripts/lib/html_generator.py`) -- uses CSS class `.activity-grid` with `repeat(auto-fit, minmax(280px, 1fr))` which also wraps.

The current Kanban view in the interactive generator has these problems:
- Meals use `repeat(auto-fill, minmax(200px, 1fr))` grid -- cards wrap to multiple rows when there are many options.
- Attractions and Entertainment/Shopping/Accommodation are in a 2-column grid layout (`1fr 1fr`), with cards stacked vertically within each column -- not a horizontal row.
- Card sizes are inconsistent: meals have 200px minimum, attractions use horizontal layout with 140px image, shopping/entertainment cards are full-width vertical stacks.
- No horizontal scrolling mechanism exists anywhere.

## Requirements (MoSCoW)

### Must Have
- Each category section (meals, attractions, entertainment, shopping, accommodation, transportation) displays items in a **single horizontal row** (no wrapping)
- Horizontal scrollbar appears when items overflow the container width
- All cards within a category have **uniform width and height** (fixed dimensions, not auto-sized)
- Cards maintain the same visual design language (image on top, info below)
- Mobile responsive: on small screens, cards should still be horizontally scrollable but with smaller dimensions
- Both the interactive React generator (primary) and the bucket-list HTML generator must be updated

### Should Have
- Smooth scroll behavior or snap-to-card scrolling for better UX
- Hide default scrollbar on desktop but keep scroll functionality (custom scrollbar or scroll-snap)
- Category section headers remain full-width above the scrollable row
- Consistent card aspect ratio across all categories

### Could Have
- Left/right arrow buttons at the edges of each row for keyboard/mouse navigation
- Fade effect at row edges to indicate more content is available
- Touch-friendly swipe gesture on mobile

### Won't Have (Non-Goals)
- Changing the data model or JSON schema
- Modifying the timeline view layout
- Changing the sidebar navigation
- Adding new categories or removing existing ones
- Changing the detail sidebar panel behavior

## Edge Cases & Risks

- Categories with only 1 item should still display correctly (no unnecessary scrollbar)
- Categories with many items (e.g., meals with 3 types x 4 options = 12 cards) must scroll smoothly
- Empty categories should remain hidden (existing behavior preserved)
- Card content that is too long (e.g., long restaurant names) must be truncated, not stretch the card
- Mobile breakpoint (`sm`) needs special attention -- cards must not be too small to read
- The 2-column layout for attractions + right-column (entertainment/shopping/accommodation) must be replaced with full-width horizontal rows per category
- ExpandableNotes and LinksRow components inside cards may need to be hidden or truncated in the compact uniform card design

## Acceptance Criteria

### AC1: Single horizontal row per category
- GIVEN a day with multiple meal options (breakfast, lunch, dinner with alternatives)
- WHEN the Kanban view renders
- THEN all meal cards appear in a single horizontal row, and a horizontal scrollbar is visible when cards overflow

### AC2: Uniform card dimensions
- GIVEN any category section with 2+ items
- WHEN the cards are rendered
- THEN every card in that section has the same width and height (no card is taller or wider than another)

### AC3: Horizontal scroll on overflow
- GIVEN a category with more items than fit in the viewport width
- WHEN the user scrolls horizontally
- THEN additional cards become visible, and vertical layout does not change

### AC4: All categories use the new layout
- GIVEN any day page in the Kanban view
- WHEN viewing meals, attractions, entertainment, shopping, accommodation, transportation
- THEN each category uses the single-row horizontal scroll layout

### AC5: Mobile responsiveness
- GIVEN a mobile viewport (< 768px)
- WHEN viewing any category section
- THEN cards are smaller but still horizontally scrollable, and content remains readable

### AC6: Bucket-list generator consistency
- GIVEN the bucket-list HTML generator output
- WHEN viewing activity-grid sections
- THEN cards also display in a single horizontal row with scrollbar on overflow

## Technical Hints

- **Primary file to modify**: `scripts/generate-html-interactive.py` (lines 2172-2394 -- KanbanView component)
- **Secondary file to modify**: `scripts/lib/html_generator.py` (CSS `.activity-grid` at line 1319, and all `renderDayContent`/`renderCityContent` functions at lines 2889-3078)
- **Layout pattern**: Replace `display: grid; grid-template-columns: repeat(auto-fill, ...)` with `display: flex; overflow-x: auto; flex-wrap: nowrap;` and fixed-width card children
- **Card sizing**: Use fixed width (e.g., 240px desktop, 180px mobile) and fixed height (e.g., 280px desktop, 220px mobile) with `flex-shrink: 0`
- **Remove the 2-column grid** at line 2220 (`gridTemplateColumns: '1fr 1fr'`) -- each category should be full-width
- **Scrollbar styling**: Use `-webkit-scrollbar` CSS or `scrollbar-width: thin` for aesthetics
- **Preserve click handlers**: `onItemClick` must still work on each card
- **Preserve responsive breakpoint logic**: The `sm` variable and `useBreakpoint()` hook already exist
- **Consult UI designer**: The requirement explicitly asks to consult a UI designer for specific card dimensions, spacing, and visual design before implementation
