### Rule 1 — Discovery Preamble (Defense Layer 0)

Per spec-20260505-221501.md Section 5.2 ("The single most important lesson"), the orchestrator MUST execute a discovery preamble BEFORE any task action:

```
ls .claude/commands/
read .claude/commands/INDEX.md
read .claude/commands/<matching-keyword>.md frontmatter + body
grep <user-keyword> scripts/*.{py,sh}
```

**Rationale**: orchestrator's prior-cycle failures stemmed not from any specific bug but from acting before researching the project's existing commands/scripts/skills. Without this preamble, every subsequent hook is corrective; with it, most failures do not occur.

**Binding effect**: any cycle whose orchestrator dispatches a subagent before completing this preamble is in violation of the cycle contract. The preamble result must be visible in the cycle's first orchestrator message before any tool call that mutates state.

### Rule 2 — Acceptance Evidence Standard

Per spec-20260505-221501.md Section 5.2 control #5 ("Acceptance evidence standard"):

- **Subagent reports MUST include verbatim grep command output for each acceptance criterion** — not summary "0 matches" claims. The exact command and the exact stdout (or empty-result error code) must be cited.
- **Orchestrator MUST run the same grep before accepting the subagent's PASS report**. Subagent self-reports are evidence; orchestrator verification is acceptance.
- **The single consolidated `scripts/verify-plan-integrity.py` is the authoritative integrity check**. Subagents that report PASS without invoking it (or its equivalent AC-bound grep) → orchestrator REJECTS.

**Binding effect**: PASS verdicts that lack verbatim grep output, or that the orchestrator did not re-run, are not acceptable. Three consecutive PASS verdicts on incomplete grep alternations during cycles 20260505-123425 + 174743 (per spec Section 5.2 bug-accounting B2) are the canonical example of what this rule prevents.

### Rule 3 — Codex Consensus Binding Rule (Default-Position)

- **Default position**: extend the single `scripts/verify-plan-integrity.py` rather than write new hooks.

- **Any cycle proposing bespoke hooks "for each symptom" must justify why it's not papering over symptoms** before the proposal is admitted to the spec's M-item plan.
