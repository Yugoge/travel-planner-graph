**Status**: COMPLETE

## What was implemented

The travel planner editor (`/trip/<id>` endpoint) previously used a vanilla-JS shell (`web/index.html` + `web/js/state.js`) that was structurally different from the published Notion-style page. This caused permanent visual divergence — CSS patches could never achieve parity between React and vanilla JS.

**Fix**: The editor now uses the React template (`scripts/lib/react_template.tpl`) as its rendering engine. The editor page is the published page with editor-only components layered on top.

## Files modified

- `scripts/lib/render_html_builders.py` — EDITOR_MODE + TRIP_ID injection; `generate_editor_html(gen, trip_id)`
- `scripts/serve-trip.py` — in-memory HTML cache with per-trip locks; editor endpoint uses React template
- `scripts/lib/react_template.tpl` — CandidatesSidebar, adaptV2Option, effectiveDay merge (useMemo), drop zone overlays, onDragStart/onDrop handlers, window.setEditorSelection bridge
- `web/js/drag.js` — removed state.js dependency; accepts callback parameters
