# BA Specification: Fix 3 Critical Bugs in Travel Plan HTML Generator

**Request ID**: dev-20260405-201500
**Created**: 2026-04-05T20:15:00+08:00

## Goal

Fix three rendering bugs in the interactive travel plan HTML page generated by `generate-html-interactive.py`: (1) meal alternatives must render as equal parallel cards instead of a subordinate text list, (2) shopping section must show individual brand stores parsed from mall `notes_base` instead of showing mall names, and (3) the Timeline view must render all activities correctly without gaps or missing elements.

## Context

The travel planner generates a single-file React HTML application from JSON data files. The current page is live at `https://travel.life-ai.app/wangfujing-dongdan-beijing/2026-04-05/`. All three bugs are in the same file: `scripts/generate-html-interactive.py`, which contains both the Python data merging logic and the embedded JSX React components.

## Requirements (MoSCoW)

### Must Have

1. **Bug 1 - Parallel Meal Cards**: All meal options (primary + alternatives) for each meal type (breakfast/lunch/dinner) must render as EQUAL parallel cards in a horizontal row. Currently, lines 2007-2071 render 1 primary card per meal type with alternatives shown as small text items in a subordinate "Also try" section. The fix must:
   - Combine `day.meals[type]` (primary) with `day.meals[type + '_alternatives']` (array) into a single flat array
   - Render ALL options as identical cards with image, name, cuisine, cost, location, notes
   - Use a responsive horizontal grid: wrap on mobile, side-by-side on desktop
   - Label primary as "Option A" and alternatives as "Option B/C/D" (data already has `option` field)
   - Remove the subordinate "Also try" dashed-border text list entirely (lines 2041-2071)

2. **Bug 2 - Individual Brand Store Cards**: The shopping section (lines 2176-2206) currently shows mall-level entries (e.g., "Wangfujing Yintai in88"). The fix must:
   - Parse the `notes_base` field of each shopping entry to extract individual brand/store entries
   - The notes_base has a structured format: `[CATEGORY] BrandName Floor -- description | BrandName2 Floor -- description`
   - Extract each brand into its own card with: brand name, category tag, floor/location, brief description
   - Keep the parent mall as context (e.g., subtitle "in Wangfujing Yintai in88")
   - This parsing must happen in the Python `_merge_day_data()` method (around line 602-635) so the React JSX receives pre-parsed store entries
   - Render each brand store as an individual card in a responsive grid

3. **Bug 3 - Timeline View Rendering**: The TimelineView component (lines 2402-2691) has broken rendering with huge empty gaps and missing elements. The fix must:
   - Investigate why gaps appear between timeline entries
   - The `hH` (hour height) constant at line 2450 is 68px (mobile) / 80px (desktop) per hour, but activities spanning only 2-15 minutes get collapsed to `24px` minimum (line 2472) while the hour grid lines stay at `hH` spacing, causing visual disconnect
   - Ensure all entries render at correct proportional positions
   - Fix any overlap/gap calculation issues in `computeColumnLayout` (lines 2362-2397)

### Should Have
- Meal cards should visually indicate the primary/"default" option (e.g., subtle badge or border)
- Shopping brand cards should have category-colored tags (FAST FASHION, STREETWEAR, KOREAN BRANDS, etc.)
- Timeline should handle 2-minute walk segments gracefully without breaking layout

### Could Have
- Shopping cards could link to the brand's store page if URL is available in data
- Meal alternative cards could show a "closest alternative" indicator based on walking distance

### Won't Have (Non-Goals)
- Changes to the JSON data files (meals.json, shopping.json) -- all fixes are in the generator
- Changes to other Python scripts or agent code
- Adding new data fields to the schema
- Changing the overall page layout or design system

## Edge Cases & Risks

- Some meal types have no alternatives (e.g., breakfast with "Not Applicable") -- handle gracefully, show single card
- Shopping `notes_base` parsing: format varies between malls (some use `[CATEGORY]`, others use plain text) -- parser must be tolerant
- Timeline: travel segments with 2-minute duration (e.g., "Walk to Yintai in88" 14:00-14:02) create near-zero-height entries that can overlap with the next activity starting at the same time
- Timeline: shopping items are already added at line 2430 but their time slots overlap with each other and with other activities in the same time range

## Acceptance Criteria

### AC1: Meal alternatives render as equal parallel cards
- GIVEN a day with lunch + 3 lunch_alternatives in the data
- WHEN the Kanban view renders the Meals section
- THEN all 4 lunch options appear as equal-sized cards in a horizontal scrollable/wrapping row, each with image, name, cuisine, cost

### AC2: Shopping shows individual brand stores
- GIVEN a shopping entry with notes_base containing "[FAST FASHION] UR 2F | UNIQLO 1F/2F | H&M 2F"
- WHEN the shopping section renders
- THEN 3 separate brand cards appear (UR, UNIQLO, H&M) each showing brand name, floor, category, and parent mall name

### AC3: Timeline renders without gaps
- GIVEN a day with activities from 13:00 to 21:00
- WHEN the Timeline view is displayed
- THEN all activities render at correct time positions without large empty gaps, and short-duration activities (2-15 min) are visible and clickable

### AC4: Shopping notes parsing handles varied formats
- GIVEN shopping entries with different notes_base formats (some with [CATEGORY], some without)
- WHEN the Python merger parses them
- THEN all parseable brands are extracted; unparseable notes are kept as-is on the mall card
