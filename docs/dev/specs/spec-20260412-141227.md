### Cycle 1

**Problem**: `rednote-mcp` (Playwright-based Xiaohongshu scraper) fails on the Hetzner server with error code `300012` ("当前IP存在风险" / "IP at risk"). Xiaohongshu detects Hetzner datacenter IPs and blocks all requests — login QR code fails to generate, `edith.xiaohongshu.com/api/sns/web/v2/user/me` returns CORS errors.

**Root cause**: Hetzner vServer (16 vCPU, 32GB RAM) uses datacenter IPs that Xiaohongshu has blocklisted. The rednote-mcp tool uses Playwright (headless Chromium) to scrape `www.xiaohongshu.com` and authenticate via `edith.xiaohongshu.com` API endpoints.

**Environment**:
- Server: Hetzner vServer, Ubuntu Linux
- rednote-mcp: `/usr/lib/node_modules/rednote-mcp/` (globally installed npm package)
- Cookies stored at: `~/.mcp/rednote/cookies.json`
- Playwright requires Xvfb: `xvfb-run --auto-servernum npx rednote-mcp`
- No VPN or proxy available server-side

## Section 2: What Was Attempted

### Cycle 1

**Approach**: Deploy a Cloudflare Worker at `xhs.life-ai.app` that acts as a full reverse proxy to `www.xiaohongshu.com`. Route all rednote-mcp browser requests through this Worker (which uses Cloudflare's edge IPs, not Hetzner's blocked IPs).

**Rationale**: Cloudflare Workers run on Cloudflare's global edge network. Requests arrive at Xiaohongshu from Cloudflare IPs (not Hetzner), bypassing the IP block. The Worker rewrites response URLs so the browser stays on `xhs.life-ai.app` instead of being redirected to `www.xiaohongshu.com`.

**Implementation**:
1. Created Worker at `/root/travel-planner/infra/cloudflare-xhs-proxy/src/worker.js`
2. Configured `wrangler.toml` with custom domain route `xhs.life-ai.app/*`
3. Deployed via `wrangler deploy` using Cloudflare API token
4. Patched rednote-mcp source files to use `xhs.life-ai.app` instead of `www.xiaohongshu.com`

**Why it partially failed**: Static URL rewriting in the Worker catches HTML/CSS/JS source URLs. However, Xiaohongshu's JavaScript constructs `edith.xiaohongshu.com` API URLs **at runtime** via dynamic string concatenation. These are never present in the static source — they're built in browser memory and sent as direct XHR/fetch calls to `edith.xiaohongshu.com`, which is NOT proxied. This causes CORS errors since `edith.xiaohongshu.com` sees the request coming from `xhs.life-ai.app` origin.

**Worker rewriting handles**:
- `https://www.xiaohongshu.com` → `https://xhs.life-ai.app` (in HTML/JS source)
- `https://edith.xiaohongshu.com` → `https://xhs.life-ai.app/api-edith` (in HTML/JS source)
- Cookie domains: `domain=.xiaohongshu.com` → `domain=xhs.life-ai.app`

**What still fails**: Runtime JS API calls build `edith.xiaohongshu.com` URLs dynamically — these bypass rewriting entirely.

## Section 6: Why Not Met

<!-- WHO WRITES: QA (when verdict is fail) -->

### Cycle 1

**Gap**: `edith.xiaohongshu.com` API calls are NOT being proxied through `xhs.life-ai.app`.

**Evidence**:
- Expected: ALL browser requests stay within `xhs.life-ai.app` domain
- Actual: Runtime XHR calls go directly to `edith.xiaohongshu.com`
- Error: CORS policy blocks `edith.xiaohongshu.com` from responding to requests originating from `xhs.life-ai.app`
- Specific failed endpoint: `edith.xiaohongshu.com/api/sns/web/v1/login/qrcode/create`

**Why static rewriting fails**: `rewriteBody()` in the Worker does `result.replaceAll('edith.xiaohongshu.com', ...)` on served HTML/JS text. But Xiaohongshu's production JS bundles construct this URL from a base config object (`window._serverConfig.edithHost` or similar) that is either: (a) not present as a literal string, or (b) obfuscated/split across multiple variables.

### Cycle 1

**Option A (Recommended): Playwright request interception in rednote-mcp**

Patch `/usr/lib/node_modules/rednote-mcp/dist/tools/rednoteTools.js` and `authManager.js` to intercept all browser network requests and redirect `edith.xiaohongshu.com` to `xhs.life-ai.app/api-edith`:

```javascript
// In initialize() after this.page = await this.browser.newPage():
await this.page.route('**://edith.xiaohongshu.com/**', (route) => {
  const url = route.request().url().replace(
    'https://edith.xiaohongshu.com',
    'https://xhs.life-ai.app/api-edith'
  );
  route.continue({ url });
});
```

Also apply to `authManager.js` `login()` method: add route intercept after `this.page = await this.context.newPage()`.

**Worker side** (already handles `/api-edith` prefix):
- `rewriteBody()` already rewrites `edith.xiaohongshu.com` → `xhs.life-ai.app/api-edith`
- Need to verify the Worker correctly strips `/api-edith` prefix when forwarding to `edith.xiaohongshu.com`

Check `buildUpstreamURL()` in Worker — currently it uses `url.pathname + url.search` routed to `UPSTREAM_ORIGIN` (`www.xiaohongshu.com`). Need separate handling for `/api-edith/*` paths:
```javascript
function buildUpstreamURL(url) {
  if (url.pathname.startsWith('/api-edith/')) {
    const edithPath = url.pathname.replace('/api-edith', '');
    return new URL(edithPath + url.search, 'https://edith.xiaohongshu.com');
  }
  return new URL(url.pathname + url.search, UPSTREAM_ORIGIN);
}
```

**Option B: Second Worker route for `edith-xhs.life-ai.app`**

Deploy a second Worker (or same Worker with a second route) that specifically proxies `edith.xiaohongshu.com`. Patch Playwright to intercept `edith.xiaohongshu.com` and redirect to `edith-xhs.life-ai.app`. This requires a DNS record for `edith-xhs.life-ai.app` pointing to the Worker.

**Recommended action sequence**:
1. Fix Worker `buildUpstreamURL()` to handle `/api-edith/` prefix → forward to `edith.xiaohongshu.com`
2. Add Playwright `page.route()` intercept in both `authManager.js` and `rednoteTools.js`
3. Test login flow: QR code should now load from `xhs.life-ai.app/api-edith/api/sns/web/v1/login/qrcode/create`
4. If CORS still fails, add `Access-Control-Allow-Origin: *` to Worker response headers for `/api-edith/*` paths

## Section 8: Attention Notes

<!-- WHO WRITES: PM-Retro -->
<!-- WHAT: Issue-specific traps, warnings, and things to watch out for in the next cycle/session. -->

**1. DO NOT modify rednote-mcp TypeScript source** — the installed package is pre-compiled. Edit only the `.js` files under `/usr/lib/node_modules/rednote-mcp/dist/`. Changes survive as long as the package is not reinstalled.

**2. rednote-mcp requires Xvfb** — run as `xvfb-run --auto-servernum npx rednote-mcp`. Without a display server, Playwright crashes with "No XServer" error.

**3. Cookie domain mismatch is critical** — cookies set for `.xiaohongshu.com` must be rewritten to `xhs.life-ai.app` by the Worker. The Worker's `rewriteCookie()` handles this. If cookies stop working, check domain rewriting first.

**4. Cloudflare Worker token scope** — use `cfut_m6rI2eOfIy6ZAFHf8Mk3SuE4BKo1OxROtVdBU0DXc2fccdbb` (Worker-scoped token). The Global API Key was only used for initial deployment; prefer scoped tokens going forward.

**5. `edith.xiaohongshu.com` serves the authentication AND content APIs** — both login (`/api/sns/web/v1/login/qrcode/*`) and user data (`/api/sns/web/v2/user/me`) go through edith. Proxying this subdomain is the critical path to full functionality.

**6. Xiaohongshu may fingerprint beyond IP** — if IP bypass succeeds but login still fails, check for device fingerprinting (Canvas, WebGL, font enumeration). The rednote-mcp browser profile has no anti-fingerprint measures.

**7. Cookies from `~/.mcp/rednote/cookies.json.bak`** — the old cookies (11 entries, expires Sept 2026) are backed up. If fresh login fails repeatedly, investigate whether old cookies work via the proxy domain (they may need domain field updated from `.xiaohongshu.com` to `xhs.life-ai.app`).

**8. Worker source location**: `/root/travel-planner/infra/cloudflare-xhs-proxy/src/worker.js`
**Wrangler config**: `/root/travel-planner/infra/cloudflare-xhs-proxy/wrangler.toml`
**Deploy command**: `cd /root/travel-planner/infra/cloudflare-xhs-proxy && wrangler deploy`

**9. The Worker currently has NO authentication** — `ALLOWED_IPS` is not set, so any IP can use the proxy. Consider setting `ALLOWED_IPS` to the server's IP after confirming functionality, to prevent abuse.
