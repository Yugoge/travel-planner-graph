# BA Specification: Persist meal-slot un-gating (`skip:false`) across page reload

**Request ID**: 20260527-133618
**Task ID**: 20260527-133618
**Created**: 2026-05-28T00:00:00Z
**Tier**: STANDARD
**Prior cycle**: 20260527-062755 (in-session React-state fix; persistence explicitly out-of-scope)

## Goal

When a user drags away a meal-slot default and places a new restaurant, the slot is un-gated in React state (prior cycle) but the change is NOT persisted: on reload the slot re-gates and the placement can be lost. Close that persistence gap by emitting the existing `skip` mutation (`{skipped:false, skipped_reason:null}`) through the existing autosave pipeline at the two React-state un-gating sites. NO new field types, NO new mutation types.

## Context

Prior cycle 20260527-062755 added two React-state writes that clear `slots[X].skipped = false` so a gated (e.g. `pre-arrival`) meal slot becomes droppable in-session. Those writes never reached the backend, so `day-NN.json` still carries `skipped:true, skipped_reason:"pre-arrival"`. The server-side `skip` mutation handler already exists (`save.py` `_apply_skip_mutation`) and the `slot_envelope` schema already models `skipped`/`skipped_reason` — but the front-end has **never emitted a `skip` mutation** (confirmed: zero `type:'skip'` occurrences in `react_template.tpl`). This cycle wires the existing-but-unused `skip` mutation into the two un-gating sites.

## Reference Source (Contract C)

- **Tier**: tier_2_verified (server handler + schema verified this session)
- **Source**: `scripts/lib/server/save.py:107-114` (`_apply_skip_mutation`) and `schemas/v2/poi-common.schema.json:194-202` (`skipped`/`skipped_reason`)
- **`_apply_skip_mutation` reads** (verbatim): `slot_id = mut.get("slot")`; `extra = mut.get("extra") or {}`; `slot["skipped"] = bool(extra.get("skipped", True))`; `slot["skipped_reason"] = extra.get("skipped_reason")`.
- **Therefore the canonical `skip` payload is**: `{ type: 'skip', slot: '<slotId>', extra: { skipped: false, skipped_reason: null } }`.
  - NOTE the field name is **`slot`** (not `slot_id`) at the mutation top level — `_apply_skip_mutation` calls `mut.get("slot")`. This MUST mirror how `select` mutations name the field (`select` also uses `slot:` — see `react_template.tpl:2406,2436,2945,2989`).
- **`skipped_reason: null`** is schema-valid: enum includes `null`, and the validator only rejects `skipped_reason:null` when `skipped=true`. Since `skipped=false`, `null` reason is correct.
- **Copy allowed**: yes — copy the payload shape from the server handler contract.
- **Dev constraint**: There are ZERO existing front-end `skip` emit sites to mirror. Ground the payload shape strictly on `_apply_skip_mutation` (tier_2) — do NOT invent extra fields. Mirror the top-level `slot:` field-naming convention from the existing `select` emit sites.

## Requirements (MoSCoW)

### Must Have
- Emit `{type:'skip', slot:srcSlotId, extra:{skipped:false, skipped_reason:null}}` whenever `handleSidebarDrop` clears `slots[srcSlotId].skipped` (Site A, line 2366). **The skip emit MUST live INSIDE the existing meal-only guard (`MEAL_SLOTS.has(srcSlotId)`, line 2355) — NOT at the unconditional `saveMutations(dayNum, [{type:'select',...,option_id:null}])` at line 2406, which also fires for non-meal slots (accommodation/activity).** (codex F3)
- Emit `{type:'skip', slot:targetSlotId, extra:{skipped:false, skipped_reason:null}}` whenever `applyBridge` clears `slots[targetSlotId].skipped` (Site B, line 2963). Already inside the `MEAL_SLOTS.has(targetSlotId)` guard (line 2957).
- **Site C (Timeline drop) — codex F4**: The timeline-entry drop handler at `react_template.tpl:1915` is a THIRD path that can land a selection on a meal slot while `skipped:true` remains on disk. It has 3 branches:
  - `direction === 'candidates'`: routes through `window.applyEditorSelection` (= `applyBridge`, Site B) when present → already covered by the Site B fix; the `saveMutations` fallback (applyBridge absent) does NOT clear skipped — emit `skip(false)` for `toSlotId` there too.
  - `direction === 'board'`: emits `select(null)+select(...)` directly via `saveMutations` (line 1915) bypassing applyBridge → emit `skip(false)` for `toSlotId` when `toSlotId` is a meal slot.
  - else (`window.setEditorSelection` = `bridge`): does not clear skipped → emit `skip(false)` for `toSlotId` when it is a meal slot.
  - For all Site C branches, guard the skip emit with a meal-slot check on `toSlotId` (breakfast/lunch/dinner only; NOT accommodation/activity/`meals-any`).
- Preserve the existing `select` emissions at every site (they persist the selection / placement).

### Should Have
- Batch the `skip` + `select` into a single `saveMutations(dayNum, [...])` call where both fire on the same user action (one network round-trip, applied in array order). Server applies mutations sequentially (`_apply_mutations` loops), so `[skip, select]` and `[select, skip]` both converge; ordering is not correctness-critical but batching avoids a redundant fetch.

## Edge Cases & Risks

- **Site A emits select(null) + skip(false)**: After un-gate-by-deselect, slot has `skipped:false` and `selected_option_id:null`. This is schema-valid (null selection allowed in draft/review stages) and matches the in-session React state. The slot reappears droppable on reload with its default option synthesized back into `options[]` — but `options[]` synthesis is React-state-only and is NOT persisted by `select`/`skip`; on reload the slot reads from disk `options[]`. This is acceptable: the un-gate (`skipped:false`) is what must persist; deselect itself already persisted via the existing `select(null)`.
- **Site B emits select(optionId) + skip(false)**: placement persists (`selected_option_id`) AND un-gate persists. This is the primary AC3 path.
- **Field-name trap**: `skip` payload top-level key is `slot` (not `slot_id`). Using `slot_id` would make `_apply_skip_mutation` no-op (`mut.get("slot")` → None → early return). Dev MUST use `slot`.
- **`extra` nesting**: `skipped`/`skipped_reason` go INSIDE `extra`, not at mutation top level. `_apply_skip_mutation` reads `mut.get("extra")`.
- **Non-meal slots**: both un-gate sites are guarded by `MEAL_SLOTS.has(...)`, so the `skip` emit is meal-only. Do not broaden.

## Acceptance Criteria

### AC1 — `skip` mutation on deselect-from-skipped-slot
- GIVEN `handleSidebarDrop` clears `slots[srcSlotId].skipped` in React state (line 2366)
- WHEN the deselect handler runs for a meal slot
- THEN the front-end also enqueues `{type:'skip', day:<dayNum>, slot:'<srcSlotId>', extra:{skipped:false, skipped_reason:null}}` via `saveMutations` (same pipeline as the existing `select` emit). (`day` is supplied by `saveMutations(dayNum,...)`; the mutation object carries `slot`/`type`/`extra`.)

### AC2 — `skip` mutation on applyBridge clear
- GIVEN `applyBridge` clears `slots[targetSlotId].skipped` in React state (line 2963)
- WHEN a sidebar candidate is dropped/tapped onto a gated meal slot
- THEN the front-end enqueues the same canonical `skip` mutation for `targetSlotId`, alongside the existing `select` emission.

### AC3 — Reload survives (live test)
- GIVEN Day 1 breakfast is `skipped:true, skipped_reason:"pre-arrival"`

- THEN `day-01.json` breakfast reads `skipped:false`, `skipped_reason:null`, `selected_option_id == placed option_id`; AND after reload the slot is droppable and the new selection renders on the board.

No extra/renamed fields. (There are zero pre-existing front-end `skip` emit sites; the server handler + schema are the conformance reference.)
