### Cycle 1

**File**: `scripts/lib/json_io.py`, lines 362-370 (`merge_agent_days` function)

**Current behavior**:
```python
for update_day in update_data.get("days", []):
    day_num = update_day["day"]
    existing_days_map[day_num] = update_day   # full day replacement
```

When a POI agent (meals, accommodation, attractions, entertainment, shopping, cafe) emits a partial day object (e.g., only `dinner` populated), this loop replaces the ENTIRE existing day object with the partial one, silently wiping the other slots (e.g., `breakfast` and `lunch`).

**Evidence of data loss**:
- Trip: `data/china-20260412-092624/meals.json`
- Commit `3d05e31` (2026-04-13 12:37): Day 2 had all 3 meals populated (breakfast=二友居西四包子铺, lunch=慕田峪长城景区餐厅, dinner=姚记炒肝店)
- Commit `47fccd4` (2026-04-13 13:14): Day 2 breakfast and lunch completely absent from file, only dinner remained (changed to 南门涮肉后海店)
- Modification log at 13:10:13 recorded `changed_fields: ["days[1].dinner"]` — meals agent INTENDED to update only dinner
- Actual file state shows breakfast + lunch wiped as side effect

**Affected agents** (all use `--merge-days` with risk of partial-day overwrite):
- meals
- accommodation
- attractions
- entertainment
- shopping
- cafe (newly added 2026-04-16 — inherits same risk)

**NOT affected**: timeline agent (day-level replacement is correct behavior there)

### Cycle 1

**Approach**: Option C from Section 8 — introduce a new `--merge-slots` flag alongside the existing `--merge-days` rather than changing `merge_agent_days()` semantics. This preserves backward compatibility for the timeline agent (which legitimately needs whole-day replacement) while giving POI agents a non-destructive save path.

**Steps taken**:
1. Added `merge_agent_slots(existing_data, update_data, agent_name)` to `scripts/lib/json_io.py`. Semantics: for each day in `update_data.days`, look up the matching existing day by `day` number; overlay the update's keys onto the existing day via `dict.update()` so only keys present in the update are replaced; keys NOT in the update (e.g., `breakfast`, `lunch`, `date`, `location`, `other_meta`) survive unchanged. Days in existing but not referenced by update pass through; days in update but absent from existing are inserted.
2. Added `--merge-slots` argparse flag to `scripts/save.py`, imported `merge_agent_slots` in the `from lib.json_io import` block, added a parallel `_merge_existing_slots()` helper next to `_merge_existing_data()`, extended `_prepare_agent_data()` and `save_single_agent()` with a `merge_slots` parameter, and added a mutual-exclusion guard in `_validate_args()` preventing `--merge-days` and `--merge-slots` from being used together.
3. Updated the Step 3 save command in the six POI agent prompts (`.claude/agents/{meals,accommodation,attractions,entertainment,shopping,cafe}.md`) to use `--merge-slots`. Each prompt's "CRITICAL" explanatory comment was rewritten to describe slot-level merge semantics. `timeline.md`, `transportation.md`, `budget.md`, and `review.md` were left untouched per BA scope.
4. Created `scripts/audit-data-loss.py` — parameterized git-history walker that counts populated slots per day per commit per POI agent, flags drops not explained by a `changed_fields` / action="delete" entry in the envelope `log`, and prints a `git show <parent>:<path>` restore suggestion for each flagged commit. Supports `--trip <slug-or-path>`, `--agent <name>`, `--all`, `--project-root <path>`; handles both named-slot (meals, accommodation) and array-based (attractions, entertainment, shopping, cafe) agents. No hardcoded trip paths.
5. Created `scripts/tests/__init__.py` and `scripts/tests/test_merge_agent_slots.py` with 8 integration tests covering: partial meals update preserves breakfast+lunch (the exact 47fccd4 scenario); accommodation partial update preserves `date`/`location`; untouched days pass through; `attractions` array replacement preserves day metadata; array-agent day without the array key preserves the existing array; new days are inserted; missing `day` field raises ValueError; and a regression guard confirming `merge_agent_days` still performs full-day replacement for timeline.

**Rationale for following Section 7 / BA spec prescriptively**: the BA's root-cause analysis (L4, merge logic at `json_io.py:367`) and the user-approved fix (Option C) specified exactly this code path. No alternative explored.

**Forced secondary edit**: `scripts/lib/json_io.py` had pre-existing nesting-depth-4 violations in `save_agent_batch`, `validate_agent_data`, and `_atomic_write` that the `pretool-quality-gate.py` hook flagged on every Edit attempt. To land the `merge_agent_slots` function at all, the three pre-existing functions were refactored by extracting helpers (`_batch_validate`, `_batch_backup`, `_batch_write_tmp`, `_batch_rollback`, `_run_validation_pipeline`, `_restore_or_cleanup`, `_cleanup_tmp`). Behavior of those functions was kept identical. `merge_agent_days` was NOT touched — its semantics remain unchanged, as required by R9 / AC4.

**Verification before reporting**:

- `python scripts/save.py --help` — both `--merge-days` and `--merge-slots` listed.
