### Cycle 1

**File**: `scripts/lib/json_io.py`, lines 362-370 (`merge_agent_days` function)

**Current behavior**:
```python
for update_day in update_data.get("days", []):
    day_num = update_day["day"]
    existing_days_map[day_num] = update_day   # full day replacement
```

When a POI agent (meals, accommodation, attractions, entertainment, shopping, cafe) emits a partial day object (e.g., only `dinner` populated), this loop replaces the ENTIRE existing day object with the partial one, silently wiping the other slots (e.g., `breakfast` and `lunch`).

**Evidence of data loss**:
- Trip: `data/china-20260412-092624/meals.json`
- Commit `3d05e31` (2026-04-13 12:37): Day 2 had all 3 meals populated (breakfast=二友居西四包子铺, lunch=慕田峪长城景区餐厅, dinner=姚记炒肝店)
- Commit `47fccd4` (2026-04-13 13:14): Day 2 breakfast and lunch completely absent from file, only dinner remained (changed to 南门涮肉后海店)
- Modification log at 13:10:13 recorded `changed_fields: ["days[1].dinner"]` — meals agent INTENDED to update only dinner
- Actual file state shows breakfast + lunch wiped as side effect

**Affected agents** (all use `--merge-days` with risk of partial-day overwrite):
- meals
- accommodation
- attractions
- entertainment
- shopping
- cafe (newly added 2026-04-16 — inherits same risk)

**NOT affected**: timeline agent (day-level replacement is correct behavior there)

<!-- This is the single source of truth for what "done" means. Do not paraphrase. -->

Fix the silent data loss bug in POI agent save pipeline. Specifically:

1. **Add `--merge-slots` flag to `scripts/save.py`** — alternative to existing `--merge-days` for POI agents that do partial-day updates.

2. **Implement `merge_agent_slots()` function in `scripts/lib/json_io.py`** — reads existing day object from disk, merges ONLY the keys present in the update (e.g., if update has only `dinner`, preserve existing `breakfast` and `lunch`). This is slot-level merge, not day-level replacement.

3. **Update all POI agent prompts to use `--merge-slots`** instead of `--merge-days`:
   - `.claude/agents/meals.md`
   - `.claude/agents/accommodation.md`
   - `.claude/agents/attractions.md`
   - `.claude/agents/entertainment.md`
   - `.claude/agents/shopping.md`
   - `.claude/agents/cafe.md`

4. **Keep `--merge-days` for timeline agent** — day-level replacement is semantically correct for timeline (whole day recalculation).

5. **Verification test**: An agent updating ONLY Day 2 dinner must NOT affect Day 2 breakfast or lunch. Verify by:
   - Running a partial update test (simulate meals agent with only `dinner` in its output)
   - Checking file state after save: breakfast and lunch must be preserved intact
   - Running `plan-validate.py` — no new "missing required field" errors

6. **Audit script for historical data loss**: Create `scripts/audit-data-loss.py` that:
   - Iterates each meals.json commit in git history
   - For each day, counts populated meal slots (breakfast + lunch + dinner)
   - Flags any day where slot count DECREASED between commits without explicit deletion intent in modification log
   - Outputs list of potentially affected trips + days + commits
   - Suggests restore commands (`git show <commit>:path > /tmp/restore.json`)

7. **Apply same fix pattern to array-based POI agents** (attractions, entertainment, shopping, cafe): although their structure is arrays not named slots, the same partial-update-wipes-existing bug exists if an agent emits a shortened array. The `merge_agent_slots()` function must handle both named-slot (meals, accommodation) and array-based (attractions, entertainment, shopping, cafe) structures correctly, or have domain-specific variants.
