# BA Specification: Fix skipped-slot gate not cleared on meal deselect

**Request ID**: 20260527-062755
**Created**: 2026-05-27T06:27:55Z
**Tier**: SMALL

## Goal

After a user drags a board meal card (e.g., Day 1 breakfast or lunch) to the sidebar to deselect it, the slot's `skipped` flag in `editorTripData` is never cleared. `isGated` evaluates `edSlot.skipped || edSlot.late_arrival_placeholder` and stays `true`, keeping `data-droppable="false"` permanently. The user cannot add any new meal back into that slot.

## Context

Day 1 breakfast/lunch are pre-arrival slots seeded with `skipped: true` in the server-side trip data (they represent meals before the traveler arrives). Once the user removes the default board card, they expect to be able to drag a new candidate back onto that slot. The `skipped` flag is never cleared on either the deselect path (`handleSidebarDrop`) or the re-select path (`applyBridge`), so the slot stays permanently gated.

## Technical Hints

### Fix Site 1 — handleSidebarDrop `setEditorTripData` updater

File: `scripts/lib/react_template.tpl`
Lines: 2359–2402

The updater creates/populates `dayEntry.slots[srcSlotId]`. After line 2364 (`if (!dayEntry.slots[srcSlotId]) dayEntry.slots[srcSlotId] = { options: [] };`), the slot object is guaranteed to exist. Add the flag clear **unconditionally** inside the updater, before the `return updated` at line 2401.

Current code at lines 2363–2401:
```js
const dayEntry = updated.days.find(d => Number(d.day) === Number(dayNum));
if (!dayEntry || !dayEntry.slots) return prev;
if (!dayEntry.slots[srcSlotId]) dayEntry.slots[srcSlotId] = { options: [] };
if (!dayEntry.slots[srcSlotId].options) dayEntry.slots[srcSlotId].options = [];
const already = dayEntry.slots[srcSlotId].options.some(o => o.option_id === optionId);
if (!already) {
  // ... option synthesis ...
}
return updated;
```

Add after line 2365 (`if (!dayEntry.slots[srcSlotId].options) dayEntry.slots[srcSlotId].options = [];`):
```js
dayEntry.slots[srcSlotId].skipped = false;
```

Placement: immediately after the `options` guard, before the `already` check. This ensures the flag is cleared whether or not option synthesis runs.

### Fix Site 2 — applyBridge `setEditorTripData`

File: `scripts/lib/react_template.tpl`
Lines: 2949–2979

`applyBridge` only calls `setEditorTripData` when `originSlotId && originSlotId !== targetSlotId` (line 2956). When a sidebar card is dropped onto a board slot, `originSlotId` is `null`, so the block is skipped entirely and `skipped` is never cleared.

Add an **unconditional** `setEditorTripData` call after line 2954 (`setEditorSelections(prev => ...)`), scoped to MEAL_SLOTS, that clears `skipped` on `targetSlotId`:

```js
// R2: clear skipped flag so gated pre-arrival slots become droppable after re-select
if (MEAL_SLOTS && MEAL_SLOTS.has(targetSlotId) && setEditorTripData) {
  setEditorTripData(prev => {
    if (!prev || !prev.days) return prev;
    const updated = JSON.parse(JSON.stringify(prev));
    const dayEntry = updated.days.find(d => Number(d.day) === Number(dayNum));
    if (!dayEntry || !dayEntry.slots || !dayEntry.slots[targetSlotId]) return prev;
    dayEntry.slots[targetSlotId].skipped = false;
    return updated;
  });
}
```

Place this block immediately after `setEditorSelections(prev => ({ ...prev, [key]: optionId }));` at line 2954, before the existing `if (originSlotId && originSlotId !== targetSlotId ...)` block at line 2956.

Note: `MEAL_SLOTS` is defined at line 2227 as a module-level constant `new Set(['breakfast', 'lunch', 'dinner', 'meals-any'])`. It is in scope inside the `useEffect` callback that wraps `applyBridge`.

### R3 Verification

Both fix sites write only `dayEntry.slots[...].skipped = false`. Neither touches `late_arrival_placeholder`. No conditional removal of `late_arrival_placeholder` is needed.
