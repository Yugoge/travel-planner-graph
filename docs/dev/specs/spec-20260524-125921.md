## Goal

Three bugs in `CandidatesSidebar` (the right-panel): drag-and-drop is architecturally broken (candidates→board never fires `saveMutations`; board→sidebar succeeds only by coincidence), the right panel uses completely different card design elements from the left `KanbanView` cards, and all section labels are hardcoded bilingual strings that ignore the `lang` state variable.

---

## Section 1 (Before): Current Broken State

**Bug A — DnD**: Board slot cards emit `{ direction: 'board', slotId, sourceSlotId, optionId }`. Candidate cards (lines 2427-2431, 2473-2479, 2521-2524) emit `{ slotId, originSlotId, optionId }` — no `direction` field, no `sourceSlotId`. The board's `onDrop` gate at line 913 requires `payload.direction === 'board' && payload.sourceSlotId` to call `saveMutations`; when a candidate card is dropped on a board slot, both conditions fail and it falls through to `window.setEditorSelection` (which works but doesn't clear the previous selection from the originating slot). Conversely `handleSidebarDrop` at line 2354 checks `direction === 'plan-to-candidates' || direction === 'board'` — so board→sidebar drag deselects correctly (board cards have `direction: 'board'`). This is why right→left partially works: the sidebar deselects the board slot. Left→right (candidate→board) fires `window.setEditorSelection` but misses the `saveMutations` call, so the selection is not persisted.

**Bug B — Visual design**: `candidateCardStyle` (line 2266-2274) produces compact text-only cards: no image, no category color label, no `RedNoteLink`, no MapLink, no hover transform, incompatible background colors (white/`#eff6ff`/`#e9f5ec` vs `#fff`), `cursor: grab` vs `cursor: pointer`, `padding: '8px 10px'` flat vs the full 280×320px image+detail card layout. The board's `cardStyle` (line 816-824) uses fixed width/height, image region, category-color header row, detail sub-rows, and an inline `.slot-drop` overlay div for drop targeting. Candidate cards have none of these.

**Bug C — i18n**: `slotLabels` (lines 2313-2317) is a hardcoded object with Chinese+English slash-strings: `'早餐 / Breakfast'`, `'上午 / Morning'` etc. The section headers at lines 2414-2415 (`'住宿 / Accommodation'`) and 2460-2462 (`'餐饮 / Meals'`) are also hardcoded bilingual literals. The panel header at line 2405 reads `Candidates — Day {dayNum}` (English-only, hardcoded). None of these use `L(key, lang)` or the `lang === 'local'` branch pattern used everywhere else. The lang toggle is `const [lang, setLang] = useState('local')` at line 2560; when `lang === 'local'` the user expects Chinese-only; when `lang === 'base'` English-only.

## Section 2 (What Was Revised): sourceSlotId Approach Superseded

> **SUPERSEDED — 2026-05-24T14:30:00Z by ticket-20260524-132346.md**
>
> The Technical Hints section below (lines 174–189 of this file) originally instructed adding `sourceSlotId: slotId` to all three candidate `onDragStart` payloads and gating the expanded `onDrop` condition on `payload.sourceSlotId`. This approach was identified as incorrect by BA-QA review and **must NOT be followed**.
>
> **Root defect**: the unified condition `(direction === 'board' || direction === 'candidates') && payload.sourceSlotId && saveMutations` gates on `payload.sourceSlotId` — if any candidate payload carries `sourceSlotId`, and the onDrop logic is not carefully sub-branched, the board-to-board clear path (`saveMutations(..., option_id: null)`) can fire for candidate drops, corrupting the source slot.
>
> **Authoritative instruction**: `docs/dev/ticket-20260524-132346.md` M1. Candidate payloads must carry `direction: 'candidates'` only — no `sourceSlotId`. The board `onDrop` must use a separate `else if (payload.direction === 'candidates')` branch that never touches the source slot.

## Edge Cases & Risks

- The board `onDrop` discriminates on `payload.direction === 'board'` to decide between `saveMutations` (board-to-board) vs `window.setEditorSelection` (legacy). A new `direction: 'candidates'` value must be added, and the board `onDrop` must handle it — otherwise candidate→board drops still fall through to the legacy bridge.
- The `.slot-drop` overlay div inside candidate cards must carry correct `data-slot-id`, `data-droppable` attributes so the board drop logic works. Since candidates ARE droppable (they are not gated slots), `data-droppable` should always be `'true'`.
- `cardW`/`cardH`/`imgH` are defined locally inside `KanbanView`'s render scope. Since `CandidatesSidebar` is a separate component, dev must either accept inline constants (280/320/140) or extract them to module scope. Inline constants are acceptable for now.
- The image field in v2 option objects is `cover_image` or `image`; `adaptV2Option` must map these so candidate cards can render the image.
- `slotLabels` keys must be added to `PLAN_DATA.trip_summary.ui_labels` for `L()` to resolve them, OR the ternary pattern must be used directly. If the keys don't exist in `ui_labels`, `L()` returns the raw key as fallback. Dev must choose: use `L()` if keys exist in data, or use explicit ternaries for guaranteed Chinese/English parity.
- Do NOT regress the `handleSidebarDrop` deselect path (lines 2347-2360) — it currently works for `direction === 'board'`.

## Technical Hints

**Bug A fix — DnD payload and board onDrop handler**

At each of the three candidate `onDragStart` handlers (lines 2427-2431 accommodation, 2473-2479 meals, 2521-2524 activities), add `direction: 'candidates'` and `sourceSlotId: slotId` to the payload.

Example — accommodation (line 2427-2431):
```
// BEFORE:
e.dataTransfer.setData('text/plain', JSON.stringify({ optionId: rawOpt.option_id, slotId: 'accommodation', originSlotId: 'accommodation' }));

// AFTER:
e.dataTransfer.setData('text/plain', JSON.stringify({ optionId: rawOpt.option_id, slotId: 'accommodation', originSlotId: 'accommodation', sourceSlotId: 'accommodation', direction: 'candidates' }));
```

At the board `onDrop` handler (line 913, and equivalents at lines 998, 1084, 1170, 1320, 1928), the condition `payload.direction === 'board' && payload.sourceSlotId && saveMutations` must be expanded to also handle `direction === 'candidates'`. The difference: for `direction === 'candidates'`, there is no "source slot to clear" (candidates don't have a source board slot), so only one mutation is needed: `{ type: 'select', slot: toSlotId, option_id: payload.optionId, origin_slot_id: payload.originSlotId }`. The `setEditorSelections` update sets `[dayNum + ':' + toSlotId]: payload.optionId` only (no clearing of source slot).

Modified branch logic inside the onDrop handler (conceptual):
```
if ((payload.direction === 'board' || payload.direction === 'candidates') && payload.sourceSlotId && saveMutations) {
  const dayNum = day && day.day;
  if (payload.direction === 'board') {
    // board-to-board: clear source, assign target
    setEditorSelections && setEditorSelections(prev => ({ ...prev, [dayNum + ':' + payload.sourceSlotId]: null, [dayNum + ':' + toSlotId]: payload.optionId }));
    saveMutations(dayNum, [{ type: 'select', slot: payload.sourceSlotId, option_id: null }, { type: 'select', slot: toSlotId, option_id: payload.optionId, origin_slot_id: payload.sourceSlotId }]);
  } else {
    // candidates-to-board: assign target only
    setEditorSelections && setEditorSelections(prev => ({ ...prev, [dayNum + ':' + toSlotId]: payload.optionId }));
    saveMutations(dayNum, [{ type: 'select', slot: toSlotId, option_id: payload.optionId, origin_slot_id: payload.originSlotId || null }]);
  }
} else if (window.setEditorSelection) ...
```

Note: this onDrop logic is IDENTICAL in 6 places (meals at ~line 913, cafe at ~998, attractions at ~1084, entertainment at ~1170, accommodation at ~1320, timeline at ~1928). All 6 must be patched with the same expanded condition.

**Bug C fix — i18n**

Replace `slotLabels` static object (lines 2313-2317) with a function that calls `L()`:
```
// BEFORE:
const slotLabels = {
  breakfast: '早餐 / Breakfast', lunch: '午餐 / Lunch', dinner: '晚餐 / Dinner',
  morning_activity: '上午 / Morning', afternoon_activity: '下午 / Afternoon',
  evening_activity: '晚上 / Evening',
};

// AFTER — derive from lang at render time:
const slotLabel = (slotId) => {
  const map = {
    breakfast: lang === 'local' ? L('breakfast', lang) : L('breakfast', lang),
    lunch: lang === 'local' ? L('lunch', lang) : L('lunch', lang),
    dinner: lang === 'local' ? L('dinner', lang) : L('dinner', lang),
    morning_activity: lang === 'local' ? L('morning_activity', lang) : (L('morning_activity', lang) || 'Morning'),
    afternoon_activity: lang === 'local' ? L('afternoon_activity', lang) : (L('afternoon_activity', lang) || 'Afternoon'),
    evening_activity: lang === 'local' ? L('evening_activity', lang) : (L('evening_activity', lang) || 'Evening'),
  };
  return map[slotId] || slotId;
};
```

Note: `L(key, lang)` already returns the correct language string for the current `lang`. The issue is purely that `slotLabels` is a static object not re-evaluated when `lang` changes. Simply replace `{slotLabels[slotId] || slotId}` (line 2509) with `{L(slotId, lang) || slotId}` and handle the cases where `ui_labels` may not have those keys by using a fallback ternary:
```
const getSlotLabel = (slotId) => {
  const resolved = L(slotId, lang);
  if (resolved !== slotId) return resolved; // L() found it in ui_labels
  // fallback for missing keys in ui_labels:
  const fallbacks = {
    breakfast: lang === 'local' ? '早餐' : 'Breakfast',
    lunch: lang === 'local' ? '午餐' : 'Lunch',
    dinner: lang === 'local' ? '晚餐' : 'Dinner',
    morning_activity: lang === 'local' ? '上午' : 'Morning',
    afternoon_activity: lang === 'local' ? '下午' : 'Afternoon',
    evening_activity: lang === 'local' ? '晚上' : 'Evening',
  };
  return fallbacks[slotId] || slotId;
};
```
