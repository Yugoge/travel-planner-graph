## Goal

Three bugs in `CandidatesSidebar` (the right-panel): drag-and-drop is architecturally broken (candidates→board never fires `saveMutations`; board→sidebar succeeds only by coincidence), the right panel uses completely different card design elements from the left `KanbanView` cards, and all section labels are hardcoded bilingual strings that ignore the `lang` state variable.

---

## Section 1 (Before): Current Broken State

**Bug A — DnD**: Board slot cards emit `{ direction: 'board', slotId, sourceSlotId, optionId }`. Candidate cards (lines 2427-2431, 2473-2479, 2521-2524) emit `{ slotId, originSlotId, optionId }` — no `direction` field, no `sourceSlotId`. The board's `onDrop` gate at line 913 requires `payload.direction === 'board' && payload.sourceSlotId` to call `saveMutations`; when a candidate card is dropped on a board slot, both conditions fail and it falls through to `window.setEditorSelection` (which works but doesn't clear the previous selection from the originating slot). Conversely `handleSidebarDrop` at line 2354 checks `direction === 'plan-to-candidates' || direction === 'board'` — so board→sidebar drag deselects correctly (board cards have `direction: 'board'`). This is why right→left partially works: the sidebar deselects the board slot. Left→right (candidate→board) fires `window.setEditorSelection` but misses the `saveMutations` call, so the selection is not persisted.

**Bug B — Visual design**: `candidateCardStyle` (line 2266-2274) produces compact text-only cards: no image, no category color label, no `RedNoteLink`, no MapLink, no hover transform, incompatible background colors (white/`#eff6ff`/`#e9f5ec` vs `#fff`), `cursor: grab` vs `cursor: pointer`, `padding: '8px 10px'` flat vs the full 280×320px image+detail card layout. The board's `cardStyle` (line 816-824) uses fixed width/height, image region, category-color header row, detail sub-rows, and an inline `.slot-drop` overlay div for drop targeting. Candidate cards have none of these.

**Bug C — i18n**: `slotLabels` (lines 2313-2317) is a hardcoded object with Chinese+English slash-strings: `'早餐 / Breakfast'`, `'上午 / Morning'` etc. The section headers at lines 2414-2415 (`'住宿 / Accommodation'`) and 2460-2462 (`'餐饮 / Meals'`) are also hardcoded bilingual literals. The panel header at line 2405 reads `Candidates — Day {dayNum}` (English-only, hardcoded). None of these use `L(key, lang)` or the `lang === 'local'` branch pattern used everywhere else. The lang toggle is `const [lang, setLang] = useState('local')` at line 2560; when `lang === 'local'` the user expects Chinese-only; when `lang === 'base'` English-only.

## Section 8 (Cycle 1): Traps, Stale Assumptions, and Warnings
