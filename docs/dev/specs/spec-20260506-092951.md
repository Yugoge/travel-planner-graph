**Approach (surgical, NOT heuristic-driven)**:

1. **Per-edit save.py --day N invocations** — every data-file write goes through `scripts/save.py --trip china-20260412-092624 --agent <name> --day <N> --input <file> --no-backup`. Cycle-2 1-line fix: `if isinstance(item.get('primary'), bool):` instead of `if 'primary' in item:`. This unblocks save.py for meals data without weakening the spec-5.9 user-language→optional translation for legitimate `primary: true` boolean inputs.
3. **ITEM A (Day 8 traveler matrix)** — Cross-checked timeline.json Day 8 (Jade departs 16:30 on flight 3U8893, arriving Wudaokou 21:30 for May 11 class) + meals.json Day 8 dinner (`Last night solo hotpot for Matilde before Xi'an`) — both confirm MATILDE SOLO for the entire Day 8 evening. Both fields now name the same traveler subset and cite cross-file evidence.
4. **ITEM B (7 name_local CJK)** — bilingual translations applied per-day via 4 separate save.py calls (meals.json --day 3, timeline.json --day 5/6/7) using exact zh-CN strings from QA cycle-1 prescription Section 7. 5. **ITEM C (shopping zh)** — save.py --day 4: `'回北京前'` → `'赴成都前'` (matching the cycle-1 notes_base 'before departing for Chengdu').
6. **ITEM D (.test_pl_check.json)** — `Path('.test_pl_check.json').unlink()` (rm forbidden by global hook); .gitignore extended with `data/*/.test_*.json`, `data/*/.tmp_*.json`, `data/*/.precheck-*` patterns to prevent future dev cycle leftovers.
7. **ITEM E (.bak files)** — `git rm --cached` on all 8 tracked .bak files (accommodation/attractions/budget/entertainment/meals/modification-log/timeline/transportation), then `Path.unlink()` on the working-tree files, then .gitignore extended with `data/*/*.bak`. 8. **ITEM F (cross-ref linter 2-source duplicate)** — DEFERRED. Spec §5.7 requires only ≥3-source detection; QA Section 7 item 7 marks the 2-source extension OPTIONAL. Per Minimum-Diff Rule, deferring to a future cycle (or to QA's own `--cross-ref-warn-only` surfacing).

**Why this approach differs from cycle 1**:
- Cycle 1 used a one-shot regex/heuristic migration script (`migrate_spec_20260506.py`) which tried to detect "did the migration alter anything" instead of "is the field actually CJK-clean / are the strings actually consistent". 7 name_local violations passed because the heuristics didn't match; Day 8 contradiction passed because the migration's "consistency check" looked for matching trip-day metadata not actual semantic agreement; shopping `回北京前` variant slipped because the heuristic only matched `赴北京前`.
- Cycle 2 makes each fix surgical and explicit: the input file specifies the exact target field, and save.py's slot-level merge replaces only that field. No heuristics; no "did anything change" gating.
