## Goal

Replace the current vanilla-JS trip editor (`web/index.html` + `web/js/state.js`) with an architecture that serves the **same React HTML as the published static page** (`generate-html-interactive.py` output) with editor-only interactive layers (candidates sidebar, drag-and-drop, selection state) injected at the React-component level — not at the DOM-string level.

The user's directive: "直接复制原始html生成机制然后将你的全部动态html机制加载上面" — copy the original HTML generation mechanism, then load dynamic mechanisms on top. This means the React template **is** the editor's rendering engine. Editor interactive features are added as React components and a React-native bridge, not as external scripts grafted onto a foreign DOM.

---

## Context

Four previous attempts adjusted CSS tokens in `web/css/main.css`, changed cover heights, or swapped fonts. None addressed the root cause: the editor is a structurally different application from the published page. The published page uses `react_template.tpl` with inline JSX styles, `ui-sans-serif` font, 280×320px kanban cards, and 200px cover. The editor uses Inter font, vertical slot layout, and different card templates. No amount of CSS patching can bridge two different component trees.

The correct architecture is to serve the React-rendered HTML on every `/trip/<id>` request, then add editor-only components inside the React tree.

## Critical Technical Findings (from Code Investigation + Codex Review)

### Finding 1: Exchange rate subprocess is a blocker for per-request generation
`InteractiveHTMLGenerator.__init__()` calls `_load_exchange_rates()` which spawns a subprocess with `timeout=10` on every instantiation. This blocks HTTP for up to 10 seconds per request.

**Resolution**: In-memory cache in `serve-trip.py`. Key = `trip_id`, value = generated HTML string. Cache is populated on first request and invalidated on `POST /api/save` success for that trip_id. The exchange rate is only fetched once per server session per trip.

### Finding 2: `generate-html-interactive.py` is not directly importable (hyphenated filename)
Python cannot `import generate-html-interactive`. Must use `importlib.util.spec_from_file_location()` or move `InteractiveHTMLGenerator` into `scripts/lib/html_generator.py` (which already exists — confirm it's the right module).

**Resolution**: Dev must use `importlib` to load the generator, OR extract `InteractiveHTMLGenerator` into `scripts/lib/html_generator.py`. Verify `html_generator.py` current content before deciding.

### Finding 3: Injecting `state.js` into the React page is unsound
`state.js` imports `drag.js`, `offline.js`, `save.js`, `routing.js`, `budget.js`. On load, it immediately calls `init()` which calls `document.getElementById("trip-title")`, `#approve-day-btn`, `#tab-timeline`, `#candidates-groups` — none of which exist in the React-rendered DOM. Auto-init fails silently, breaking everything.

**Resolution**: `state.js` is reference logic only. The editor page uses a React-native selection/save bridge (`window.setEditorSelection`), and `drag.js` is refactored to not import from `state.js`.

### Finding 4: Drop zones do not exist in KanbanView
`KanbanView` renders read-only display cards. There are no `.slot-drop` elements.

**Resolution**: Two options (dev chooses):
- Option A (simpler): Add `.slot-drop[data-slot-id]` overlay zones within each KanbanView category section header (above the horizontal scroll). Users drop onto the section, not onto a specific card position.
- Option B (cleaner): Keep KanbanView read-only; TimelineView gets `.slot` drop zones (already has slot concept in `web/index.html`). Toggle to timeline mode for editing.

The spec recommends Option A (drop zones in KanbanView category headers) for visual consistency, but dev may choose Option B if implementation is cleaner.

### Finding 5: React + vanilla JS boundary
A window global that stores data does not trigger React re-render. The bridge must call React setState.

**Resolution**: Inside `NotionTravelApp`'s `useEffect`, expose:
```js
window.setEditorSelection = (dayN, slotId, optionId) => {
  // update React selection state
  setEditorSelections(prev => ({ ...prev, [`${dayN}:${slotId}`]: optionId }));
  // queue save
  fetch('/api/save', { method: 'POST', body: JSON.stringify({...}) });
};
```

### Finding 6: `EDITOR_MODE` flag injection
The React template must know it is in editor mode. The simplest approach: `render_html_builders.py` injects `const EDITOR_MODE = true;` into the HTML script block when generating for the editor (serve-trip.py path), vs `false` for the published page.

## Edge Cases & Risks

- **Exchange rate cache miss on server restart**: First request after restart will have 10s TTFB for each trip. Acceptable for local dev tool.
- **Concurrent requests while cache is cold**: `ThreadingHTTPServer` is multi-threaded. Two simultaneous first requests for the same trip will both call the generator. Mitigation: hold a per-trip generation lock (same pattern as `TripStore._locks`).
- **Drag-and-drop on React-rendered elements**: React re-renders on state change, which destroys and recreates DOM nodes. Event listeners bound directly to DOM nodes (not via delegation) will be lost. `drag.js` uses event delegation (root element listeners) — this pattern survives React re-renders as long as the root IDs (`#candidates-groups`) persist across renders. Root IDs MUST be on stable outer container elements, not on dynamically-rendered list items.
- **Babel standalone compile time**: The React template compiles 1847 lines of JSX client-side via Babel standalone. Adding editor components increases compile time. Not a blocking concern for local dev, but worth noting.

**Cache structure in `serve-trip.py`:**
```python
_html_cache: dict[str, str] = {}  # trip_id -> generated HTML
_html_cache_lock = threading.Lock()

def _get_or_generate_html(trip_id: str, project_dir: Path) -> str:
    with _html_cache_lock:
        if trip_id in _html_cache:
            return _html_cache[trip_id]
    # Generate outside lock to avoid blocking all threads
    html = _generate_html_for_trip(trip_id, project_dir)
    with _html_cache_lock:
        _html_cache[trip_id] = html
    return html

def _invalidate_html_cache(trip_id: str) -> None:
    with _html_cache_lock:
        _html_cache.pop(trip_id, None)
```
Call `_invalidate_html_cache(trip_id)` at the end of `handle_save()` success path.
