**Request ID**: dev-20260505-060527

## Goal

Resolve a 7-bug cluster on the China itinerary HTML page (`https://travel.life-ai.app/china/2026-04-12/`) so that (a) every booked transport/attraction the user paid for appears in BOTH the kanban view and the timeline view at its correct time slot, (b) sidebar trip-grouping uses pure city names only, (c) Days 9-11 contain Beijing/Wudaokou content for Jade (not stale Xi'an content), (d) meal alternatives no longer crowd the timeline as parallel entries, and (e) the Matilde-out-of-scope phantom accommodation stops rendering as a real card. The page must look polished enough to restore user trust after multiple failed iterations.

## Context

The China trip plan (15 days, 2026-05-02 → 2026-05-16) uses a single renderer (`scripts/generate-html-interactive.py`, ~3500 lines) that consumes 7 JSON data files in `data/china-20260412-092624/`. The fix must be COMPREHENSIVE in this single cycle, not yet another partial pass.

## Edge Cases & Risks

- **Risk-3**: Suppressing meal alternatives in TimelineView while keeping them in kanban requires careful gating: the `_options` array drives BOTH views today. Mitigation: TimelineView reads `day.meals[mealType]` (primary) ONLY when `_isAlternative` index 0; or introduce a separate `day.meals[mealType+'_primary_only']` shape.
- **Risk-4**: Day 4 cover image: if header_subtitle change moves transit text out of `location_base`, the cover lookup at line 648 already uses skeleton `Datong` — should remain stable. Verify post-fix that Day 4 cover is still a Datong cover (not blank).
