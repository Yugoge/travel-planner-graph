# BA Specification: Fix Shopping Brand-Splitting Duplicate Image Bug

**Request ID**: dev-20260413-063000
**Created**: 2026-04-13T06:30:00+08:00

## Goal

Stop splitting shopping malls into individual brand cards in the HTML generator, eliminating the systemic duplicate-image problem where all brand cards within a mall display the same parent mall photo.

## Context

The HTML generator (`scripts/generate-html-interactive.py`, lines 726-797) splits shopping items with a `brands` array into separate cards per brand. Brand-specific images are never fetched (images.json has zero `brand_*` keys among its 102 POI entries), so all brand cards fall back to the parent mall's `image_url`. This affects 9 out of 10 shopping items across the entire 15-day itinerary, producing 24 cards that all show duplicated parent images. The user correctly identified this as a systemic issue.

The brand-splitting logic was introduced as part of commit `cfc5766` ("fix: realistic prices across all categories + shopping merge bug") as a workaround. The brands data itself is valuable -- it provides specific sub-recommendations within each shopping area -- but displaying each brand as a full-size independent card with the same image creates visual noise and a "default image" appearance.

## Requirements (MoSCoW)

### Must Have
- Stop generating individual brand cards from the `brands` array
- Show each shopping item as ONE card using its own `image_url` (the mall/street photo)
- Preserve brand information by listing brands within the card's description/notes area
- Brand names, categories, and descriptions must remain visible to the user

### Should Have
- Display brands as a compact sub-list within the mall card (name + category + brief description)
- Support both `name` and `name_local` for brand display depending on active language
- Maintain the existing fallback path (line 778-796) for items without brands

### Could Have
- Collapsible/expandable brand list within the card (UI enhancement)
- Category icons or badges for each brand type (SILK, FOOD, CRAFTS, etc.)

### Won't Have (Non-Goals)
- Fetching individual brand images from Gaode Maps (Option B) -- too many API calls for marginal visual gain; brands are often stall-type shops without distinct map images
- Creating a new card layout specifically for brand sub-items (Option C) -- overengineered for this use case
- Modifying shopping.json data structure -- the brands array is well-structured and should be preserved as-is

## Edge Cases & Risks

- Items with empty `brands: []` (e.g., Day 4 Weidu Antique City) already fall through to the else branch and are unaffected
- The `_parse_shopping_brands()` regex fallback (line 749) also triggers brand splitting -- must be handled the same way
- Brand descriptions vary in length; very long multi-brand lists could make cards too tall
- The `mall_name_base`/`mall_name_local` fields on brand cards (lines 771-772) are referenced in the React template (line 2335); removing brand cards means this display logic for "parent mall" labels becomes unnecessary

## Acceptance Criteria

### AC1: Single card per shopping item
- GIVEN a shopping item with a `brands` array (e.g., Day 1 Qianmen Street with 4 brands)
- WHEN the HTML is generated
- THEN exactly ONE card is rendered for that item, using its own `image_url`

### AC2: Brand information preserved in card content
- GIVEN a shopping item with brands
- WHEN the card is rendered
- THEN all brand names and their descriptions appear within the card body (not as separate cards)

### AC3: No duplicate images
- GIVEN the generated HTML for all 15 days
- WHEN viewing shopping sections
- THEN no two adjacent shopping cards show the same image (unless they are genuinely different locations that happen to share imagery)

### AC4: Items without brands unaffected
- GIVEN a shopping item without brands (e.g., Day 4 Weidu Antique City)
- WHEN the HTML is generated
- THEN the card renders identically to current behavior

## Technical Hints

- **Primary file to modify**: `scripts/generate-html-interactive.py` lines 726-797
- **Pattern**: Replace the `if brands:` block (lines 750-777) with logic that builds a single card, appending brand info to `notes_base`/`notes_local`
- **Template reference**: Lines ~2335 where `mall_name_base` is used in JSX can be cleaned up
- **No data file changes needed**: shopping.json, images.json remain as-is
- **Test**: Regenerate HTML and verify shopping card count drops from 25 to 10 (9 brand-split items collapse + 1 non-brand item stays)
