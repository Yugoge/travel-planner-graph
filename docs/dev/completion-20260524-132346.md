## Root Cause Analysis

**Root Causes**:

- **Bug A (DnD)**: `CandidatesSidebar` candidate `onDragStart` payloads were built without a `direction` field. The board `onDrop` handlers gate on `payload.direction === 'board' && payload.sourceSlotId` to call `saveMutations`; candidate payloads failed both conditions and fell through to the `window.setEditorSelection` legacy bridge only — selection appeared to work but was never persisted via `saveMutations`. Additionally, the accommodation board `onDrop` at line 1320 had no `direction` gate at all.

- **Bug B (Visual design)**: `candidateCardStyle` (lines 2266–2274) produced compact text-only cards: no image region, no fixed 280×320px dimensions, wrong background colors, `cursor: 'grab'`, no category-color header, no `RedNoteLink`, no hover transform. These differed completely from the board `cardStyle` tokens.

- **Bug C (i18n)**: `slotLabels` was a static object with hardcoded bilingual slash-strings (`'早餐 / Breakfast'` etc.) evaluated once at component definition, never re-evaluated when `lang` changed. Panel header and section headers were also hardcoded bilingual or English-only literals with no `L()` calls anywhere in `CandidatesSidebar`.

All three bugs were introduced during initial `CandidatesSidebar` feature development — no single regression commit; the component was built as an isolated implementation without reusing the board card structure or i18n helpers.

## Implementation

**Files Modified**:
- `scripts/lib/react_template.tpl` — 83 lines added, 41 lines removed (1 file, net +42 lines)

**What was implemented**:

1. **Bug A — DnD payload**: Added `direction: 'candidates'` to all 3 candidate `onDragStart` payloads (accommodation ~L2437, meals ~L2493, activity ~L2552). No `sourceSlotId` added (per ticket M1 — candidates have no source board slot to clear).

2. **Bug A — Board onDrop handlers**: Added `else if (payload.direction === 'candidates')` branch to all 6 board onDrop handlers (lines 913, 998, 1084, 1170, 1320, 1928). Each candidates branch calls `window.applyEditorSelection(payload.optionId, toSlotId, payload.originSlotId || null)` with a `saveMutations` fallback when the bridge is absent. The accommodation handler at line 1320 (previously missing any direction gate) was given the full board + candidates branch pattern.

3. **Bug A — Double-save fix**: Candidates branch uses `window.applyEditorSelection` (not `window.setEditorSelection`). The `applyBridge` function internally calls `saveMutations`, `setEditorSelections`, `preserveCurrentAccommodationOption`, and cross-meal copy logic — calling `setEditorSelection` separately would double-save with the second mutation missing `origin_slot_id`.

4. **Bug B — Card layout**: Replaced all 3 candidate card rendering sections (accommodation ~L2430–2466, meals ~L2484–2523, activity ~L2545–2582) with board-card-equivalent layout: outer div `width:100%/maxWidth:280px/height:320px`, image region `height:140px`, category-color header row with emoji, name row with `RedNoteLink`, sub-detail row, `.slot-drop` overlay with `data-droppable="true"`. Width uses `width:100%/maxWidth:280px` (not fixed 280px) to prevent horizontal overflow in the ~276px usable sidebar column.

5. **Bug B — Overlay fix**: Candidate card `.slot-drop` overlays have no `onDrop` handler (only `onDragOver`). This allows board card drops onto the candidates area to bubble up to `#candidates-groups` `handleSidebarDrop`, preserving the AC2 regression guard. Previously, a `stopPropagation` on the overlay would have blocked deselection.

6. **Bug C — i18n**: Replaced static `slotLabels` object with `getSlotLabel(slotId)` function using `L(slotId, lang)` with identity-check fallback (`resolved !== slotId ? resolved : lang==='local' ? zh : en`). Panel header, accommodation/meals section headers, loading text, and empty-state text all converted to `lang==='local' ? zh : en` ternaries. The `L()` identity check (not truthy check) is required because `L()` returns the raw key string as fallback — a truthy `||` chain would never fire.
